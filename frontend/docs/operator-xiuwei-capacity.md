# 修为人数试算

在 `/operator` →「养成规划」页头点击「修为人数试算」打开弹窗。登录并选中子账号即可使用，不要求管理员权限或先创建培养清单。原有培养清单、目标、日程和未保存编辑保持原状。

起始、目标修为默认 1→17，修改后即时计算，目标必须高于起始。同一次页面会话的条件和展开组在关闭重开后保留；切换子账号、游戏或离开养成规划会关闭弹窗，更换账号/游戏重置条件。条件不写入本机或云端。

## 计算口径

复用现有修为费用规则，分别显示风火、地水、阴阳三组。风、火共用同一份扇类材料，人数为风火合计，其他组同理。所有人都按同一个修为区间估算，不推断具体密探现有练度，也不统计实际拥有多少位密探。混沌无已知费用规则，暂不试算。

对该区间需要的每种材料取 `floor(当前库存 / 单人需求)`，最小值即该组人数 N。用不到的材料不限制人数。培养 N 人后的剩余为 `库存 - N × 单人需求`；再养一人的缺口为 `max(单人需求 - 剩余, 0)`。零人时展示培养第一人的缺口。

阴阳 13→17 示例：单人需宝石镜 940、水镜 2760、星汉镜 2100。库存分别为 3000、8000、5000 时可供 2 人，剩余 1120、2480、800；再养一人缺水镜 280、星汉镜 1300。

仅衡量修为材料，等级需满足解锁条件，五铢钱、兵书和等级突破材料另计。使用完整当前库存独立试算，不扣其他计划的需求、不预留或消费库存，不创建真实密探、培养目标、日程或升级交易，不对接 Maa 自动执行/计数。

## 库存与交互

复用养成规划已有库存读取与账号边界。弹窗刷新只触发库存读取，不重新读取、保存或重排培养计划。同步期间隐藏旧人数；失败或数量非法时显示错误与重试入口，不当作零库存。成功读取的空库存按 0 人处理。

桌面为三张结果卡与五列用料表；手机为三行展开结果，保留单人需求、库存、培养后剩余和下一人缺口。一次只展开一组。弹窗内部滚动，窄屏仍保留遮罩边缘。关闭按钮、点击遮罩或 Escape 关闭并恢复入口焦点；下拉展开时 Escape 先收起下拉。

## 验证范围

定向 Node 测试覆盖人数瓶颈、整数边界、共用属性组、缺口、非法/未知库存和区间；Vitest/jsdom 覆盖即时试算、刷新、错误恢复、关闭焦点、无需培养清单、只读边界以及账号切换时的迟到响应。

真实布局与触控需人工验收：以 390px 和 1440px 打开弹窗并选择 13→17，展开三组、刷新库存、关闭重开；补查 320px、767/768px 切换、手机横屏及深色主题。确认内容可读、无横向溢出、底部关闭可达，以及原清单和日程编辑未受影响。组件检查不代表浏览器视觉或真实服务器同步已验收。
