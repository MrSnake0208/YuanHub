# 库存永久成就系统构想

状态：产品构想，暂不进入开发  
更新时间：2026-08-18  
适用范围：库存账号的长期奖励记录

## 1. 定位

永久成就用于记录低频、难得且值得纪念的奖励事件。它不同于可随日期范围实时重算的周期统计：成就一旦解锁，应跨日期筛选、刷新、浏览器和设备保持状态，首次提醒也只能出现一次。

当前阶段不实施永久成就，不修改后端契约，不在前端使用 `localStorage` 模拟永久解锁。

## 2. 候选成就

| 分类 | 示例 | 触发思路 |
|---|---|---|
| 巧遇 | 双星同框、三星同框 | 单条奖励记录中出现 2/3 位特别关注密探 |
| 牵挂 | 念念有回响 | 一个统计周期内覆盖全部特别关注密探 |
| 重逢 | 久别重逢 | 某位关注密探间隔较长时间后再次获得 |
| 积累 | 金叶满仓 | 白金币等价值达到经过数据校准的阈值 |
| 连收 | 白金币七日连收 | 连续自然日白金币等价值大于 0 |
| 偏爱 | 本期偏爱明显 | 偏爱指数达到阈值且心纸样本量充分 |

具体名称、门槛和稀有度需要结合真实账号数据分布确定，避免成就过易、长期无法解锁或被少量数据误触发。

连续收获只考虑白金币等少数有明确日常意义的重要道具。关注密探的连续收获不作为普通成就，除非后续数据证明它确实足够稀有且有趣。

## 3. 后端持久化要求

可靠的永久成就需要后端保存至少以下字段：

```text
account_id
achievement_id
achievement_version
unlocked_at
seen_at
trigger_record_ids（可选，用于解释与审计）
favorite_agent_ids_snapshot（关注类成就需要）
```

建议对 `(account_id, achievement_id, achievement_version)` 建立唯一约束，使重复导入、重复计算和并发请求保持幂等。

关注类成就需要保存解锁时的关注列表快照。否则用户后来增删关注对象，会改变历史成就的含义。

## 4. 未来接口能力

具体路径待后端评审，能力范围包括：

- 查询某库存账号的成就、进度与解锁时间；
- 返回新解锁且尚未查看的成就；
- 批量标记成就已查看；
- 导入奖励记录后幂等地评估受影响的成就；
- 对补录的历史记录正确执行回溯解锁；
- 多项成就同时解锁时返回一个稳定批次，避免重复提醒。

永久成就默认不进入库存交换档案 v2，也不随库存导出迁移。若未来需要迁移，应另行定义用户偏好与成就档案协议，不能直接扩充现有奖励记录。

## 5. 解锁表现

视觉采用“账簿印章”或“藏书票”，不使用通用奖杯墙。首次解锁在成就区域原位展开，避免全屏阻断弹窗和角落通知：

- 单次动画约 600 至 800ms，只使用 `transform` 和 `opacity`；
- 多项同时解锁合并成一次提示，例如“新得 3 枚印记”；
- 普通刷新、切换日期和重复导入不能重播；
- `prefers-reduced-motion: reduce` 下直接展示最终状态；
- 绛红只用于印章这一处小面积强调，其他颜色沿用现有设计令牌。

只有首次解锁永久成就播放这类动效。周期趣味统计不产生未读标记，也不因切换日期范围播放解锁动画。

## 6. 启动条件

开始实施前需要同时满足：

1. 已积累足够真实数据，可以校准成就阈值和稀有度；
2. 后端确认成就归属库存子账号，并完成持久化模型评审；
3. 明确补录历史记录、删除奖励记录和修改关注列表时的成就语义；
4. 前后端确定成就版本升级与废弃规则；
5. 确定永久成就是只增不减，还是允许在原始记录删除后撤销。

在这些问题确认前，永久成就保持为文档构想，不进入开发排期。
