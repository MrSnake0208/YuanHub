# 月卡剩余天数界面实施计划

范围：按用户确认的效果图重排库存「管理」弹窗；库存主体、记录领取及后端协议保持原能力。延续本任务的静态 UX 审查，实际浏览器由用户验收。

1. 月卡默认展示剩余天数，设置/修改时只输入天数及今日是否已领取。起止日期留作内部协议；截止日仍为业务今天 + N，包含截止日，倒数到 0 后不再新增后续日期的邮件。
2. 白金币/符传各自设置；未开启的月卡保持紧凑。单封奖励、数量与分组通过「调整」展开，保留所有旧数据。底部合计和保存独立于滚动内容，无修改时可直接完成。
3. 复用服务端 throughDate 与每日投递去重；不在前端增加邮件或代替领取。跨日安全重读；未保存草稿不被覆盖，跨日草稿要求重读核对。
4. L2 展示/交互，保存映射按 L3 数据正确性定向验证：天数换算、到期、今日选择、无效输入、取消、跨账号与重复编辑不手加邮件；不使用共享数据库测试、不启动浏览器或额外服务。

交付检查：定向 Vue 组件测试及相关 diff；人工在 390/768/1440px（含窄屏/软键盘）核对设置、调整和底部按钮。实现结果另记于直接相关的 inventory-quick-maintenance 文档。
