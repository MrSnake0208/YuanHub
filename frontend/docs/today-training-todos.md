# 首页今日历练与待办

首页「我的养成计划」在成员摘要前展示当前游戏子账号、当前培养清单的今日历练，包括历练类型、层数、次数和体力合计。点击「加入今日待办」后，上方出现独立的待办卡片；养成卡片缩为已加入摘要。沿用现有 `operatorGrowthTracking` 功能开关，日程来源为已保存的云端体力日程。

## 操作与数据边界

- 「查看完整规划」进入养成页的追踪页签。未保存、无今日安排、方案不可执行、待重算和不支持的版本分别提示；合法的零安排显示「今日无需刷取历练」。首页不执行求解，也不自动将临时推荐保存为日程。
- 按北京时间 05:00 划分业务日期；换日清空当前显示并读取新一天，不自动导入、不顺延昨日未完成项。切换用户、子账号或当前清单后重读各自数据。
- 点击勾选表示完成该行剩余次数，可以取消。只记录完成状态，不扣体力、不改库存、不改变规划、不触发 Maa。暂不提供逐次计数或跨清单合并。
- 规划变化后点击「更新今日待办」并确认。按历练类型和层数保留完成次数；次数增加显示剩余差额，移除或减少项目仍保留已完成记录。移除项目取消完成后不再显示。新安排加已完成次数超过同类每日 6 次时禁止更新，需先调整规划。
- 页面重新可见、账号事件和重连会重新读取；保存中、确认中先延后刷新。写入失败或版本冲突锁定操作，明确「读取最新状态」后核对并重试，不自动重放不确定的写入。

隐藏「我的养成计划」不影响已加入的待办；隐藏「今日待办」会隐藏活动及历练待办，数据仍保留。两种显示共用一个 `TodayTrainingDaily` 实例和请求状态，使用已有 `training` / `checklist` 偏好 ID，不新增偏好结构。

## 部署及持久化

后端先部署新增 `/v1/operator/training-plans/{planId}/daily-tasks`，再部署前端；回滚按相反顺序。新前端连接旧后端会显示读取错误，不会把 404 当作未加入状态。无需迁移已有规划或库存；首次加入才产生独立 `operator_daily_tasks` 记录，集合按用户、子账号、清单、业务日期隔离，删除子账号时一并清理。

后端只接受版本号与完成标记，从服务器保存的日程提取待办，不接受客户端传入刷取内容。读接口不修改数据；写接口校验当前清单、当天日期、权限与版本，事务内使用账号写栅栏和待办 CAS，提交后发布账号事件。接口契约见后端 `docs/operator-daily-tasks.md`。

## 验证与人工验收

风险 **L3**：新增私有 API、持久化、并发更新和账号级联清理。已新增纯函数、组件、API、服务、HTTP 契约和 Mongo 容器测试，更新账号删除测试。容器回归、相关既有回归和真实浏览器验收由用户执行，静态/模拟 DOM 检查不能证明实际手机布局或服务器同步。

用户最小补充检查（仓库根目录起）：

```bash
cd BackEndV3-Share
./gradlew integrationTest --tests '*OperatorDailyTasksMongoTest' --console=plain
./gradlew test --tests '*SubAccountServiceTest' --console=plain
```

容器测试仅使用 `TestMongo` 创建的自有可抛弃 replica set，不连接开发或生产服务。前端既有调用方回归如需运行：

```bash
cd YuanHub
npx vitest run behavior/todayTrainingPlans.spec.js behavior/todayComingSoon.spec.js behavior/operatorEntryDefaults.spec.js
```

人工检查（390px 手机和 1440px 桌面）：

1. 准备含「地水 10 层 ×1、12 层 ×4」的已保存日程：首页应为 5 次 / 100 体力；加入后出现 2 行待办、摘要收起，再次进入不重复创建。
2. 勾选及取消一行：成功后更新进度；刷新或第二设备读取同一子账号/清单应一致。断网保存不得显示成功，恢复后先读取最新状态。
3. 修改并保存今日方案：出现更新提示；确认后保留完成次数。切子账号/清单以及北京时间 05:00 换日，不应显示其他范围的待办。
4. 隐藏养成模块：已加入待办仍可操作；隐藏待办再恢复：完成记录仍在。完整规划入口应进入追踪页签。
5. 检查长清单名、窄屏文字换行、Tab/Space 操作、更新确认弹窗、加入后的定位与焦点；真实对比度、触控和屏幕阅读器效果待人工确认。
