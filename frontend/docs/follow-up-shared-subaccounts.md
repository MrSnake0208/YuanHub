# 后续任务：统一子账号与跨域 Token

本次合并只交付库存页面的界面与交互改动。密探功能、账号模型和开放接口相关冲突暂不在本次变更中解决，后续按本文重新设计和实现。

## 目标

每个用户子账号同时支持库存和密探管理。库存数据与密探养成数据仍保持各自的业务模型，但共享同一个 `account_id`、名称、所有权和生命周期。

## 待完成事项

1. 后端将库存子账号和密探子账号统一为一套账号资源，统一处理创建、改名、归属校验和删除级联。
2. 密探页面改为使用统一账号列表，不再维护独立的密探账号 CRUD。
3. 库存、密探和 OpenAPI Token 统一绑定同一个 `account_id`。
4. OpenAPI 权限同时支持 `inventory:*` 和 `operator:*`；评估是否允许一个 Token 携带两个数据域的 scope。
5. 个人中心重新设计 Token 生成界面：账号选择只保留一份，权限按库存/密探分组或使用跨域预设。
6. 更新接口契约、前端 API 封装和契约测试，覆盖账号隔离、混合 scope、删除级联和权限拒绝。
