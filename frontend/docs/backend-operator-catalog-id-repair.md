# 密探目录 ID 变更修复

## 已确认的问题

2026-09-19 核对公开 API：公共图鉴只包含 `char_129_zhoutai`（周泰）、`char_130_chenlin`（陈琳），库存目录还包含已删除的 `char_130_zhoutai`、`char_129_chenlin`。两份响应的 `catalog_version` 相同，因此仅比较版本无法发现残留。

库存页的心纸清单已经使用公共图鉴，但网页奖励补录仍读取库存目录。TXT 按名称匹配时会找到两个周泰。该匹配不读取用户养成；删除某个子账号的旧养成不是修复公共目录的前提。

后端原来在新增、修改公共密探时同步 `entity_catalog`，删除时没有同步；库存目录又独立从旧资源补齐密探。子账号 `operator_current` 保留旧 ID，前端完整编辑器要求该 ID 存在于当前图鉴，因此无法编辑旧条目。

## 修复行为

- 网页补录的道具来自库存目录，密探来自公共图鉴；每次打开刷新目录与预览。真正的同名歧义仍拦截；不根据名称改写 JSON 中的旧 ID。
- 后端 `EntityCatalogService` 的密探列表和新增记录校验直接读取 `OperatorCatalogService`。停止向 `entity_catalog` 同步、播种密探，既有 agent 行不再参与公开目录和新写入校验。
- 库存导入仍先完整校验再写入；已接收且正文相同的旧流水保持幂等成功，正文不同返回冲突，新流水中的旧 ID 拒绝。
- 已删除密探的特别关注仍可以取消。
- 「当前养成」单独列出图鉴中已删除的旧 ID，并提供确认后移除的入口；这些记录不再进入正常养成卡片或已招募统计。公共图鉴读取失败时不判定孤儿记录。

## 旧养成清理接口

`DELETE /v1/operator/current/{operatorId}?account_id=...`，普通登录 JWT。

- 只允许本人子账号，归属从 JWT 校验；账号不存在或不属于本人返回 404 `account_not_found`。
- ID 仍存在于公共图鉴时返回 409 `operator_still_in_catalog`。
- 在事务中移除此子账号各版本（含旧 `universal` / `*`）下该 ID 的当前养成；保留其他 ID、其他子账号和历史导入记录。
- 每个受影响版本写入 `reason=catalog_removed` 的校正审计，并保留删除前的练度字段。删除历史导入记录触发重放时再次执行清理，避免旧条目复活。
- 重复清理已不存在的条目返回成功，不重复写入清理事件。
- 此操作清理当前养成，不迁移到新 ID，不处理心纸库存、标注、目标或规划清单。

## 发布与使用

先发布包含新 DELETE 接口和目录读取修复的后端，再发布前端。后端发布后，库存公开目录自动排除残留 ID，无需删除生产数据库中的历史目录行。

旧养成不会自动清空。用户先导出需要保留的资料，再进入目标子账号的「当前养成」，核对完整旧 ID 后点击「移除旧养成」。若要保留练度，应在正确的新 ID 下重新登记；不能按数字序号互换，也不能将同名心纸库存直接相加。

本次开发只修改源码、运行测试及只读核对公共接口，没有部署服务或执行线上账号数据删除。
