# 库存操作历史：写入完成上下文隔离（A2）

本补丁落实 [Phase 2 复盘第 3 节的 A2](responsive-pilot-review-phase2-20261013.md#3-缺陷与风险清单仅建议不修源码)。风险为 **L3**：涉及账号、登录身份和异步写入完成的隔离。源码及合成测试已完成定向验证，真实 UI 验收仍待用户执行；A1 尚未实施。

## 变更与不变量

- 业务仍由 `src/pages/inventory/index.vue` 单独持有，两个历史视图继续调用同一删除函数，恢复入口仍在父页。视图、CSS、API 参数及后端库存重放契约未变。
- 删除确认、写入返回、历史刷新返回、当前库存刷新返回、错误提示及 finally 均检查发起 generation、账号、登录状态及 disposed。既有同步 watch 在账号、登录状态、登录身份或游戏变化时递增 generation，因此 A→B→A 以及另一身份复用同一账号 ID 都不能复活旧操作。
- 每个有效 generation 同时只允许一个写入；确认返回后再次检查 busy。上下文失效立即清除旧 busy、动作错误和撤销提示；finally 仅能释放自己 generation 的锁，同 record ID 的新操作也不会被旧 finally 解锁。卸载同步释放旧锁，Promise 可以自然结束。
- 有效删除仍更新本页记录与撤销提示，恢复仍移除对应撤销提示；两者均刷新历史及当前库存、失效统计。有效失败保留对应错误和可重试入口。resize 不递增业务 generation，不额外读取或写入。
- 已发起的服务器写入可能仍成功。过期结果只停止本页后续副作用，不取消、回滚或补发写入；切回账号后的正常读取结果取决于服务器写入与读取的时序。

## 用户人工验收

只使用可丢弃测试记录；沿用已有开发服务，不为验收重启服务。

1. `/inventory` → 操作历史：在 390/1440px 打开删除确认后取消，记录保留、按钮可再次操作、焦点可达。
2. 正常删除后确认历史和当前库存更新、可撤销；撤销后记录恢复。重复点击不重复提交，失败后可重试。
3. 请求期间从其它合法入口切账号/身份/游戏或离开页面，再返回；新上下文不出现旧错误或撤销提示、按钮不残留禁用。账号 A→B→A 也应隔离旧操作；不要把客户端丢弃结果理解为服务器撤销写入。
4. 请求期间在 640/641px 两侧切换宽度：状态连续、只有一份列表，尺寸变化不额外触发业务请求，焦点不丢到页面外。

完整浏览器、真机、真实后端竞态、全量回归和生产构建均未执行。用户明确验收 A2 后，才进入 A1 的独立改动。
