# 养成规划云端接入

本页说明当前实装，与早期规划文档有差异时以当前页面和接口实现为准。

## 保存边界

- `OperatorGrowthTracker.vue` 保留材料缺口、共享库存分配、逐日推荐、目标天数试算与历史展示算法。
- `useOperatorPlannerCloud.js` 管理按子账号隔离的工作区与每个清单的日程，负责本机迁移、加载与保存状态。
- `operatorPlannerRemote.js` 转换 API 字段，保留动态密探 ID、资源键与日期键。固定快照读取时不按新规则重算。
- `plannerSnapshotWriter.js` 串行提交 revision 更新并合并待发出的日程修改；失败草稿保留在本机，重试先核对响应丢失时可能已经提交的请求。版本冲突不自动覆盖云端。

保存预测不改写实际库存、奖励流水或密探练度。默认清单继续使用特别关注与云端 growth-targets；自建计划持有独立目标。

清单顶部常驻「添加密探」「新建清单」「管理清单」文字入口。「添加密探」打开当前清单的成员编辑器，默认展示未选成员，特别关注清单也可加入非星标密探；「新建清单」建立另一张清单。「养成中」快捷筛选仅显示当前账号已拥有且养成状态为养成中的目录成员，未拥有或没有练度档案的图鉴条目不纳入；筛选和搜索不清空已选成员。勾选保存只调整清单成员，不修改星标或养成状态，也不建立随养成状态自动变化的动态清单。

体力日程展示刷取层数与次数建议；Maa 自动执行暂未支持，保存到云端不表示已下发或执行。

清单名称与来源说明位于操作栏上方；宽屏将成员管理与日程操作放在同一行，窄屏按组换行。仅「添加密探」采用深色主按钮。「刷取材料备齐度」表示当前库存对清单可规划刷取资源需求的覆盖比例，不是实际练度进度；密探卡片中的「目标进度」仍按实际等级、修为和化极相对目标计算。「清单心纸库存」展示当前清单成员的已有心纸合计。

「添加密探」打开专用选人视图，显示目标清单，不展示改名和删除入口；默认筛选未选成员，也可切到「养成中」。已有成员保持选中且不能在添加视图中移除，底部仅统计本次新增人数，未选新增成员时不能提交。取消不会保存草稿；改名、移除成员和删除仍在「管理清单」中操作。手机端（≤700px）打开添加视图时聚焦标题，点击搜索才唤起输入；桌面端保留搜索聚焦。手机窄屏的四项快捷筛选保持单行，空间不足时在控件内部横向滚动。

最近一次成功读取或保存的云端日程会按子账号和培养计划缓存在 `localStorage`，进入页面时可先用于快速展示，随后仍向云端校验并以云端响应为准。缓存随规划规则版本失效，不承接离线编辑，也不改变云端作为权威数据源的边界；清除浏览器站点数据只会移除这份加速缓存和未提交草稿，不会删除已保存的云端日程。

每日获取或支出编辑先保存账本与现有安排，只有点击「重新计算当日及后续日程」才重新推荐。完整日程的可选 `context.plan_baselines` 保存各日期首次编辑前的计划，用于跨刷新恢复提示；未重算且现有安排不足以完成时，通过 `result.awaiting_recalculation` 标记待重算，`eta_days` 为空；沿用原有 `horizon` 状态枚举以兼容现有校验。元数据随完整快照原样保存。重算保留当天体力来源、派遣、自定义支出与未来手工日，重新安排当天历练和 6-24。详见 [日程编辑与回顾](operator-stamina-schedules.md)。

## 规划条件：首页摘要与按需编辑

「调整设置」保留「规划条件 → 方案对比 → 编辑每日」三步和原培养清单。首页展示三个模块：培养策略、日常安排、体力来源。常规模式可直接选择「整体完成」或「优先完成密探」，仍分别以整张清单最早备齐、清单顺序的备齐日期为目标；无需打开高级设置即可进入方案对比。

两种模式始终可切换。「按目标天数规划」保留目标天数、截止日期选择和原有最低白金币独立试算规则；体力储备从折叠入口编辑，不改变已到账体力与待领取整笔储备的含义。切换子账号清空未保存的期限/储备试算，不把上一个账号的数据带入新账号。

四个摘要入口分别打开对应设置，桌面（≥768px）为右侧抽屉，手机为全屏编辑面板。标题、独立滚动正文和保存/取消操作保持可达，窗口宽度变化不重建编辑器。输入草稿时不改动首页摘要；保存成功后关闭面板并更新，失败保留草稿和原有同步恢复提示。关闭未保存修改需确认放弃，关闭后恢复入口焦点。初始化、打开、取消和预览均不写入云端或真实库存。

| 设置 | 保存范围 | 对已有日程的影响 |
| --- | --- | --- |
| 派遣与购买体力 | 当前培养清单的日程偏好 | 沿用原日程快照保存与修订规则 |
| 目前能刷的关卡 | 当前子账号工作区 | 一次保存四组关卡，沿用原日程修订规则 |
| 月卡与商店体力 | 当前子账号长期来源设置及当前清单日程 | 保存后直接同步今天及未来的月卡两项，包含手工日期，保留其他收入和手工支出 |
| 其他每日固定来源 | 当前子账号长期来源设置 | 未固定的推荐沿用新来源；已经保存的日程需单独预览并应用 |

月卡摘要按今天的有效期、档位与奖励开关展示；无月卡时，商店字段有数值也不会被判定为有效月卡。预设仅在主动切换档位时使用，重开面板不重置自定义金额或日期。商店领取按已保存开关纳入预测，仍需玩家实际领取，预测不会改写库存。固定来源列表可直接修改名称、数量和每日固定开关；选择已有来源即加入草稿，同一来源不能重复加入。合计仅包含启用的其他固定来源，不把月卡重复计入其中，也不把未领取体力当库存。

月卡保存需等待设置和日程均确认成功，才关闭面板并提示同步完成；部分失败可关闭面板使用现有重试入口，或处理云端提示后重新保存原值补同步。不会批量改写其他清单，目标天数模式同样支持月卡直接同步。

其他固定来源沿用「更新已有未来日程」，位于体力来源模块的折叠区域，在常规模式提供。选择今天或未来的开始日期，决定是否替换手工日期中的对应来源，先「查看将修改的日程」，再「应用到未来日程」并最终确认。继续保留支出、一次性来源和过去记录；默认保留手工日期。确认期间账号、清单、版本、来源或预览发生变化时，旧确认不会继续写入，必须重新预览。

这次验证使用 Node/Vitest/Vue Test Utils（jsdom）、源码编译和生产构建，不运行浏览器自动化。人工验收：在 `/operator` 的养成规划中打开调整设置，使用 390/768/1440px 检查四个入口、日期字段、保存/取消返回位置和下一步；补查 320/430/900/901/1024px 及手机横屏、真实软键盘，确认无横向溢出或遮挡。

## 编辑每日：添加体力支出

「添加支出」在支出卡片内展开，不覆盖体力获取。普通渠道点选后按原 ID 增加一次；历练先选择当前配置允许的层数，展示规则表中的单次消耗，再点「添加到支出」，同渠道同层数沿用原条目累加。自定义支出在同一区域填写名称、单次体力、次数和可选材料；取消不入账，确认后沿用原自定义结构，仍可编辑和删除。草稿输入即时更新本地表单，已保存条目仍在确认输入变更后进入保存队列。

本地账本先显示已应用的修改，卡片内提示正在保存；收到云端确认后才收起面板、提示保存成功并短暂强调对应行。入队被阻止时保留选择或表单；本机草稿写入失败时回滚本地账本。异步失败的未确认内容保留，并在操作区提供前往原同步恢复区的入口；重试复用原待保存快照，先读取云端核对响应丢失的提交，不能重新点击添加代替恢复。显式放弃时读取云端，不将其误报为添加成功。

关闭或 Esc 不提交未完成选择，关闭后恢复添加按钮焦点；切换日期、子账号或培养清单会清理局部选择。添加不触发自动日程重排，仍通过原「重新计算当日及后续日程」按钮操作；体力获取、月卡、6-24固定/重复安排和完整资源总览保持原有规则。

人工验收：在「养成规划 → 体力行程 → 编辑每日」，以 390/768/1440px 检查默认、渠道、历练、成功、自定义五状态；补查窄屏、Esc/Tab和真实触控。确认恢复/刷新后的记录与次数、错误后的输入保留、超支警告，以及获取、6-24重复安排、重新计算和返回路径。组件/规则检查不能证明浏览器布局和真实云端保存已验收。

## 所需后端接口

以下接口使用普通登录 JWT，query 参数 `account_id` 指定子账号，响应为既有 ApiResult。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/v1/operator/training-workspace` | 清单、独立目标、当前清单、通关层数 |
| GET / PUT | `/v1/operator/training-plans/{planId}/stamina-schedule` | 偏好、顺序、自定义安排及完整固定日程 |
| POST | `/v1/operator/training-plans/{planId}/members/{operatorId}/remove` | 原子移除与可选毕业，保留备注 |
| POST | `/v1/operator/training-workspace/import-local` | 工作区、日程与导入回执同事务提交 |
| GET | `/v1/inventory/records` | 读取近 30 个业务日的密探奖励流水，前端按 05:00 业务日聚合 |

工作区与日程分别维护 revision，PUT 携带 expected_revision。日程 schema_version=1、rules_version=13，并保留时区字段以兼容既有数据；当前 YuanHub 固定使用 `Asia/Shanghai`（北京/上海时间），每天 05:00 作为新一天的开始。历史日程日期键保持不变，跨设备旅行不会改变日期边界。

心纸统计从流水接口读取 `entity_type=agent` 在 `[业务日05:00, 次日05:00)` 内的记录，并在前端按 `Asia/Shanghai` 业务日聚合近 30 个业务日期内的正数 `reward_delta`；每位密探平均值为 `acquired / active_days`，保持页面当前口径。这样不依赖后端把日期聚合从自然日午夜切换到 05:00。

## 本机迁移与恢复

保留原 `operator-training-workspace:v1` 和 `cultivation-stamina-planner:v1` 本机数据。首次接入会展示导入预览；云端已有内容时，本机清单作为新增自建计划导入，默认特别关注在导入时转为固定成员快照。用户可选择只使用云端并保留本机备份。

迁移请求和 migration_id 在发送前完整保存在本机，失败重试复用相同回执。明确的版本冲突可重新比较。日程保存失败时可重试、导出待保存 JSON，或明确放弃草稿并读取云端；未完成保存会提示离开页面，账号切换不会应用旧账号请求的响应。

账号 SSE 的 `operator_training_workspace`、`operator_stamina_schedule`、`operator_annotation`、`operator_growth_target`、`operator_favorites` 以及断线重连会触发对应补读。首次建立 SSE 连接不重复执行页面初始化时已经发出的读取；断线重连才进行补读。工作区和日程补读并行执行，同一时刻的重复刷新请求会合并。有未保存草稿时先处理草稿，避免被事件刷新覆盖。

体力获取、支出次数、单次体力和单次产出的数字输入在确认变更（失焦或回车）后进入保存队列，不再随每个键入字符发送一次保存。保存器仍会串行提交并合并尚未发出的连续修改。

先部署对应后端，再部署前端。后端 MongoDB 需要支持事务。养成规划继续使用 `operatorGrowthTracking` 功能开关，生产默认关闭；上线开放按 [功能开关规则](standards/feature-flags.md) 执行。

```bash
node --test test/operatorPlannerCloud.test.js test/operatorGrowthApi.test.js test/operatorTraining.test.js test/cultivationPlanner.test.js test/fixedPlannerSchedule.test.js
npm run build
```

测试涵盖当前模拟器快照往返、独立清单迁移、动态资源键、连续保存、响应丢失、冲突与草稿恢复。浏览器验收还应检查账号切换、迁移预览、毕业并移除及已有历史日程的显式更新。

## 常用自定义支出与持续每日安排

在「编辑每日 → 添加支出」的原网格末尾选用常用项目，标题旁「管理常用支出」可创建、编辑和移出。也可在现有自定义支出卡片点「固定到支出列表」，只保存模板，不再次添加当天支出；同ID重复固定会打开已有项目。同名不同ID保留。点击常用项目首次添加1次，已有同ID则增加1次。

常用模板使用独立 `GET/PUT /v1/operator/custom-spend-templates`，按登录大账号共享，跨子账号和游戏保持；退出或更换大账号清空页面数据，失败草稿按大账号隔离。每日次数和启停则保存在当前子账号的当前培养清单，互不带入。模板改动只影响以后添加；已有每日安排使用其副本，可在设置中主动采用最新模板。移出列表不会停用其他清单的规则。

自定义支出「设为持续每日安排」设置次数和生效日期，先预览再确认；无结束日期，直到主动停用。兰台每次10体力、每天10次即固定100体力，其余预算再由推荐分配；零体力据点产出也计入。产出仍由玩家填写，经验按经验值录入，不新增游戏掉落预设。「规划条件 → 持续每日安排」可找到已有规则，模板移出后仍可修改或停用。原有自定义批量操作改名「应用到日期范围」，仍只覆盖选中范围。

直接修改、删除或增加每日规则项目仅影响当天，标记为单日例外；删除后显示「当天已跳过」，可「恢复每日安排」。规则改次数或停用保留单日例外；取消尚未开始的安排也保留最后项目资料，删除模板后仍可重新启用。整份日程重设清除未来手工例外但保留长期规则。启用前预览会列出例外、旧同ID项目的接管数量和被替换的后续版本；任一天预算不足均整次拒绝，指出日期。当前窗口外的来源变化在更新日程时检查。最多32项规则，每项最多366个日期版本。

长期规则不会写满90份手工记录。单次模拟仍最多90天，之后更新或重设继续带入。材料备齐后停止自动刷取，未来日期显示「规则预览 / 未保存日程」，仅浏览不保存、不给真实库存入账。目标天数试算计入长期规则，但不带逐日手工修改；费用累计仅覆盖有限实际求解日程。遇到旧客户端能力冲突请更新页面，勿删规则降级保存。

人工验收（未运行浏览器）：390px手机和1440px桌面各检查一次从原网格添加兰台、每日10次、跳过一天再恢复；刷新及切换子账号确认模板共享而次数独立；原派遣、历练、6-24和临时自定义添加仍可直接使用。真实布局、触控、生产网络与移动端性能由用户手动验收。
