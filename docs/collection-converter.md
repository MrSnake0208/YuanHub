# 卡池与活动表格转换

需要 Python 3，无需安装第三方包、启动服务或打开 Excel。源 `.xlsx` 不会被修改，也不会连接数据库或自动导入网站。

## 一键转换

macOS 双击仓库根目录的 `转换卡池与活动.command`，默认读取根目录的 `YuanHub信息收集表.xlsx`。后续使用相同文件名更新表格后，再次双击即可。

转换其他表格，在仓库根目录执行：

```bash
python3 scripts/convert_collection.py "/路径/后续表格.xlsx"
```

默认在表格旁创建 `<表格名>-json` 文件夹，生成 UTF-8 的 `卡池.json`（`pools` 对象）和 `活动.json`（`schema_version: 1`、`items` 对象）。同路径同名生成文件会被覆盖；原表格不变。可用 `--output-dir "/路径/输出目录"` 指定目录。

## 导入

1. 卡池：进入 `/recruitment/admin` → 高级维护 → 批量导入 JSON，选择 `卡池.json`。
2. 活动：进入 `/calendar/admin` → 活动目录 → 批量导入，选择 `活动.json`，校验预览后确认。活动会默认启用并公开。
3. 活动超过 **200 条或 1 MiB** 时，汇总文件供保存和查阅，不能整批导入。额外生成可导入的分批文件：

```bash
python3 scripts/convert_collection.py "YuanHub信息收集表.xlsx" --split-activities
```

仍保留两个汇总 JSON，额外生成 `活动-分批-001.json` 等，每批最多 200 条。依次导入分批文件即可，不必再导入活动汇总。旧分批文件不会自动删除；以后表格变小时，只使用本次终端报告的批次数，或指定新的输出目录。生成的分批文件若超过 1 MiB 会报错，需缩短备注或拆分源表。

当前表格含98条卡池、282条活动；转换时按用户补充默认加入两游戏各一个“绣衣天下”常驻池，共输出100条卡池。第 226 行“何意泰山倾”和第 227 行“影战”未填结束时间，按持续活动保留，`end_date:null`。完整活动需要两批导入。

## 表格约定与映射

读取名为 `汇总` 的工作表；只有一个工作表时允许改名。首个非空行是表头，列顺序可变，必须包含 `游戏 / 一级分类 / 二级分类 / 名称 / 开始时间 / 结束时间`。可选 `密探UP / 洞窟备注 / 男主`；`持续时间`不参与计算，以起止时间为准。支持 Excel 日期序号（包括 1904 日期系统）和 `YYYY-MM-DD`、`YYYY-MM-DD HH:mm`、斜杠日期；不支持旧 `.xls` 或未保存计算结果的公式日期。

| 表格分类 | JSON 映射 |
| --- | --- |
| 招募 → 限定 / 复刻 / 照影 / 自选 / 常驻 | 卡池 `limited / rerun / zhaoying / choice / permanent` |
| 活动 → 活动 | `ACTIVITY`，不猜测活动规模 |
| 活动 → 大型活动 / 中型活动 / 地宫 / 泰山府 | `ACTIVITY` + `LARGE_EVENT / MEDIUM_EVENT / UNDERGROUND / TAISHAN_FU` |
| 心纸营建 → 历险 | `ACTIVITY` + `FURNITURE`，原分类保留在说明 |
| 心纸营建 → 神秘洞窟 | `ACTIVITY` + `FURNITURE` + `MYSTERIOUS_CAVE` |

活动结束时间留空表示持续进行，写入 `end_date:null/end_time:null`，可单独保留开始时刻。活动时间保留到分钟，时区为 `Asia/Shanghai`；只有日期时不补时刻，有限档期一端有时刻而另一端仅日期时，将日期端表示为 `00:00`。洞窟左右备注、男主写入活动公开说明。卡池接口只接收日期；原表有具体时刻时保留在 `source_note` 并提示。

普通 UP 按顿号、逗号、分号、换行拆分为稳定槽，JSON 中 `operator_id:null`。网站导入时按图鉴唯一同名且同游戏的 4 星/5 星密探（含照影 SP）自动绑定；未知或重名保留占位，需在管理页核对。不做模糊匹配。4 星仅计获得次数，不影响绝密抽数和保底；照影 SP 按 5 星统计。含“范围”的自选/历史范围描述只存 `source_note`，不生成虚构密探。

普通卡池 ID 由“游戏 + 名称 + 开始日期”生成，不依赖行号；常驻池由“游戏 + 名称 + permanent”生成，补充开始日期不改变身份。重排、追加、补充结束日期或 UP 不改变 ID。同 ID 的重复记录跳过、内容冲突报错；活动同名同档期同游戏的重复/冲突同样处理。缺开始日期行跳过并报告，非常驻卡池仍要求起止日期齐全；常驻池开始日期允许留空，结束日期始终为null（无限期），表格有结束日期时提示并忽略；其他不支持的分类、无效日期、非法游戏或冲突会让整次转换失败，校验失败不会覆盖上次结果。

网站卡池导入仅按 `pool_id` 判重；曾通过其他来源建立、ID 不同的同名卡池仍可能重复，首次导入前核对管理目录。卡池及活动导入均不覆盖已有记录；补资料后重新转换，不会更新数据库中已导入条目，需在管理页编辑。持续活动结束后，应编辑已有活动补齐结束日期；直接重导不同结束日期会按现有导入自然键视为另一条记录。

## 最小验证

风险等级 L3：持续活动涉及活动接口、持久化与日历空结束日期语义。脚本测试覆盖日期精度、UP 范围、稳定 ID、分类备注、缺开始日期、空结束日期、重复冲突、XLSX 读取、分批完整性及失败时保护旧结果。

```bash
python3 -m unittest discover -s scripts -p 'test_convert_collection.py'
```

## 两游戏常驻池

一键命令与CLI默认补充原表没有的“代号鸢 / 绣衣天下”和“如鸢 / 绣衣天下”，类型permanent、起止日期均为null、无虚构UP。表内已提供同游戏同名招募池时不再补一份；建议分类填写“招募 / 常驻”。源Excel不修改。站上显示“常驻 · 无限期”；尚无开始日期，不纳入按日期编排的活动日历。首次导入创建这两条，之后按固定pool_id跳过。
