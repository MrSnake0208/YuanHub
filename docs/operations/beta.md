# 内测报名与管理界面

## 使用入口

- `/beta`：公开规则、当前开放状态、本人资格、自助报名和取消候补。
- 本地测试模式（`./dev.sh beta`）下 `/beta` 会额外显示“本地测试工具”，任何已登录账号都能自助重置隔离的本地活动（`POST /v1/beta/test-reset`，按钮由 `/v1/beta/me` 的 `can_reset_local_test` 控制），不影响正式内测。
- `/admin/beta`：管理当前批次，需要服务器授予的 `beta:manage` 权限；已接入 `/manage` 工作台。
- 登录、注册和找回密码页面均提示“注册统一账号不等于获得内测资格”，并保留安全的站内回跳地址。

首批100人，其中25个为固定 Share 名单的共同预留、75个公开；25%不是Share人数上限，也不是每个老账号保证一份。72小时到期释放未用预留，总容量不变；后续扩至150/200时新增全部公开。页面数字和可执行动作以服务器为准，不能只修改前端常量开放功能。

未配置活动时显示未开放，不展示虚假的剩余名额；维护、暂停新增、公开名额满、全部满、候补和网络错误分别显示。正式开放不再要求内测资格，但个人云功能仍需正常登录。

## 实现接入点

`src/api/beta.js` 统一解析响应；`src/store/beta.js` 保存临时状态、合并请求、隔离账号切换后的旧响应，不能把资格持久化为授权凭据。`src/utils/betaAccess.js` 定义文案、入口跳转和云端请求分类，实际授权仍在后端。

接口沿用 `{status_code, data}` 包装及 snake_case；本人和管理响应均包含嵌套 `campaign`，前端不拼接来自不同时刻的身份与活动状态。服务端失败不会在页面伪装成满员或自动登出。

`router/routes.js` 中仅 `/`（含 `/today`）、`/inventory`、`/operator`、`/operator/quick`、`/star` 设置 `requiresBeta`。公开作业、BOX只读链接、纯本地账房、账户恢复和管理入口保留。`/beta` 自身不得设置 `requiresBeta` 或 `requiresAuth`，否则会造成循环跳转。

`api/request.js` 还拦截个人中心、账房云方案和嵌入式星石页面触发的受限请求。账户连接码查看/撤销不受内测资格限制，创建/改权及云账号操作要求资格。全局账号事件流随权限变化启停，错误/关闭后不继续尝试绕过服务端限制。

站内 `BETA_GRANTED` 通知跳转 `/beta`；通知不是资格凭证。管理变更必须填写原因并携带当前配置版本，审计页面展示内测配置变更前后值。

## 状态刷新

公开说明页进入时加载状态。登录用户查询本人资格；多个消费者共用同一请求。订阅者存在时，在可见页面每30秒、窗口重新获得焦点和服务器预留截止时重新查询；退出/切换账号立即清除旧资格。浏览器时钟不决定名额是否到期。

报名结果未知时查询服务器，不能自行减名额或把一次成功通知永久缓存为 ACTIVE。取消候补只适用于 WAITING，重新加入会排到队尾。

## 开发验证

```sh
npm test
node --test test/betaAccess.test.js test/betaApi.test.js test/betaState.test.js
npm run build
```

新增测试覆盖接口字段、受保护/公开边界、真实路由表、跨账号与异步请求竞争、错误恢复、管理审计字段。现有 API 序列化测试通过独立测试夹具声明已通过资格检查，生产代码没有测试豁免开关。

开发服务由工作区既有 `dev.sh frontend` 管理，部署仍使用正常 `npm run build` 产物。后端动态状态不由构建时 feature flag 控制；不需要添加一个允许所有用户的本地常量。

浏览器联调需覆盖：未登录直达受限页→说明页、注册/登录回跳、报名候补、资格开通后返回原页、维护撤回入口、管理操作版本冲突、桌面及390px手机布局。使用页面模拟接口验证UI与使用真实Mongo验证配额是两项独立验证，不能互相冒充。

新增私有云功能时，必须同时维护前端路由/API分类与后端 `BetaAccessPolicy`，并添加对应测试。不能以隐藏导航、前端构建开关或本地保存的布尔值替代后端资格判断。
