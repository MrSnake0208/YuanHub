# 库存奖励补录与报告补传

入口：库存页面顶部 **记录奖励**；操作历史保留 **导入本地报告**。

## 库存页面常用操作

库存清单、统计报告、操作历史顶部的公共操作区并列「记录奖励」和「更新库存」；「更新库存」保留主按钮样式，写入绝对量 `stock_snapshot`，「记录奖励」打开原手工工作台，写入增量 `reward_delta`。尚无库存的新账号仍优先完成首次盘点，奖励流水不能代替完整基准。

手机端（≤640px）将最近完整盘点标签与时间紧凑排列，一级导航与搜索区等宽；道具/心纸分类使用下划线选中态，与持有状态筛选区分。道具和心纸清单不展示可追踪种类数、已持有种类数及持有比例，心纸保留特别关注数量。资源卡片收紧分类标题与道具之间的留白，保留数量和保底换算。

统计报告以「统计时段」直接展示日期筛选，手机端收紧快捷时段与表单间距；起止日期在可用宽度足够时并排，不足时自动换行。选择快捷时段直接查询，自定义日期后点击「查看统计」查询报告；日期摘要保留包含起止当天的口径，收获条数明确标为「奖励记录」。

操作历史用于查阅、筛选、删除／撤销与追踪入账，只保留「导入本地报告」入口。顶部手工入口、历史报告入口和统计空态报告入口共用唯一工作台；成功后焦点停留在结果区，Tab 与 Escape 继续有效；关闭后焦点回到实际触发按钮，保留当前页签和浏览位置。库存编辑时不能打开工作台，工作台打开或结果未知锁定时不能开始库存编辑。未保存奖励草稿关闭后保留，切换账号／游戏沿用丢弃确认；结果未知时必须原样重试。

## 符传快捷记账

库存页「符传快捷记账」可记录普通符传、天机符传的新获得、使用及白金币兑换。展开后读取当前账号库存与版本；获得奖励填写来源并只增加符传，使用只减少符传。数量支持加减和手输，校准当前总量仍用「更新库存」。仅记录刚发生且尚未入账的操作，已被盘点或报告包含的旧操作不要再次填写。

常规兑换两种符传均为200白金币/张；普通符传另可选「月卡商店」，每份10张、1600白金币，数量按钮按10张调整。月卡商店记录实际购买数量，不判断游戏内购买资格、每周限购或补购；不提供自定义折扣价格。

提交前展示每项增减、原余额与新余额，确认后后端整笔更新扣币、增券和流水。受影响的每项资源都必须有完整或列出条目盘点基准；缺测、余额不足、溢出、账号/游戏或库存版本变化均阻止提交。发生时间由服务端记录，本入口不做历史补录。库存冲突后须重新读取并核对；网络或服务异常导致结果未知时锁定原操作编号和正文，只能原样重试，确认前不能切账号或离开，不要在其他入口再次补录。刷新或强行关闭页面仍可能丢失待确认内容，需先核对操作历史再操作。

操作历史的「资源使用 / 兑换」按有符号数量展示；一条兑换记录包含两项变化，删除/恢复整笔重放。后续操作依赖兑换所得等情况使重放余额为负时，删除/恢复会被拒绝，原记录与库存保持不变。兑换不计入奖励获得量，抽卡资源收支体现两边变动；获得奖励仍计入奖励统计。交换档案继续导出当前快照和可选奖励历史，不导出站内使用/兑换流水，不能作为完整操作历史备份。

人工验收：桌面/手机展开快捷记账，核对普通符传与天机符传各兑换1张均扣200白金币，普通符传月卡商店兑换10张扣1600；活动奖励只增加券，使用只减券；在操作历史删除及恢复一笔兑换，确认两项同时变化。真实布局、触控及浏览器交互需用户检查。

## 手动添加

### 寿春派遣：只补记录

选择「派遣-寿春」，填写实际领取日期、时间、消耗体力和全部碎片，再选择用途：尚未计入的领取选「增加库存（新增收入）」；已经计入盘点的领取选「已包含在库存中，仅补记录」。两种用途都使用真实领取时间，不要把时间改早来通过校验，也不根据两次库存数量推算碎片。

只补记录会逐个核对碎片的完整/条目盘点基线，并向服务端请求只读预览。任一碎片未盘点，或领取晚于其有效盘点，均不能确认；请先回到库存核对并盘点。确认时服务端再次在事务内校验全部条目与库存版本，整笔保存或整笔拒绝。成功显示「已补记报告，库存数量未增加」，获得报告仍计入完整碎片数量和领取日期。紧凑入口也需先预览再确认。

预览后改输入、切换账号或游戏须重新预览。库存变化被明确拒绝时保留草稿，核对后重新预览；网络异常或回执不完整时锁定原文档、记录编号和版本，只能原样重试，不要另建一笔。刷新或强行关闭页面会丢失尚未确认的内存草稿，应先检查操作历史再继续。

补记成功会递增库存并发版本，但不修改数量或盘点基线。之后删除/恢复旧盘点仍按现有规则重放历史，补记流水的库存效果可能重新计算；「只补记录」保证本次提交不重复入库，不是永久排除历史重算。

人工验收：在桌面和手机（建议 390px）选择寿春、填写两种碎片与体力，选择只补记录并预览确认；核对回执、当前数量与获得报告。再检查缺少一种碎片盘点时的具名错误、草稿保留和重新预览。真实布局、触控及浏览器表现待人工检查。

先选择目标子账号，从始终展开的渠道预设中选择来源，填写实际发生时间（日期可直接输入或点击日历图标选择；时刻支持分段输入，也可在任一段粘贴 `HH:mm` / `HH:mm:ss`；页面标明本机时区）。点击小时、分钟或秒的任意一位后直接输入两位数，即替换该段，无需手动全选；离开该段或按 Enter 时，合法的一位数自动补零。修改日期或时刻后需重新预览；无效日期、空段或超出范围的时刻会阻止预览。点击道具图标或密探头像添加奖励，重复点击累加；选中后可点图标左下角减少，也可在入账清单中加减或直接输入数量。心纸支持姓名搜索、品质与属性筛选；筛选只影响候选项，不会移除已选心纸。派遣渠道必须填写实际消耗体力。预览后确认补录。

时钟图标展开精确选时面板，可直接修改时、分、秒，用 ↑ / ↓ 微调当前段，或按 Enter / 点击「完成」收起。触屏点击时钟先展示面板并滚动到可见区域，不自动聚焦数字输入；点击具体数字后再输入。鼠标操作仍自动聚焦小时。空值或超出范围时显示提示并禁用「完成」；Esc 或点击外部只收起面板，已输入内容保留。「使用当前时间」同时更新日期与时刻。桌面端日期、时刻、消耗体力保持同一行；≤480px 的窄屏选时面板在字段下方随内容展开，不覆盖后续输入，更宽视口使用浮层保持字段位置。

已知渠道自动决定奖励类型；切换渠道时保留兼容的已选条目，移除不适用的奖励并清空体力。所有心纸列表排除 SP 密探；范围校验仅约束手动添加，不改写报告中的原始记录。「其他奖励」切换背包道具/密探心纸仅改变候选区，不清空已选内容；清单按类型和 ID 区分条目，支持分别修改数量、移除和整体清空。保存按非空类型生成一条或两条独立流水，两条共用账号、来源和实际发生时间，在同一请求内校验并提交；任一条非法时不提交。网络结果未知时两条流水的 ID 与正文一起锁定并原样重试。操作历史中分别查看、删除或恢复，不联动撤销。若填写包含“派遣”的自定义渠道，也必须填写体力；混合道具与心纸会阻止保存并保留清单，提示按类型分别录入各自实际体力，避免拆分后重复累计派遣时长，不自动分摊体力或填 0。

历练切换到其他渠道时会清空该历练草稿，避免将快捷计算的材料带入另一来源。

白金币奖励可填写1–2147483647的整数；所有渠道的白金币图标连续添加及数量加减均以10为步进（道具图标首次添加为10），密探日常和月卡快捷录入也相同。库存盘点的白金币使用数字键盘文本输入及两侧加减按钮，按钮每次加减10，下限为0、上限为2147483647。手动输入不要求10的倍数，月卡预填65后点击增加得到75，不向整十对齐；其他道具仍每次加减1。报告导入不改写原始数量。

日常快捷入口提供「每日茱萸1」（实际茱萸道具）并保留「密探日常50」，月卡通过紧凑档位选择预填60/65/80/90，并可在本次入账中编辑实际数量。今日奖励可在每日茱萸编辑面板选择记录已领取的白金币，默认50；两种形式共用每日来源键。打开时只读取当前子账号云端月卡档位，不自动勾选来源、选择入账用途或确认提交；读取失败仍可手选，迟到的响应不覆盖手工选择或另一个账号。两个游戏档位均为可编辑参考值，完整映射待确认；请按实际领取核对。

月卡各档位始终使用 `monthly-card` 来源ID，流水ID仍按来源与北京时间05:00游戏日生成，与档位/数量无关。同日改档位后再次提交会触发原有幂等/冲突检查；请到操作历史核对原记录，取消已经保存的来源，仅补录遗漏来源。确需修正时先删除原错误记录，再按实际发生时间补录；已有盘点覆盖的收入选择补标，不能再次加库存。删除和恢复仍使用现有库存重放机制。

邮箱待领取奖励暂不入账；完整的后续方案见[邮箱待领取奖励设计](mail-rewards-design.md)，本轮没有新增邮箱账本。

最小验证：`node --test test/rewardChannels.test.js test/rewardImport.test.js test/acquiredStats.test.js`；组件：`npm run test:behavior -- behavior/rewardEntryWorkspace.spec.js`。人工在390px/1440px打开记录奖励，选择星光、勾选月卡与日常，核对65+50=115；调整月卡为64再改回65，预览并核对分开流水，补标不增加库存，重复同日提示冲突，切账号不带入旧档位。真实布局与提交结果由用户验收。

补录使用 `reward_delta`，不会将输入转换成库存快照。已有较新库存基线覆盖的旧奖励由后端判定为仅历史，仍可用于获得量统计。

### 历练按次数快捷录入

首次进入不显示必填字段错误；点击加入、预览或切换材料模式时才标记未填或非法字段。校验失败后聚焦字段旁的错误提示，仅在提示不可见时就近滚动，不跳到顶部摘要或自动聚焦输入框；顶部错误摘要仍可返回对应字段。修改输入后清除错误提示，再次预览时重新校验。

进入「历练」渠道默认选中「按次数填写」，可手动切换为「按材料填写」。使用一个固定录入区：直接点选风火、地水、阴阳或经验；三类修为选择第 1–12 关，经验选择新手、初级、中级、高级、终极、实战、鏖战、绝境八个具名档位。填写实际成功完成次数（可用加减按钮调整，初值 1，不默认选择类型或关卡）。下方显示本条材料数量，点击「加入本次记录」进入紧凑清单；同类型同关卡再次加入时合并次数并提示。加入仅保存本次草稿，确认补录后才入账。加入后保留类型和关卡、次数恢复为 1，未修改输入前不会重复计入；不自动聚焦次数输入框，避免手机弹出键盘。

清单支持编辑、取消修改和删除。编辑替换原记录的次数；修改为已有类型/关卡时合并到该记录。尚未加入或保存的输入会参与奖励合计和预览，界面明确提示；不完整或非法输入阻止整笔预览与切换材料模式，避免漏记。编辑其他记录前须先加入、保存或清除当前未保存输入，防止覆盖。任何数量变更都会清除旧预览。四种类型可混合录入，材料按 ID 合计，例如风火第 7、8、9 关各 2 次：金丝扇 +170、羽扇 +220、仙门扇 +70。经验清单显示「经验 · 绝境历练」等名称；经验与修为之间切换时清空关卡，必须重新选择，已加入清单不丢失，三类修为之间切换仍保留当前关卡。

修为历练默认下拉显示常用关卡 4、6、8、10、12。在「历练奖励」标题右侧展开「常用关卡」可勾选任意 1–12 关，至少保留一关；在同一折叠区勾选「显示全部 1–12 关」可临时选择全部关卡。三种修为历练共用常用列表，该偏好按子账号和游戏保存在当前浏览器，刷新或重开保留，不跨设备同步；存储不可用会提示仅在本次页面生效。取消某关的常用标记不会更改已填关卡或当前预览，该关会保留为「当前选择」；清空奖励草稿不会清除常用设置。经验固定显示全部八档，隐藏常用关卡设置，不受修为关卡偏好限制，也不改写该偏好或新增经验偏好存储。

录入区使用分段类型选择、紧凑次数控件，材料预览、奖励清单及手工历练确认预览显示项目已有的材料图标，旁边保留名称与数量；图标加载失败时保留文字占位，不影响计算或提交。仅计算必得材料的提示常驻，详细规则收于「掉落说明」。

《代号鸢》《如鸢》均支持三类修为×十二关和八档经验，按子账号的游戏版本启用。用户于2026-10-03确认两版本的修为材料与数量完全一致，并提供完整十二关六阶表，已与现有表逐格对照一致，因此共用已有掉落表，不复制两套数据。经验复用养成模块现有八档数据，两个游戏均可使用，请按实际获得核对；未知游戏仍禁用按次数预设，可按材料填写。

经验各档单次「兵书残卷 / 兵书全卷」依次为 25/0、25/2、30/3、40/4、50/5、65/6、85/8、100/9。新手档只生成残卷条目，也不要求目录存在全卷；其余档位必须同时存在两种兵书。绝境六次合计残卷 +600、全卷 +54，不生成六韬兵书或零数量条目。

按次数模式的清单只读；切到「按材料填写」会复制全部有效计算结果，随后可以修正数量、添加实际额外掉落，手工数量不再受公式驱动。切回按次数时，已有材料草稿须在工作台内明确确认替换。清空、切渠道、下一笔及账号/游戏变化会清理全部计算草稿。

仅计算关卡必得修为材料和兵书；修为第 1、2 关各一种，其余各两种，经验新手档一种、其余各两种。概率粮草、白盐、织物、爵位经验与铜钱均不自动增加。每笔共用一个实际发生时间，可描述 1–44 组不同「类型+关卡」组合，最多合计二十种材料；同类型同关卡自动合并次数，不同发生时间分别录入。次数须为正整数，拒绝空值、零、负数、小数及科学计数文本；可以超过 6 次，每组上限为 `floor(2147483647 / 本关最大单次数量)`，同材料合计也不能超过 `2147483647`。当前输入未填、非法、合并后超限或当前可写目录缺任一必得材料时，阻止整笔预览，不按名称猜测或生成目录项。

预览不写库存，确认后发送一笔原协议 `reward_delta` / `item` / `历练` 流水，不包含体力、层数或次数字段。名称与 ID 来自当前目录；历史仍按渠道和材料数量展示。实际发生时间、快照覆盖、仅历史和服务端警告沿用原语义，接受记录不等于当前库存增加；不要改晚时间强行增加库存。

同日同层允许多个合法批次，各笔使用随机记录 ID。结果不明时锁定同 ID 和正文原样重试；成功后可开始下一笔。**已自动上报或已在历史记录中的同批奖励不要再次补录**：手填与 MaaYuan 使用不同来源的 ID，系统不会根据相似材料/时间自动合并。刷新或离开页面会丢失未确认草稿；修正已成功记录请使用操作历史的删除/撤销，不填负次数抵扣。

### 白金币日常快捷录入

工作台提供「每日茱萸 1」「密探日常 50」「月卡奖励 60」快捷选项，可在同一天同时勾选，合计 110 白金币；选择后仍保留原有双栏，各来源显示在右侧「本次入账」，沿用数量调整、移除、清空和预览操作，预览后一次提交两条独立来源流水。点击已选来源可取消，另一来源的数量保留；其他奖励通过「普通补录」选取。选择后必须明确指定本次用途：

- **新增收入（计入库存）**：记录实际新获得的奖励，沿用服务端按发生时间与库存基线计算的规则。
- **补标已盘点收入（仅补历史）**：用于已经被 MaaYuan 扫描或手动盘点包含的收入。填写实际发生时间；页面在预览和首次提交前读取最新盘点，逐种核对所选道具自身的完整/列出条目库存基线。缺少任一道具基线，或发生时间晚于它的基线时，阻止提交，不会自动改写时间。白金币与茱萸的局部盘点不能互相替代，心纸盘点也不能作为物品覆盖证据。

快捷日常按「当前账号 + 来源 + 游戏日」复用记录 ID；游戏日按北京时间 05:00 划分。重复同 ID 同正文由后端去重；不同数量或时间会返回冲突，页面提示核对操作历史，修正时先删除原记录。普通补录与 MaaYuan 原始流水保留自己的 ID，不会自动合并为快捷记录；已存在的同笔收入不要再次补录。

补标仍是真实的奖励流水，不是独立备注。覆盖快照存在时不重复增加当前库存；以后删除覆盖快照，库存仍会按剩余记录重建。网络失败保留同 ID、实际时间与请求正文，只能原样重试。

获得统计按明确渠道归类洛阳派遣和鸢报，其余来源或缺少明细的汇总量列为「其他／未分类」。洛阳每小时收益只计算该渠道的白金币与茱萸，不混入月卡、密探日常或其他来源。

### 每日茱萸与日常打卡

资源页「日常打卡」直接打开精简工作台，普通「记录奖励」顶部也有「每日茱萸」快捷项。每日茱萸默认记录实际道具 `zhuyu +1`，不增加白金币；50 白金币仅是统计等价值，不能重复入账。茱萸数量按 1 调整，白金币仍按 10 调整，手输数量须为有效正整数。

打卡项目为每日茱萸、既有密探日常与月卡奖励，不默认勾选。月卡沿用当前账号可编辑档位；密探日常沿用既有 +50 预设，本次不将其改名为密探特训，也不增加符传月卡。勾选已经领取的项目，确认实际发生时间，选择「增加库存（新增收入）」或「已包含在库存中，仅补记录」，点击「一键记录」。精简视图不显示道具目录，不增加第二次预览确认；每个来源分别保存流水。

打开打卡或切换游戏日时，按当前账号分页读取该游戏日已有记录，每页 100 条（后端上限），沿游标读取至末页；已记来源显示「已记录」并禁用。状态读取失败时禁止打卡，可重试。快捷录入和打卡共享来源键，密探/月卡保留历史键，每日茱萸使用 `yuanhub:daily-reward:daily-zhuyu:<游戏日>`。同名的普通手工记录和 MaaYuan 流水仍有独立 ID，不能自动识别为同一收入。

并发出现 409 时整批未写入，重新读取状态并移除已记录项，保留其他选择，用户核对后再提交。网络结果不明时锁定原请求，仅允许原样重试。成功结果区区分接受、重复、仅历史及归档；补标不会在已覆盖的盘点上重复加库存。删除某来源后可重新录入；原记录仍存在时，恢复操作按现有冲突规则处理。

切换账号/游戏会清除当前草稿和已录状态，迟到目录、状态及提交结果不回写新上下文。普通补录的未提交草稿在进入打卡后保留，返回普通补录继续编辑。

人工验收：手机 390px、平板 768px、桌面 1440px 打开资源页 → 日常打卡，检查项目、时间和提交按钮可达；选每日茱萸确认只增加 1 茱萸，再打开显示已记录；另选密探日常仍可记录。窄屏 320px 与手机横屏检查无整页横向溢出、键盘不遮挡输入。自动化只覆盖逻辑和组件，不代表真机布局验收。

### 含茱萸与邮箱的库存趋势

「周期获得账簿 → 抽卡资源收支」提供「实际白金币」「含茱萸等价值」「含邮箱」「含茱萸与邮箱」切换，月历、库存摘要、净变化与趋势统一使用选定口径。等价值按最近已知白金币库存 + 最近已知茱萸库存 × 50 计算，不代表已经兑换；趋势数据点可查看两项组成。

两项库存分别由有效快照建立基线，盘点后的奖励用于推算；仅有奖励获得量不能当库存。缺少白金币或茱萸基准的日期不计算等价值，并提示缺测；明确零值或完整快照未列出的条目才视为零。茱萸兑换导致白金币增加、茱萸减少时，等价值不会重复增加。

月历显示记录日相对上次记录的库存变化，比较可能跨越多日。例如 1 日盘点 100、5 日盘点 80，5 日的 -20 是相对 1 日的差额，不证明支出全部发生在 5 日。本期净变化是**本期首末有效库存点之差**，并非完整自然月或所选时段首日到末日的已核实收支；奖励获得量仅统计 `reward_delta`，库存快照不进入获得量。不能用获得量或净变化单独反推支出、转化。

报告继续只用所选时段内的盘点建立基准，不自动借用周期外快照。无基准空态中的「调整日期范围」定位到日期输入；「盘点道具库存」进入完整道具编辑；「导入库存报告」直接打开同一个报告工作台，保留当前统计页签。只打开入口不会写业务数据。本期无基准不等于账号从未盘点；部分资源缺测不遮掉其他已知资源，读取失败提供重试，超过 5,000 条时明确结果可能不完整，不以截断记录判定从未录入。

库存和变化是独立维度：明确零库存显示 0；首次已知库存标记「基准」，变化不可比较；后续同值盘点显示零变化 0；无基准显示 —。当日未更新时不生成零变化，日期详情展示原记录日期及「实际盘点／盘点后推算／基于最近记录折算」来源。基准日期和来源在手机摘要中同样保留。趋势虚线仅表示跨未记录日期连线，不是未来预测。

含邮箱时，白金币列加上邮件的待领白金币，普通符传列加上待领符传封数 × 3；含茱萸与邮箱时白金币再加茱萸 × 50，天机符传不变。各视图使用同一计算结果，详情展示背包、茱萸与邮箱组成。正常领取在基准齐全且无其他操作时只改变存放位置，含邮箱总量不增加；手动调整邮箱只是新的储备观测，不进入奖励获得量，也不能据此推断当天实际收支。

历史按所选时段内的基准建立，旧储备仅能提供最后一次保存时间的观测；不把当前邮箱填入更早日期。未录入、明确零、无基准、无新记录分别显示。邮箱历史或库存分页不完整、读取失败、读取期间版本变化且重试仍不稳定时，不展示含邮箱完整合计，原有实际白金币／含茱萸口径仍可用。

删除领取奖励会修正背包历史，邮箱观测保留并标记「关联领取记录已删除」；恢复奖励不再扣一次邮件。此类人工纠错可以改变总量，不作为实际消耗显示。保存储备、领取及删除／恢复都会使报告重新读取。

## 手动库存盘点与零库存基准

库存目录提供「盘点全部道具」，心纸沿用「编辑心纸库存」。在没有有效完整基准且进入完整编辑模式时，可以明确勾选「我已核对全部库存，未填写项按 0 计」后点击「确认盘点」，即使全部为零也会保存一笔合法的 `full stock_snapshot`。全零快照的 `entries` 为空，记录及完整基准仍然有效；前端隐藏道具已有数量继续保留。

已有完整基准且数量未变时，普通保存继续禁用，不新增重复盘点记录。局部分组编辑不提供完整库存的零值确认；修改数量的保存行为沿用既有协议。未登录、账号未选、库存读取未成功或读取失败时不能将默认零提交为盘点。保存中冻结草稿并阻止重复点击；失败保留草稿与确认，取消需确认丢弃，取消本身不写入库存。网络错误或结果不明时，锁定同一记录 ID、发生时间与请求正文，只能原样重试；明确校验或权限拒绝后允许修改。取消结果未确认的编辑会重新读取库存，不会撤销服务器可能已接受的盘点。刷新或离开页面会丢失这笔未确认请求，应先核对操作历史与库存，避免重复盘点。切换账号、游戏或登录身份会清除旧草稿，旧读取/保存响应不能覆盖新的上下文；离开页面后不因迟到响应再次刷新。

`full_baseline_at` 是完整盘点证据，`listed_baseline_at` 是单项盘点证据；`updated_at`、登录、连接码授权以及正库存数量都不能代替盘点基准。首页的 `inventoryRecorded` 表示存在录入数据，`inventoryHasFullBaseline` 表示完整盘点，两者沿用 [今日一览的数据录入状态](./ux/today-data-readiness.md)。只有奖励的账号可以已有录入，但资源报告仍需盘点基准；已完整盘点全零的账号无需重新录入。

Hero 的「已登录／云端存储」描述认证与存储方式，不宣称每次读取或编辑已同步成功。目录更新日期是追踪目录版本，不是账号库存更新时间；局部统计组按实际容器宽度重排，不修改其他页面的 Hero。

## 导入 MaaY 报告

支持 UTF-8 `DailyRewards*.txt` / `StockReport*.txt`（包括 BOM、Windows 换行）及库存交换 v2 JSON，接受奖励流水与库存快照。自动上报模式的背包快照也可能写入 `DailyRewards-<账号名称>-<account_id>.txt`，记录类型以正文为准。点击投递区选择文件或拖入单份报告后自动解析，也可以展开文本输入区粘贴报告。预览默认收起原始状态详情与记录 ID，可逐条展开查看。单份报告上限 5 MB，单次提交 1..1000 条记录。

- TXT 按 `MaaYuan 库存记录` 块解析，读取 `#@MaaYInventoryRefV2` 中的原始 ID、账号与体力信息。
- 道具使用当前后端库存目录，密探使用当前公共图鉴，将名称还原为 ID；库存目录中已从公共图鉴删除的历史密探不参与匹配。不同实体类型按报告原顺序与原记录 ID 对应。
- 保留原发生时间、原记录 ID、渠道、消耗体力和奖励数量。缺少账号时绑定当前选中子账号；已有账号不符时阻止该记录导入。
- 默认选择上报失败的记录。已成功或状态未知的记录可核对后逐条选择。
- 库存快照保留 `stock_snapshot`、机器标记 `s` 指定的 `listed` / `full` 范围、原数量及零值，不转换成奖励。`listed` 只更新列出的条目；`full` 是该实体类型的完整库存基线，未列出的条目归零。服务端按原时间处理，较旧快照不会覆盖较新库存基线；快照不进入奖励获得量。
- 报告模式使用完整公共密探目录，允许已知但不适用于当前账号游戏的密探在快照中补零；原条目不删除，服务端忽略其库存应用并返回警告。跨游戏非零数量、奖励或未知 ID 仍拦截。手动奖励模式继续按账号游戏筛选目录。
- 未知或有歧义的名称、缺失 ID、截断内容、无效数量、账号/体力标记不一致等保留为错误行。混合记录块有错误时整块阻止导入。

仅预览不会发送写请求。点击确认后复用 `POST /v1/inventory/import`，展示接受、重复、仅历史、已归档数量及后端警告，并刷新当前库存和操作历史、清除获得量缓存。快照预览明确展示记录类型、范围与绝对库存数量；确认前提示零值更新或完整快照归零的含义。

手动流水的 `effective_at` 会原样发送给服务端。服务端按账号和业务时间重放：如果它早于已有的完整库存快照，或早于对应条目的局部库存基线，快照覆盖范围内的数量不会改变当前库存，但流水仍会保留在历史并可用于时段获得量；未被 `listed` 快照覆盖的条目仍可能影响 current。提交结果中的 `history_only` 反映服务端实际判定，手工工作台始终提示较新完整或局部盘点可能使奖励仅记录历史，以服务端实际结果为准；不依赖操作历史的分页列表判断是否存在较新快照，也不为此加载全部历史。

## 重试

服务端以同一账号、同一记录 ID 和正文进行幂等去重。重复导入同一份 TXT 或同一条流水会计入 `duplicates`，不会再次补录；页面在全部重复时显示“记录已存在，未重复补录”。同 ID 不同正文会返回冲突。TXT 内部同一 `record_id` 的重复行也会在预览阶段禁用，避免重复勾选。

网络或服务端错误后，本次请求内容会在当前页面中保留并锁定，只能原样重试；明确的格式、权限或冲突拒绝允许修正。不要为同一条历史报告重新生成记录 ID。手动补录尚未确认成功时应留在页面原样重试，刷新或离开页面会丢失该手动草稿。

HTTP 422（例如 `agent_game_mismatch`）属于服务端校验拒绝，等待后重传不会自行解决。先核对账号游戏、目录与实际连接的后端版本。快照中的已知跨游戏零值需要后端部署现有兼容逻辑；若旧服务仍拒绝，应更新服务后原样补传，不要把快照改成奖励或删除原条目规避校验。

功能直接复用现有正式库存接口，无新增后端接口或延后开放的功能开关。

## 公共密探目录变更

每次打开补录入口都会重新读取 `GET /v1/inventory/catalog` 和 `GET /v1/operator/catalog`，并清除旧预览。两份目录都读取成功后才允许补录；公共图鉴不可用时不会退回历史密探目录。公共图鉴成功返回空数组时，也不会补入已删除的密探。

当前图鉴仍有多个同名 ID 时，TXT 继续按歧义拦截，不会随意选择第一项。JSON 携带已删除的 ID 时也会拦截，不会根据名称静默改写原始记录。

网页补录的目录校验不会迁移云端旧养成或心纸库存。后端同时将库存目录中的密探改为直接读取公共图鉴；旧养成可以在「当前养成」确认后清理。发布顺序与范围见 [密探目录 ID 变更修复](./backend-operator-catalog-id-repair.md)。
