# 招募档案

`/recruitment` 记录属于当前游戏账号，需登录、全站内测资格及 `src/config/features.js` 中的 `recruitmentArchive=true`。访问统一使用全站内测资格，不再要求独立授权。旧 `/admin/recruitment-access` 入口重定向管理工作台，旧名单/模式数据保留但不再控制使用权限；卡池维护权限不变。首页展示账号栏、备份入口、摘要与卡池时间线，移除了卡池下方“最近记录”和“历史总抽数”维护区。

## 卡池与编辑

无限期常驻池（包括两游戏的绣衣天下）固定置顶，始终显示，不受年份筛选或正反排序影响，也不算作“日期未知”。其他卡池按开始日期从新到旧纵向排列，可筛选年份、切换排序；未知开始日期置后。卡片显示真实日期、目录状态、本池已知累计、密探记录条数与距离下次保底的抽数，缺失值保持未知。日期状态按北京时间计算。封面复用已绑定UP立绘/头像，缺失或加载失败使用纸色封面；手机单列排版。

点击整卡或「记一笔」打开实际卡池弹窗；停用或目录未确认池显示「查看记录」。窗口同时显示所点击池的池名、日期、记录与进度，提醒核对实际抽取的池；已结束池也可查看和维护。时间线不展示账号旧卡池偏好，不据此高亮或排序，点击与保存无需设置全局卡池。先问「这次抽到了哪位密探？」；选择后才展开必要字段：

- 「记录密探」：UP头像或搜索本游戏4星/5星密探（包括照影SP与非UP）→出货间隔可留空→核对真实距保底→「保存这笔」直接提交。取消单条输入不写入。
- 「还没出绝密」：只填写游戏里当前距离保底的数字→「保存保底进度」。不是本次又抽几次，也不创建绝密记录。
- 历史维护：下方按密探名字查找、加载更早记录；点已有记录编辑→完成→底部统一保存。取消编辑保留原记录；批次总量与基准不因单条编辑改变。

日常保存复用同一个 `submit`、单条校验及原子命令；普通与教程显示相同按钮。成功后不关闭本池：命令成功且同ID、目标字段、当前进度、删除结果按回执读回核验后，显示保存的密探与已知/未知间隔、服务器返回的本池已知抽数/绝密条数/距保底，突出本笔记录（两种视图一致）或保底。窗口内可以继续记下一次真实出货。

请求成功但读取失败/字段不符时显示「结果尚未确认」，提供重新核对，阻止重复提交或新建；草稿保留。若其它设备在此后改了资料，可关闭并重新打开本池查看最新档案。未修改时不发送空保存。字段错误、未知保底不会请求写入；网络失败同内容重试沿用稳定请求ID与事件ID。备份与恢复仍独立于日常记录，本次不改导入。

按**每次出货**记录：同一密探可重复，每条填写“多少抽出货”，指从上次绝密到此次出货的间隔，不是池内累计次数；未知可留空。再次打开回显已有密探及抽数，可修改、添加或移除。结果继续使用既有出货记录。

## 页面内使用教程

页头只有一个「使用教程」入口，不主动弹教学。点击后只选择「跟着记录一次」「先练习一下」，或关闭。`/recruitment` 路由统一校验登录与全站内测资格；通过后挂载真实工作区，不查询独立招募授权。教程仍默认软隐藏，显式启用时保留隔离练习。管理路由的权限不变。

真实带练按玩家实际操作推进：亲自核对账号和时间线的池名、UP、日期并选池 → 点「记录密探／还没出绝密」 → 出货时点 UP 或搜索密探、填写可靠间隔（记不清保留未知） → 核对游戏当前距保底 → 正常保存，等待 API 与读回核对。提示紧邻对应控件，使用作用域内 `data-guide-target` 锚点；目标确实不可见才柔和定位，减少动态效果设置时不使用动画。不使用下一步代替点击、选择、输入或保存。

没有出绝密只更新保底，不新增事件。出货保存必须读回同一池、同一 event_id 与提交字段；保底保存必须读回一致进度及版本。读取失败、冲突、未读回、错误均不显示正式确认。正常操作与教程共用 `pool_records_save` 提交和 `saveReceipt` 核验，没有教程专用保存模式；成功后定位刚才的记录／保底，展示本池数字变化及下次继续的位置。已确认回执只校准一次基准，不覆盖后来草稿；必要时继续读分页。

回访玩家可在原记录上切换真实进度条／密探视图查看，或选择练习，不必再造一条。历史修改沿用点真实记录 → 完成单条草稿 → 底部保存。`EntryEditor` 的旧批次、历史基准、120 抽窗口入口仍不可达，教学不声称已提供这些功能。教程不自动改数字、删除或导入数据。

出货间隔未知仍提交 `pull_span=null`，未知不等于实际 0 抽。**保底未知限制：**现有原子契约要求距保底为整数 1–40，不能留空提交；保存校验会阻止未知进度提交，玩家核对游戏后才能保存。退出教程保留当前窗口草稿，不猜 0 或 40，不扩后端契约、不拼接非原子写入。已垫 = 40 − 距保底，不能混用出货间隔与当前进度。

「退出教程」或第一次 Esc 只移除提示，不关闭真实编辑器、不清草稿、不取消真实请求。再次 Esc 沿用普通窗口关闭。重新进入根据当前真实业务与草稿状态引导，不要求重复登记。教程状态不持久化，不再读取或写入旧四主题完成偏好。关闭实际编辑器、离开页面或按已有确认流程切换账号，仍沿用正常草稿生命周期。

`RecruitmentPractice` 仅在本次挂载的局部内存持有示例池、密探、记录和进度，复用 `RecruitmentTimeline` 与没有 API 依赖的 `PoolEditor`。真实账号 store、统计、localStorage 和后端均不连接；示例提交只更新父组件的临时状态，绝不构造正式 `saveReceipt`。全程显示「练习 · 不会保存到你的账号」，结果为「已经熟悉怎么记录；需要时到自己的卡池里记一笔」，关闭即丢弃示例。练习允许亲自选择两种结果、搜索、填写、查看示例变化。

## 记录与保底语义

当前进度可选择「已抽／已垫」填写方式：首次默认「已抽」填写距离下次保底的抽数 `N`（整数1–40）；「已垫」填写已经抽了的次数 `P`（整数0–39），保存时换算为距保底 `40 − P`。例如填「已抽33」或「已垫7」保存的是同一进度；切换时输入框、摘要数字与进度条自动换算，切换本身不产生待保存修改。未知进度仍留空。进度卡片下方不再展示换算示例与未知进度的长说明，保存时仍校验真实进度。

填写方式作为当前浏览器的偏好，通过 `yh_recruitment_progress_input_mode` 保存到 localStorage，仅保存「已抽／已垫」，不保存抽数或草稿；跨卡池、切换游戏账号、刷新及重新进入页面后沿用最近选择。每个卡池仍独立读取自身真实进度，未知不会继承上个池的数字。练习保持独立内存选择，不读取或覆盖正式偏好。存储失效或值不合法时默认「已抽」，存储不可用时当前组件内仍可切换；清除浏览器本地数据后恢复默认。

关闭按钮、点击遮罩和普通 Esc 共用未保存修改确认：保底抽数变化、出货记录的新增/修改/删除，以及尚未加入记录的真实输入都会提示「还有修改未保存，关闭后将丢弃。」默认聚焦「继续编辑」；取消保留输入，选择「放弃并关闭」才关闭。仅切换填写方式、查看原记录或打开空搜索不提示；保存并读回核对后没有新修改时直接关闭。教程中第一次 Esc 仍只退出教程；练习结果页可直接关闭。确认期间不重复弹窗，旧弹窗的确认结果不能关闭后来打开的卡池。

同时填写距下次保底抽数 `N`（整数1–40），服务端按 `40 − N` 替换当前进度；40是明确标注的换算口径。未知或超出换算范围的旧进度不自动猜值；新增或修改5星的保存契约不允许距保底留空（仅4星计次或纯排序可保留未知），需先核对真实进度，无法确认时可以退出教程保留当前窗口草稿。出货修改、新增、移除与保底一起提交，失败全部回滚并保留草稿；打开/取消不写入，保存仅作用于正在编辑的池。

首页不请求历史分页，仅在打开弹窗后读取本池记录，源数据按出货顺序加载、界面从新到旧展示，可加载更多；读取失败不能把未加载的记录当成空池保存。提交仅包含改过或新建的稳定event_id及明确移除的ID，没加载/没修改的历史不被覆盖。每次最多修改/新增120条、移除120条；新行和请求ID在网络重试时保持不变，重复保存已登记结果不会新建重复事件。跨设备409时重读本池版本，保留用户草稿，核对后重新提交。

占位UP绑定正式密探后保留固定槽身份并显示新名字/头像；退役的旧结果可修改抽数或移除。停用、目录或图鉴不可用时可维护已有记录和保底，不能新增结果；游戏快照错配只可查看和导出。

摘要和卡片“已知累计”采用旧基准、独立事件已知间隔、批次总量及当前进度之和。修改独立事件替换其贡献，移除独立事件减去该条抽数；相邻跨度不变。批次内节点的编辑/移除不改变批次总量，已知跨度之和不能超出该批次总量。基准与批次继续保存，首页不提供其旧维护入口。

账号切换、身份失效或账号游戏变更清除弹窗及未提交草稿；A账号迟到响应不能关闭B账号新弹窗。关闭弹窗恢复发起卡片焦点。首版仍不提供彻底清空与MaaYuan自动采集。

色条长度按40抽刻度显示，≤20绿色、21–30金色、≥31红色；超出刻度仍显示原始数值，未知抽数用中性色。颜色只帮助比较间隔，不推算概率或欧非评级。仅已确认non_up显示“歪”，未知UP状态不猜标记。

## 历史位置与顺序调整

1. 日常点击密探、填写间隔并「加入」，新记录先出现在最新处。
2. 进度条视图可从头像、色条、数字或行内空白处拖动整条记录；密探视图仍拖动头像，将整条出货放到历史位置；同一密探多次出货按 `event_id` 分别移动。触屏长按进度记录或密探头像 300ms 后拖动，普通上下滑动仍滚动列表。悬浮记录与虚线空位提示放置位置，靠近列表边缘自动滚动；Escape 或触控取消恢复原位置。
3. 松手仅更新本窗口草稿，两种视图同步显示，底部提示待保存并通过「保存修改」统一提交。「恢复保存前顺序」只撤销排序，保留新增、字段编辑和删除草稿；关闭未保存窗口或切账号仍需确认。

头像可用 Tab 聚焦，上下键逐条移动并播报当前位置，移动后焦点仍在该头像。普通点击头像、进度条或密探名字继续编辑。编辑面板内收起的「调整顺序／补录到历史位置」保留为无需拖动的单指替代：原生选择框按**最早→最新**列出全部参照记录（含被搜索隐藏的结果），用序号、名字、间隔、日期和ID尾段区分重复出货；日期不参与排序。拖动和键盘移动的显示顺序是**最新→最早**，提交自动转换成**最早→最新**。

尚有分页时，列表提供「读取全部后排序」，复用按当前版本每页100条的全量读取；加载失败保留草稿并可「重试读取全部记录」。未读完、读取失败、超过20000条、搜索过滤、只读、编辑单条中、请求处理中或回执未核验时不允许拖动/键盘重排。搜索时明确提示清除搜索后拖动，不能把过滤结果提交为完整历史。拖动期间版本变化则取消本次移动；已有顺序草稿遇到版本冲突继续保留，需通过位置菜单核对，或恢复保存前顺序后重新拖动。超过上限不能截断提交。减少动态效果时关闭让位动画。

前端使用 MIT SortableJS 的触控 fallback，未新增后端接口、数据库迁移或备份格式。

新增、编辑、删除、顺序及保底通过一次`pool_records_save`事务保存，顺序为可选`ordered_event_ids`完整集。纯移动不发送未改变的字段、不修改pull_span或相邻跨度，不改变累计、保底、UP、4星次数、SP属性、批次归属/总量及已删除结果；未知间隔保持null。未知保底仍可纯排序，新增/修改5星的保底要求不变。

保存后逐页读回，完整ID顺序与回执相符才显示「历史顺序已保存」。保底留空表示保留提交时的原进度，回读须与该进度相符（包括未知及超出换算范围的旧进度），不会把留空当作清除进度。回读失败或顺序不符保留草稿与回执，只能重新核对，不能重复新增；网络失败同内容沿原请求ID重试。409保留草稿，需重新读取全部记录、重新选择位置并核对后保存，已删除参照不会被自动当作最新；读完后可点「核对失效草稿」，明确确认只移除这些旧记录的本地修改，其余草稿保留，再重新选择位置。重新打开、刷新或其它设备读取均使用服务端顺序。练习仍只在内存中操作，不能写真实账号。

JSON v1备份保留全局`sort_order`，空账号恢复保持顺序；CSV沿导出事件顺序输出，仍只供阅读。无需迁移或更新导入格式。

## 备份与恢复

账号栏“备份与恢复”就近展开面板；收起保留同账号输入，切账号关闭并清空。无公共目录时仍可通过“导入备份”聚焦文件选择。

历史 `current_pool_id` 字段与旧客户端 `set_current_pool` 命令继续兼容，JSON 导出、预览和恢复保留该字段；时间线忽略它。`event_create` / `batch_create` 的 `mode=current` 仍表示按当前抽卡进度录入。旧 `EntryEditor` 无正式页面或路由入口，其默认池依赖保留。

JSON `yuanhub.recruitment.v1` 继续导出同一版本的完整事件、批次、基准和进度，包括已删除记录，最多5MiB / 20000条结果，超限整包拒绝。本次不新增名单字段或改变备份格式，新弹窗中的出货仍由既有events备份。导入先预览、确认候选总数；默认保留当前状态，不复活旧删除、不写公共目录、不新增用户临时池或密探。网络结果未确认时可重试原导入请求。

CSV包含baseline、pool_state、batch、event行，批次内事件与已删除事件不重复计数，未知值留空。UP名字采用当前槽解释，无法匹配回退原快照。CSV仅用于阅读，不能恢复。

管理页 `/recruitment/admin` 需要 `recruitment_catalog:write`；用户不能自定义卡池或临时密探。

新增 UP 名额后，通过“对应图鉴密探”选择同游戏的4星或5星密探（含照影SP）；图鉴加载成功时可选择，保存中或图鉴加载失败时禁用。加载失败仍保留已有绑定及占位名称，点击“刷新目录”成功后恢复选择；“已对应图鉴”仅表示该名额已有绑定。

## 时间线封面色系

封面只按当前目录优先、映射快照其次、原快照兜底的 `pool_type` 选择柔和纸色渐变，两游戏共用同一规则。优先级如下，排序、年份、账号、日期状态和屏幕宽度不参与配色：

| 类型规则（从上到下匹配） | 色系 |

## 管理员隐藏与历史入口（2026-10-08）

在「管理卡池 → 卡池状态」选择正常显示、停用但显示或隐藏。隐藏保存前会确认：公共列表移除，无历史账号不可首次录入，已有历史不删除。取消确认无写入。恢复时明确选择正常或停用；隐藏不会暗中重置 enabled。管理员列表可按全部/正常/已停用/已隐藏筛选，并按名称或 ID 搜索。

隐藏池只在有已保存个人池的账号保留入口，卡片标记「已隐藏 · 历史保留」，只能维护旧事件和真实保底，禁止新增出货；统计、CSV 与 JSON 导出保留。archive 的 pool_states 用于状态提示，公共目录缺少隐藏项不被误判为接口失败；每次刷新重新读取个人档案和目录，切换账号清除旧上下文。既有「记录密探 / 还没出绝密」流程保持。

编辑器保留名称/类型/日期和 UP 管理。游戏/ID 不能改，录错请先隐藏错误卡池，再新建正确卡池。正式 UP 已有固定历史身份，错绑须退役旧槽并添加新槽；旧绑定在图鉴不可用时仍能随其他字段一起保存。占位首次绑定图鉴继续保留原槽 ID。422 显示具体错误并保留草稿；409 可读取最新版本供核对，不会自动更新草稿 revision 或覆盖他人修改。

JSON v1 schema 不变。隐藏期间只能在目标账号已有个人池/事件/批次身份范围内判重与恢复存量；无法凭离线文件证明真实性，因此空账号首次恢复隐藏池、增加服务端未存的新出货会被拒绝。需要首次恢复时由管理员明确恢复显示后走原协议。隐藏不删除任何历史。

公共活动日历的招募派生项也排除隐藏池，避免错误卡池从另一个公共入口出现；招募管理员目录仍完整保留。

## 4星计次与照影SP
