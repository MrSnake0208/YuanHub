# 招募档案（内测）

本地查收入口是 `/recruitment`。`src/config/features.js` 中 `[FEATURE_KEYS.RECRUITMENT_ARCHIVE]: true` 已显式开启，可用有内测资格的账号直接打开页面。该构建开关在开发与生产构建中均跟随显式值；本次没有 push 或部署，尚未发布到线上。上线前先完成下列用户回归，再由用户决定是否开放；需暂时关闭时将该值改为 `false`。开发服务统一用工作区 `./dev.sh`，复用已有服务。

进入页面即可看到当前账号所属游戏的全部公共卡池，包括已停用池；无需手动添加。已有个人卡池与历史保留，未保存的卡池进度显示“未知”。浏览和筛选不会创建个人档案，选定当前池、校正进度或补录时才保存对应卡池状态；停用池禁止新增出货记录，仍可查看与维护历史、进度。公共目录尚未配置时可“补历史总抽数”或“导入备份”，按钮会展开对应表单并聚焦输入。历史基准单独放在“历史总抽数”折叠区。

主入口改为“卡池时间线”：全部卡池按开始日期从新到旧纵向展示，可筛选年份或切换从早到晚；缺少开始日期的卡池始终放在已知日期之后，并可单独筛选“日期未知”。卡片展示真实名称、起止日期、目录状态、服务端本池已知累计与绝密条数、最后一次绝密后的当前抽数；缺失统计与进度显示“未知”，不会推算收集率。日期状态按北京时间判断，结束日期当日仍包含在进行中；没有完整起止日期时只显示目录启用状态，目录未确认和旧个人池分别明确标识。封面复用本仓库已绑定 UP 密探的立绘与头像，缺少立绘或加载失败时使用纸色封面。

点击卡片后在同一位置进入该池维护区、清除旧日期筛选并读取本池历史，可记录绝密、补录历史或校正进度；新增记录表单限定所选池。浏览与编辑不会自动改当前池偏好，需明确点“设为当前卡池”。“返回时间线”恢复卡片焦点和全池最近记录，保留同账号的年份与卡片排序。停用池仍可校正进度、修改已有记录，但不能新增或补录。手机端卡片单列重排，桌面端显示侧边日期轨与横向封面。每条绝密记录填写本次出货抽数。接着当前记录会扣除已计入的旧进度，再保存最后绝密后的尾抽。例如旧进度 21、27 抽出货、尾抽 4，本次新增 10 抽。进度未知时先校正或改为历史补录；确认没有尾抽时可以明确填写 0。未保存的目录卡池不计入账号累计、未知进度数量或备份内容。

N 是手填“距离下一次 40 抽还需多少次”，按 `40 − N` 替换当前进度。40 抽只是明确标出的换算口径，不代表目录中每个卡池已经核实同样的规则。

历史补录不改变当前进度；抽数不知道可留空。只有一批总量时按批次保存，累计只计总量一次。120 抽顺序助手按从旧到新填写绝密位置，窗口外的前一次绝密不明确时首条跨度保持未知；按整个窗口计数须确认尚未计入档案，且窗口不包含已计入的当前进度。已有抽数属于历史基准时选择“从基准拆出”。

删除独立记录 A17、B31、C17 中的 B，只剩 A17、C17，总量 65→34；当前进度和相邻记录不变。下一次修改前可撤销。已知总量批次里的单个结果没有可独立推导的抽数，删除该结果不减批次总量，删除整批才减总量。

时间线下方的“最近记录”与选池后的本池记录共用筛选与分页，可选择全历史从新到旧或从早到晚；账号基准只有一份，无法分配给某个卡池。获得日期只记录日期，不等同于系统录入时间：当前记录默认客户端本日，可清空；历史补录默认日期未知。用户不能自定义卡池或临时密探。管理员在 `/recruitment/admin` 配置每池 N 个 UP 名额，可全部使用占位；非 UP 继续从本游戏绝密图鉴选择。占位对应真实密探后使用同一固定名额身份，历史自动显示当前图鉴名字与头像，抽数、进度、日期、顺序与个人版本不变。减少 N 会退役名额，增加 N 创建新身份；管理员修改真实映射会同步改变该名额历史的展示。旧临时档案仍可查看、导出、修改已存在记录与删除，但不能新增结果。管理员配置的本池 UP 名额明确标为 UP；图鉴其他绝密仅在完整、非空且已核对的固定 UP 名单下自动推导非 UP，名单不完整时保留未知，可手填。

账号切换会清除所选卡池、年份/排序、未提交草稿、导入预览和撤销入口。另一设备写入冲突时读取最新数据并保留同账号草稿，核对后重新提交。游戏快照不一致时只能查看和导出。首版不提供彻底清空与 MaaYuan 自动采集。

“备份与恢复”入口位于顶部“当前数据账号”栏，点击后在账号栏下方展开，再次点击收起；收起保留同账号的文件与选项，切换账号会关闭面板并清除导入草稿。空档案中的“导入备份”仍会展开此面板并聚焦文件选择。

“备份与恢复”从云端同一版本完整快照导出 JSON 和 CSV，包含删除记录。JSON 格式是 `yuanhub.recruitment.v1`，使用紧凑 UTF-8，最多 5 MiB / 20,000 条结果；超限不会输出截断备份。CSV 分 baseline、pool_state、batch、event 行，已知计数贡献单列：批次内结果和删除记录贡献为 0，未知值留空，避免分析时重复计算；占位绑定正式密探后，CSV 按同一卡池固定身份显示最新名称，无法匹配则保留原快照名称。CSV 不能用于恢复。

备份不能创建或修改公共目录，也不能新增用户自定义卡池/临时密探；既有旧档案不会因此被清空。导入先选 JSON、再选择保留当前状态或使用备份状态，默认跳过可能重复计数的新增。核对预览的候选总数、风险与逐项结果后再提交；更换文件、选项、账号或档案版本会要求重新预览，旧备份不会默认复活已删除记录。若提交响应因网络中断未确认，即使云端更新已通过 SSE 到达，也可“重试上次导入”查询同一次提交的结果；保留原始请求身份，不再重复计数。更换文件、选项或账号则放弃该重试意图。
