# 招募档案

`/recruitment` 记录属于当前游戏账号，需登录、独立招募档案访问资格及 `src/config/features.js` 中的 `recruitmentArchive=true`。访问资格由 `/admin/recruitment-access` 管理（需 `recruitment_access:manage`）：有限模式仅允许授权用户，公开模式允许已激活用户，不依赖全站内测资格。首页展示账号栏、备份入口、摘要与卡池时间线，移除了卡池下方“最近记录”和“历史总抽数”维护区。

## 卡池与编辑

管理员目录中的全部卡池按开始日期从新到旧纵向排列，可筛选年份、切换排序；未知开始日期始终置后。卡片显示真实日期、目录状态、本池已知累计、绝密记录条数与距离下次保底的抽数，缺失值保持未知。日期状态按北京时间计算。封面复用已绑定UP立绘/头像，缺失或加载失败使用纸色封面；手机单列排版。

点击整卡或「记一笔」打开实际卡池弹窗；停用或目录未确认池显示「查看记录」。窗口同时显示池名、日期，提醒核对实际抽取的池，不自动选当前卡池。先问「这次有没有出绝密？」；选择后才展开必要字段：

- 「抽到了绝密」：UP头像或搜索真实绝密（包括非UP）→出货间隔可留空→核对真实距保底→「保存这笔」直接提交。取消单条输入不写入。
- 「还没出绝密」：只填写游戏里当前距离保底的数字→「保存保底进度」。不是本次又抽几次，也不创建绝密记录。
- 历史维护：下方按密探名字查找、加载更早记录；点已有记录编辑→完成→底部统一保存。取消编辑保留原记录；批次总量与基准不因单条编辑改变。

日常保存复用同一个 `submit`、单条校验及原子命令；普通与教程显示相同按钮。成功后不关闭本池：命令成功且同ID、目标字段、当前进度、删除结果按回执读回核验后，显示保存的密探与已知/未知间隔、服务器返回的本池已知抽数/绝密条数/距保底，突出本笔记录（两种视图一致）或保底。窗口内可以继续记下一次真实出货。

请求成功但读取失败/字段不符时显示「结果尚未确认」，提供重新核对，阻止重复提交或新建；草稿保留。若其它设备在此后改了资料，可关闭并重新打开本池查看最新档案。未修改时不发送空保存。字段错误、未知保底不会请求写入；网络失败同内容重试沿用稳定请求ID与事件ID。备份与恢复仍独立于日常记录，本次不改导入。

按**每次出货**记录：同一密探可重复，每条填写“多少抽出货”，指从上次绝密到此次出货的间隔，不是池内累计次数；未知可留空。再次打开回显已有密探及抽数，可修改、添加或移除。结果继续使用既有出货记录。

## 页面内使用教程

页头「使用教程」打开轻量主题选择，不自动选择当前卡池。先核对游戏账号，再按时间线的年份、卡池名称和起止日期亲自选池；「当前卡池」是已有偏好，不保证是这次实际抽取的池。卡池内「本池帮助」可选择同样主题；打开教程后只显示关闭和换主题。新用户在可新增、记录读取成功的空池收到自愿邀请，可直接关闭或「以后不自动提示」。回访用户仍可主动学习全部主题。

| 主题 | 实际操作 | 完成证据 |
| --- | --- | --- |
| 第一次使用招募档案 | 核对账号、选实际池，切换进度条和密探视图 | 读取成功、亲自切换两种视图；仅「查看引导完成」，不创建记录 |
| 抽了几次，但没有出绝密 | 按游戏真实状态修改距保底→保存保底进度 | 本次命令成功、对应池进度回读一致 |
| 抽出了绝密密探 | UP快捷按钮或其他密探搜索→间隔已知或留空→核对保底→保存这笔 | 本次新增event_id和提交字段读回一致，两视图可查看 |
| 补录或修改以前的记录 | 时间线找到历史池，点真实已有记录→修改→完成→底部保存 | 原event_id的实际修改字段读回一致；仅浏览不会标为写入完成 |

教程和普通操作共用同一个真实表单与保存步骤：新增用「保存这笔」；仅进度用「保存保底进度」；历史多条编辑保留「完成 → 底部保存」。教程没有自己的提交代码；退出教程不影响真实输入或请求。保存结果核验用于所有用户，教程完成偏好另外要求本次教程会话的目标一致。回读不到目标或读取失败时重新核对，无需再次新增；必要时继续读取分页。每次回执只校准一次已提交基准，保留后续编辑、删除与保底草稿。409先重读版本，保留草稿，核对后重试。

「出货抽数」是与上次绝密之间的间隔，不是开池以来累计。例如上次绝密后第20抽又出绝密，填20。首条也只填确知的间隔，没有特殊自动推算；未知沿用 `pull_span=null`。同一密探再次真实出货可以另记一条。

「距保底」是当前池的进度，按当前40抽口径换算：已垫 = 40 − 距保底。例如真实已垫7抽，填33。抽了没出绝密只修改保底，不新增结果；出货后仍需按游戏当下状态核对保底，本页不自动重置、也不跨池继承。

**保底未知限制：**现有原子 `pool_records_save` 契约要求 `remaining_pulls` 为整数1–40，明确拒绝null。间隔未知和保底未知是两回事；前者可以保存，后者目前无法在本页原子提交。字段旁提前说明，不默认40、不把未知当0。用户可整理当前窗口草稿、关闭教程，确认真实游戏进度后再保存；关闭整个窗口或切换账号会丢弃未提交草稿。本次不扩后端契约，也不拼接非原子写入。

「抽数怎么填写？」可折叠查看累计、当前进度、视图、取消和删除说明。已知累计只汇总可确认的基准、独立间隔、批次总量和当前进度；未知不是实际0抽，批次节点不再重复累计。基准可能已包含历史，新增前需核对，避免重复计数。`EntryEditor` 的历史总量批次、120抽窗口与基准修正入口目前不可达，教程不提供这些操作；历史维护主题可查看、修改已有记录，无记录时引导回时间线找到实际历史池，不要求伪造新出货。

进度条与密探头像是同一组记录的两种展示。头像左下角为本次间隔；时间线UP头像×N才是本池获得次数，—为未知。删除由用户在普通编辑里执行，保存后才生效；教程不自动删除、导入或改基准。

随时「关闭教程」或Esc仅移除教学提示，保留真实字段、当前草稿、编辑窗口和已发出的保存请求。再次Esc沿用普通窗口关闭。偏好仍按用户+游戏账号隔离：开始、暂关、禁用邀请、记录教程完成各自独立。`viewedTopics` 只记录查看引导；`completedTopics` 只在对应本次会话的命令和回读证据成立后写入。旧偏好不替代当次核验；保存中退出，即使随后成功也不标教学完成。

未登录、无账号、档案读取失败、空目录均提供实际前置条件。游戏错配只读，可探索视图，不能写入；停用/历史快照/目录失败不能新增，可按现有权限维护已有数据与保底。读取错误不当空数据。

08风险L2：局部录入分支与既有保存回读，不改业务算法/API。最小回归：`npx vitest run behavior/recruitmentPage.spec.js behavior/recruitmentPoolEditor.spec.js behavior/recruitmentTimeline.spec.js`。隔离组件浏览器检查与真实账号保存、真机键盘需分别确认。

## 记录与保底语义

同时填写距下次保底抽数 `N`（整数1–40），服务端按 `40 − N` 替换当前进度；40是明确标注的换算口径。未知或超出换算范围的旧进度不自动猜值；当前保存契约不允许距保底留空，需先核对真实进度，无法确认时可以退出教程保留当前窗口草稿。出货修改、新增、移除与保底一起提交，失败全部回滚并保留草稿；打开/取消不写入、不更改已有当前池偏好。

首页不请求历史分页，仅在打开弹窗后读取本池记录，源数据按出货顺序加载、界面从新到旧展示，可加载更多；读取失败不能把未加载的记录当成空池保存。提交仅包含改过或新建的稳定event_id及明确移除的ID，没加载/没修改的历史不被覆盖。每次最多修改/新增120条、移除120条；新行和请求ID在网络重试时保持不变，重复保存已登记结果不会新建重复事件。跨设备409时重读本池版本，保留用户草稿，核对后重新提交。

占位UP绑定正式密探后保留固定槽身份并显示新名字/头像；退役的旧结果可修改抽数或移除。停用、目录或图鉴不可用时可维护已有记录和保底，不能新增结果；游戏快照错配只可查看和导出。

摘要和卡片“已知累计”采用旧基准、独立事件已知间隔、批次总量及当前进度之和。修改独立事件替换其贡献，移除独立事件减去该条抽数；相邻跨度不变。批次内节点的编辑/移除不改变批次总量，已知跨度之和不能超出该批次总量。基准与批次继续保存，首页不提供其旧维护入口。

账号切换、身份失效或账号游戏变更清除弹窗及未提交草稿；A账号迟到响应不能关闭B账号新弹窗。关闭弹窗恢复发起卡片焦点。首版仍不提供彻底清空与MaaYuan自动采集。

色条长度按40抽刻度显示，≤20绿色、21–30金色、≥31红色；超出刻度仍显示原始数值，未知抽数用中性色。颜色只帮助比较间隔，不推算概率或欧非评级。仅已确认non_up显示“歪”，未知UP状态不猜标记。

## 备份与恢复

账号栏“备份与恢复”就近展开面板；收起保留同账号输入，切账号关闭并清空。无公共目录时仍可通过“导入备份”聚焦文件选择。

JSON `yuanhub.recruitment.v1` 继续导出同一版本的完整事件、批次、基准和进度，包括已删除记录，最多5MiB / 20000条结果，超限整包拒绝。本次不新增名单字段或改变备份格式，新弹窗中的出货仍由既有events备份。导入先预览、确认候选总数；默认保留当前状态，不复活旧删除、不写公共目录、不新增用户临时池或密探。网络结果未确认时可重试原导入请求。

CSV包含baseline、pool_state、batch、event行，批次内事件与已删除事件不重复计数，未知值留空。UP名字采用当前槽解释，无法匹配回退原快照。CSV仅用于阅读，不能恢复。

管理页 `/recruitment/admin` 需要 `recruitment_catalog:write`；用户不能自定义卡池或临时密探。

新增 UP 名额后，通过“对应图鉴绝密”选择同游戏的绝密密探；图鉴加载成功时可选择，保存中或图鉴加载失败时禁用。加载失败仍保留已有绑定及占位名称，点击“刷新目录”成功后恢复选择；“已对应图鉴”仅表示该名额已有绑定。

## 时间线 UP 出货摘要（2026-10-06）

立绘继续表达 UP 阵容；每个当前有效 UP 使用 42px 小头像与右下角压边的单行 `×N` badge，次数不独占一行。头像使用 `--line` 的 1px 弱边界，不保留稀有度强调描边；正数为茶棕底/奶油字，`×0` 与未知 `—` 为暖白底/次要暖棕字、较轻字重。所有有效槽都展示，以 8px 间距紧凑横排；头像与 badge 共用一个网格单元，较大次数按内容占宽，只在完整单元之间换行。封面内保留底部留白，不新增头像 hover 或独立控件。整卡按钮保持键盘入口，ARIA 名称明确读作“密探名，获得 N 次”；未知统计读作“统计未知”，摘要本身不增加焦点或 live region。

数据直接取 `archive.pool_summaries[pool_id].up_agent_counts[upSlot.id]`，字段/键缺失或无效值显示 `—`。槽 id 在占位绑定图鉴后不变；图鉴失败回退槽名/头像占位，目录缺失回退池快照。只读首页不会请求 events；进入池后仍按需分页。账号切换沿用 useRecruitment 的同步清空与 generation 拦截；保存或SSE后权威 archive 刷新也更新 chip。

本改动为 L3（新增读 API 字段）。最小回归命令：

cd ../BackEndV3-Share
./gradlew test --tests '*RecruitmentServiceTest' --tests '*RecruitmentControllerContractTest'

容器回归只使用已有 TestMongo 隔离数据库，禁止接入开发数据库。浏览器重点检查390px/1440px，320px下多UP/较大次数不溢出；未知、0、账号切换、保存后刷新和整卡Tab/Enter保持正确。
