## 1. 目标与职责边界

「当前养成」不是图鉴的列表版，也不是养成追踪的缩略版。它承担两个职责：

1. 作为当前子账号的密探养成状态台账，集中展示、校正和提升当前属性；
2. 从台账中任选任意数量的密探，生成信息完备的委托交接资料。

四个相关视图的边界如下：

| 视图 | 回答的问题 | 主要动作 |
|---|---|---|
| 图鉴 | 有哪些密探、当前账号拥有谁 | 浏览、筛选、登记拥有 |
| 当前养成 | 已拥有密探当前练度如何、现在能做什么 | 比较、标注、校正、快捷提升、生成委托资料 |
| 养成追踪 | 接下来重点练谁、还差多少、多久够 | 设置目标、计算缺口和 ETA |
| 库存 | 当前有哪些资源、资源如何变化 | 盘点、导入、查看流水 |

### 1.1 明确不进入本页面的内容

- 展示当前已装备星石并支持快捷卸除；不在本页面提供星石替换、升级、推荐、多方案或库存管理，这些能力以后由独立星石管理界面统一承载；
- 双命盘只展示「命盘一 / 命盘二」，不维护「当前命盘」或切换当前装备；
- 不计算、不展示、不校验五铢钱；
- 不把长期目标、材料 ETA 或完整库存流水搬入当前养成；
- 不限制委托清单人数，五位只是桌面端同屏可读性的最低设计目标。

## 2. 核心概念与状态模型

页面中有四类互相独立的状态，不能合并为一个字段：

| 状态层 | 可选值 | 数据含义 |
|---|---|---|
| 拥有状态 | 未拥有 / 已拥有 | 客观账号状态；当前养成只列出已拥有密探 |
| 养成状态 | 养成中 / 已毕业 / 不养成 | 主要用于当前养成的分组、排序和筛选 |
| 特别关注 | 未关注 / 已关注 | 独立追踪心纸收集、化极记录、目标和提醒 |
| 委托选择 | 未选择 / 已加入委托清单 | 当前一次委托资料的临时选择，不改变养成状态 |

养成状态的产品语义：

- `养成中`：默认值，表示当前没有被置后的特殊安排；
- `已毕业`：由用户主观认定已经完成养成；不自动根据等级、修为或化极判断；
- `不养成`：已经拥有但不准备继续投入常规养成资源；保留完整资料。

特别关注与养成状态可以任意组合。已经满级、满修为并拥有满意命盘的「已毕业」密探，仍可能因为心纸收集、化极记录或委托使用而保持特别关注。养成状态不得自动新增或取消特别关注。

委托选择同样独立：任何养成状态、任何关注状态的密探都可以加入委托清单，包括「不养成」。

### 2.1 默认筛选与简化规则

顶部把养成状态与特别关注拆成两组控件：

```text
养成状态：全部 38｜养成中 21｜已毕业 12｜不养成 5
特别关注：全部｜仅特别关注 7
```

- 默认展示全部已拥有密探，排序优先级为「养成中 → 已毕业 → 不养成」；
- 在同一养成状态内，特别关注优先，其后继续按等级、化极、修为和发布顺序排序；
- 已毕业和不养成只负责排序、筛选和视觉弱化，不会锁定编辑、阻止委托选择或自动改变特别关注；
- 用户选择的筛选、排序和折叠状态按「账号」保存在浏览器；
- 「只看可提升」是独立筛选，不改变养成状态；
- 特别关注继续沿用现有独立业务含义和 API，是养成追踪名单的真相源。

## 3. 页面与信息布局

### 3.1 紧凑工作区头部

进入当前养成后，页面头部只保留执行任务所需的信息：

```text
[子账号] [版本] [搜索] [养成状态] [仅特别关注] [只看可提升]
[选择委托资料] [生成委托资料（N）]
```

通用 Hero、账号管理和数据交换不应持续占据当前养成首屏：

- 首次进入仍可展示完整页面头部；
- 用户开始滚动或进入「选择委托资料」后切换为紧凑吸顶工具栏；
- 委托预览中隐藏全部编辑、提升、账号管理和导航控件。

### 3.2 密探紧凑数据行

桌面端采用纵向对齐的数据行，不做五张并排卡片：

```text
☐ 头像  孙尚香 · 火 / 破军  [特别关注]
   等级 Lv90 [+5] [+10]  修为16 [+1]  化极4-3 [下一节点]
   攻击 8186  生命 28704  奇闻：攻击500/500 · 生命2600/2600 · 增伤15/15
   星石：主 破军60 · 七杀50 · 空｜辅 天相50 · 空 · 空      [卸除…]
   命盘一：技能增伤 · 普攻强化 · 初始能量
   命盘二：群体增伤 · 防御转攻 · 免伤                  [完整编辑]
```

展示字段：

- 头像、名称、属性、从属、养成状态；
- 等级、修为、化极节点；
- 奇闻三项当前值与上限；
- 奇闻内部固定使用 `attack / hp / special`，其中 `special` 的展示名称从密探公共图鉴读取，不由账号数据或页面职业映射决定；
- 攻击力、生命力及其来源状态（自动计算 / 扫描观测 / 手动校正）；
- 六个当前装备星石槽位的名称、等级与空槽状态；
- 两套命盘的名称和各自最多三个具体命盘；
- 数据更新时间或数据完整性提示；
- 行内快捷操作及完整编辑入口。

桌面端设计目标：在 `1440 × 900` 视口、紧凑工作区头部下至少完整看到五位密探。星石摘要与攻生/奇闻采用左右分栏或可换行的紧凑槽位，单行建议控制在 `112～124px`，不能通过缩小正文字号实现五人同屏。移动端改为纵向卡片，星石区默认显示摘要并可展开；导出的委托资料使用独立的桌面宽度版式。

### 3.3 单项编辑与提升的区别

当前值和相邻按钮表达两种不同动作：

- 点击当前值：校正 YuanHub 中的记录，不扣库存；
- 点击相邻提升按钮：执行一次真实养成，更新密探属性并扣除对应库存。

| 单项 | 点击当前值 | 默认快捷按钮 | 智能建议替换示例 |
|---|---|---|---|
| 等级 | 输入准确等级 | `+5`、`+10` | `材料已齐，可升至 Lv95` |
| 修为 | 输入准确修为 | `+1` | `材料已齐，可升至修为17` |
| 化极 | 选择准确节点 | `下一节点` | `心纸已齐，可升至4星` |
| 奇闻 | 直接编辑三项当前值 | 无 | 无 |
| 攻击 / 生命 | 查看计算明细或手动校正 | 无 | 随输入实时刷新 |
| 已装备星石 | 查看槽位、名称、等级与面板贡献 | `卸除` | 无；不在此页推荐或替换星石 |
| 双命盘 | 打开双命盘编辑 | 无 | 无 |

视觉上必须区分「校正」和「提升」：提升按钮在确认前显示消耗预览；校正表单明确写出「只修改记录，不扣库存」。

星石卸除是第三类动作：它不扣材料、不删除星石资产，但会改变当前装备并影响攻生。单槽卸除放在对应槽位详情中，整套卸除放在星石区次级菜单；两者都需要确认并显示预计攻生变化。成功 Toast 提供即时撤销，恢复窗口内的空槽继续提供「恢复上一颗」；不能把高风险整套卸除做成无确认的行内图标。由于当前页不提供通用换装，服务端可恢复记录是卸除功能的上线门槛。

### 3.4 智能建议替换规则

智能建议不增加额外按钮，而是替换对应单项的默认快捷按钮：

```text
普通：修为16 [+1]
可执行：修为16 [材料已齐，可升至17]
```

规则：

1. 等级建议目标为下一组有意义的 `+5 / +10` 节点或当前材料可达到的最高节点；
2. 修为建议可以跨越多个连续可支付阶段；
3. 化极建议可以跨越多个连续可支付节点，并优先用星级边界作为文案；
4. 只校验经验书、突破材料、修为材料、密探心纸及觉醒特殊材料；五铢钱完全忽略；
5. 「已毕业」仍可接收化极等建议，特别关注的已毕业密探仍正常进入养成追踪；
6. 「不养成」仍保留建议、快捷按钮和主动预览能力，只通过默认置后减少主工作区干扰；
7. 多个密探可能争抢同一份通用材料。每次操作完成后必须用最新库存重新计算其余建议；
8. 执行前由服务端重新计算并确认消耗，前端建议不得作为最终扣减依据。

### 3.5 委托交接资料

用户进入「选择委托资料」模式后，密探行左侧显示复选框，并出现批量操作栏：

```text
已选择 8 位密探｜全选当前筛选｜清空｜生成委托资料（8）
```

要求：

- 可选择任意数量，不设五人上限；
- 可以按选择顺序或手动调整顺序；
- 前五位可显示为建议主力，其余自然作为可替换密探，但不强制区分；
- 交接资料完整展示等级、修为、化极、奇闻、攻击、生命、当前已装备星石和双命盘；
- 交接资料不展示星石库存或管理动作、库存、提升按钮、编辑按钮或内部账号 ID；
- 1～5 位可生成单页图；超过 5 位支持连续长图，后续可补每五位分页导出；
- 第一版只生成本地 PNG / 可复制文本，不创建公开分享链接；
- 标注子账号别名、游戏版本、生成时间和数据完整性，但允许隐藏账号别名。

### 3.6 自动采集报告导入

当前养成的数据交换入口接受《密探养成数据交换协议 v3》JSON。检测到只有 `operator_snapshot + source_kind=scan` 时显示为「导入自动采集报告」；包含 `operator_annotation_snapshot` 时显示为「导入完整养成档案」。流程固定为：

```text
选择文件 → 校验格式 → 选择子账号 → 服务端预览差异 → 排除/确认记录 → 提交 → 刷新列表
```

预览必须分开展示等级、修为、化极、奇闻、攻生、双命盘和当前已装备星石，并说明哪些分区会覆盖、合并、保留或等待人工复核。若文档包含主观 annotation record，再独立展示养成状态、特别关注、养成目标和备注；没有该 record 时必须明确显示「主观数据不变」。自动采集权限不允许携带 annotation record。

已装备星石必须随扫描一起导入，因为扫描攻生只在同一套等级、修为、化极、奇闻和装备输入下有效。任一输入改变后，旧扫描攻生显示为「已过期」；有完整规则时改用实时计算值，没有完整规则时提示重新采集，不能继续把旧观测值标成当前值。

正式字段和覆盖语义见 [`operator-growth-data-exchange-protocol-v3.md`](./operator-growth-data-exchange-protocol-v3.md)；采集字段映射、奇闻上限和异常处理见 [`operator-auto-scan-integration-plan.md`](./operator-auto-scan-integration-plan.md)。

## 4. 数据来源与一致性

| 数据 | 当前来源 | 目标来源 |
|---|---|---|
| 名称、头像、属性、从属、命盘目录 | 公共密探图鉴 | 不变 |
| 等级、修为、化极、旧单命盘 | `GET /v1/operator/current`；化极已经由 `starLevel` 完整承载 | 扩展后的当前养成响应，继续沿用 `starLevel` |
| 双命盘 | 当前浏览器备用数据 | 云端 `disc_loadouts` |
| 当前已装备星石 | 云端现有 `star_stones` 与自动采集结果 | 继续沿用云端 `star_stones` 六槽；资产化后再支持快捷卸除 |
| 奇闻、手动攻生命、观测值 | 当前浏览器备用数据 | 云端 `combat_stats` |
| 奇闻名称与上限定义 | 当前部分硬编码和职业推断 | 公共图鉴 `oddity_schema`；管理员只维护 `special_oddity_name`，上限由稀有度派生 |
| 自动攻击 / 生命 | 前端 Wiki 规则计算 | 前端继续计算；服务端保存输入而非重复派生值 |
| 养成状态 | 暂无 | 云端独立 `growth_state` |
| 特别关注 | 已有 `agent-favorites` API | 不变；继续独立于养成状态 |
| 养成目标与备注 | 浏览器备用数据 / 暂无 | 云端独立存储；通过可选 `operator_annotation_snapshot` 交换 |
| 材料与心纸 | 库存当前投影 | 不变，由快捷提升事务原子扣减 |
| 委托选择 | 暂无 | 浏览器临时状态；不依赖后端 |

本地备用数据迁移到云端时必须由用户确认，不得在用户不知情的情况下用某台设备的旧缓存覆盖云端新数据。

## 5. 分阶段实施

### 阶段 0：公共图鉴前置改造、契约冻结与测试基线

目标：在改 UI 前固定语义，避免继续累积「当前命盘」「星石摘要」等临时模型。

前端工作：

- 在密探公共图鉴管理员编辑器增加“第三奇闻名称”，新建密探必填；存量缺失项显示待补齐状态；
- 公共图鉴读取层接入 `special_oddity_name / oddity_schema`，不再把职业建议当作正式名称；
- 固定本文件中的页面职责、字段和交互文案；
- 为现有等级、修为、化极计算器补足边界测试；
- 记录当前本地双命盘和战斗属性存储键，准备一次性迁移；
- 明确旧 `discs` 仅作为「命盘一」兼容来源，不代表当前装备；
- 冻结 `myshare-operator-exchange@3`、客观/主观 record 边界、`attack / hp / special` 奇闻键、统一的 `star_level` 化极编码，以及已装备星石槽位语义；
- 明确五铢钱从全部可执行判定和消耗结果中排除。

后端工作与依赖：扩展公共图鉴实体和管理员写入 DTO，公共读取接口返回服务端派生的 `oddity_schema`；名称或稀有度变更更新 `catalog_version` 并清理缓存。完成前不开放 v3 正式写入。

验收：管理员可以维护第三项名称；养成值和 v3 样例只使用稳定键；修改展示名称不会迁移已有用户数据或使攻生观测过期；产品、前端、后端对状态枚举、双命盘语义和升级事务边界没有歧义。

### 阶段 1：后端客观资料底座与只读工作台 MVP

目标：先把完整委托资料建立在跨设备真相源上，再解决「一眼看到完整资料」和「把资料交给委托对象」的问题。

实施顺序固定为“后端先完成契约与测试，前端再接入”，不再把浏览器双命盘或奇闻缓存作为阶段验收依据。

后端工作：

- 复用现有 `starLevel`，不新增另一套化极存储；
- 复用现有六槽 `starStones`，明确其当前装备语义，并允许 current PATCH 直接完整替换六槽；
- 增加最多两套且没有 active 状态的 `disc_loadouts`；
- 增加 `combat_stats.oddities`、扫描攻生、手动校正与输入有效状态；
- 增加 entry revision 和安全局部 PATCH；
- 保证 v2 `discs` 只更新第一套，不覆盖第二套或战斗属性；
- 保证 v2 import/export/delete replay 兼容。

权威批次规格：[`backend-operator-current-foundation-spec.md`](./backend-operator-current-foundation-spec.md)。可直接投递的后端任务：[`backend-implementation-prompt-operator-current-foundation.md`](./backend-implementation-prompt-operator-current-foundation.md)。

前端工作：

- 将现有简略行重构为分区紧凑数据行；
- 在当前养成展示 6 槽已装备星石摘要，第一阶段可先只读；
- 展示两套命盘，不展示当前装备或切换操作；
- 把攻击、生命、奇闻从编辑弹窗提升到列表主视图；
- 增加搜索、基础筛选和任意数量委托选择；
- 使用现有 `html2canvas` 生成委托 PNG，并支持复制文本；
- 将浏览器中的双命盘、奇闻、六槽星石和手动面板通过一次 PATCH 写入，成功后以云端为准；星石不得通过旧 v2 import 补发；
- 完成 `320 / 375 / 414 / 768 / 1024 / 1440` 宽度验收。

后端依赖：本阶段前端开工前，必须完成上述客观资料底座、OpenAPI/Swagger 和契约测试。公共目录与现有 `starLevel/starStones` 已就绪，不属于本阶段待重做项。

验收：换设备后两套命盘、奇闻、攻生和六槽星石一致；桌面端至少可同时阅读五位完整密探；委托选择人数不受限制；列表和输出不包含星石管理动作或当前命盘语义。

### 阶段 2：自动采集直导与主观养成状态

目标：在阶段 1 客观资料已经跨设备可靠的基础上，补齐养成状态、目标与自动采集写入闭环。

前端工作：

- 接入后端阶段 A2 的养成状态与目标 API；
- 增加「养成中 / 已毕业 / 不养成」标注、筛选和置后排序；
- 保留现有特别关注 API 和 UI，并支持与任一养成状态组合；
- 化极在 current 与 v3 中统一读取 `starLevel/star_level`；已装备星石继续读取现有 `star_stones`；
- 将当前名称型奇闻和固定 `500/2600/15` 初始化迁移为稳定 `attack / hp / special`，名称和上限均读取公共图鉴 `oddity_schema`；服务端仍按 3 星 `300/1560/9`、4 星 `305/1820/11`、5 星 `500/2600/15` 校验；
- 提供 v3 JSON 文件入口、来源账号映射、服务端差异预览、逐 record/逐密探/逐分区排除和提交结果；
- 客观与主观记录分区展示；支持把本地养成目标迁移为 annotation record，但不得因文档缺失主观记录而清空现值；
- 对扫描攻生显示输入签名状态，星石等输入变化后立即标记旧观测过期；
- 阶段 1 已完成本机客观备用数据迁移；本阶段只处理可选 annotation record 中的主观目标与备注；
- 云端保存成功后停止继续写入旧本地主观格式，只保留短期降级缓存；
- 委托资料显示云端更新时间，不再依赖「仅本机」警告。

后端依赖：阶段 A1 客观资料底座、阶段 A2 养成状态与目标，以及 v3 import preview/commit；v3 的 `star_level` 直接写入现有 `starLevel` 并按公共图鉴身份复核，`equipped_star_stones` 在协议边界适配到现有 `starStones`。

验收：换设备登录后，状态、奇闻、攻生命校正值、已装备星石和两套命盘一致；同一份扫描文件可预览后导入，且不会覆盖用户养成状态或特别关注。

### 阶段 3：行内校正与双命盘编辑

目标：减少进入完整大弹窗的频率，同时保留准确校正入口。

前端工作：

- 等级、修为、化极当前值支持锚定式编辑；
- 奇闻三项按稳定键支持行内编辑和就地校验，第三项标签实时取公共图鉴；
- 攻击、生命显示计算来源，并允许清除手动校正恢复自动计算；
- 已装备星石支持查看面板贡献、单槽卸除、整套卸除、即时撤销和空槽「恢复上一颗」；
- 双命盘编辑去除当前装备单选，只保留两套名称和各自三个命盘；
- 所有校正动作明确提示「不扣库存」；
- 保存时提供局部 loading、成功和字段级错误反馈。

后端依赖：支持安全的局部校正接口，以及原子星石卸除、持久化最近卸除记录和恢复接口；不能用清空前端数组或旧 `listed operator_snapshot` 模拟卸除。恢复链路未完成时，本阶段只展示星石，不开放卸除。

验收：用户可以在不离开比较语境的情况下校正主要数据；键盘和触屏均可完整操作。

### 阶段 4：原子快捷提升与智能按钮

目标：实现属性变化与库存扣减的一次性闭环。

前端工作：

- 等级提供 `+5 / +10`，修为提供 `+1`，化极提供「下一节点」；
- 点击后读取服务端消耗预览，展示扣减前后库存；
- 接入批量智能建议，用「可升至……」替换默认按钮；
- 执行期间锁定对应密探的提升操作；
- 成功后同时刷新密探状态、库存和所有受共享材料影响的建议；
- 对库存不足、状态过期、重复请求显示明确的行内反馈；
- 不提供前端串行调用两个导入接口的降级实现。

后端依赖：升级预览、批量建议、幂等原子执行、库存消耗流水和并发版本校验。

验收：任何失败都不会产生「属性已变但库存未扣」或相反状态；重复点击不会重复扣减。

### 阶段 5：增强与长期能力

可选内容：

- 委托资料每五位分页、模板选择和用户备注；
- 可撤销的升级反向流水；
- 有期限、可撤销的私密分享链接；
- 多选批量设置养成状态或特别关注；
- 操作历史与状态变化时间线。

本阶段不阻塞核心工作台上线。

## 6. 跨阶段质量要求

### 6.1 可访问性与交互

- 图标按钮必须有可访问名称；
- 移动端主要触控目标建议不小于 `44 × 44px`，相邻操作至少保留 `8px` 间距；
- 星石槽位优先换行而不是缩小文字；空间不足使用可操作的「另有 N 颗」展开控件，并支持键盘触发，不能只靠 hover 看完整信息；
- 输入始终有可见标签，不以 placeholder 代替；
- 字段错误放在对应字段附近，并通过 `aria-describedby` 关联；
- 保存、提升、星石卸除/撤销、状态切换都必须有 loading 和成功 / 失败反馈；
- 不仅用颜色区分养成状态和特别关注，必须同时展示文字或图标。

### 6.2 视觉规范

- 继续使用纸底、暖白、奶油、暖棕、茶棕和蜜黄；
- 特别关注使用蜜黄底棕字；
- 已毕业可使用茶棕小面积标签或印章式描边；
- 不养成使用低强调度细描边或虚线，不使用大面积绛红；
- 海盐蓝仍只用于品牌 / 外链 / 焦点描边；
- 正文不小于可读阈值，不能为了五人同屏压缩成密集小字。

### 6.3 性能与长列表

- 已拥有密探超过 50 位时使用虚拟列表或分批渲染，滚动、筛选和星石展开不阻塞主线程；
- 委托导出使用独立的离屏静态排版数据源，不能直接截图虚拟列表的当前可见区域；
- 星石摘要、攻生和扫描状态预留稳定高度，异步刷新不得造成整页明显跳动；
- 自动采集 preview 对大文件显示可取消的进度状态，解析/网络失败保留已选文件和明确重试入口。

### 6.4 测试清单

- 养成状态筛选、特别关注组合筛选、账号隔离、状态切换失败回滚；
- 委托选择跨筛选保留、任意人数、顺序和导出内容；
- 本地数据迁移冲突和取消迁移；
- 自动采集格式/版本拒绝、身份不确定、部分分区、奇闻越界和重复 `record_id/scan_id`；
- 名称型奇闻键被 Schema 拒绝、第三项 OCR 名称不一致只产生 warning、公共图鉴缺名降级提示、管理员改名不迁移用户值；
- v3 只有客观 record、同时包含主观 record、annotation listed/full、显式 null 清除与账号 mapping；
- 3 星奇闻 `300/1560/9`、4 星 `305/1820/11`、SP 无小节点的展示与校验；
- 已装备星石双命盘去重、单槽/整套卸除、失败回滚、撤销和观测值过期；
- 等级 `+5 / +10` 边界、修为等级上限、化极星级边界；
- 共享材料竞争后建议重算；
- 原子提升幂等、库存不足、状态过期和网络中断；
- 桌面五人同屏以及移动端无横向溢出；
- 委托输出不包含账号内部 ID、编辑控件或星石管理动作；当前已装备星石摘要与攻生来源一致。

## 7. 完成定义

核心阶段完成后，用户应能：

1. 在当前养成中直接比较至少五位密探的全部关键养成资料；
2. 用养成状态把已毕业和不养成密探稳定置后，同时独立保留特别关注追踪；
3. 点击当前值进行不扣库存的准确校正；
4. 使用贴近单项的快捷按钮提升等级、修为或化极；
5. 在材料足够时看到替换默认按钮的一步到位建议；
6. 通过一次确认同时更新密探属性和对应库存；
7. 导入自动采集 JSON，经差异预览后同步基础养成、攻生、当前已装备星石与双命盘；
8. 在列表查看当前已装备星石并安全地单槽或整套卸除；
9. 任意选择多位密探并生成包含当前已装备星石和双命盘的委托资料。
