# MaaYuan Share 设计规范 v1.0

> 本站由 **MaaYuan · 鸢BWiki · 辟雍学府 · YuanAssist** 四方共建。
> 定位：MaaYuan 主导的 JSON 作业站，同时是各家功能的联合看板入口。
> 目标用户：如鸢 / 代号鸢玩家（女性向），整体气质：温暖、柔和、书卷气。

> **适用边界：** 下列色彩、字体与组件样式描述的是 YuanHub 已有品牌基线和典型页面，不是要求所有页面长得一样的硬性模板。用户本次明确的效果图或设计提示词可覆盖非功能性视觉建议；没有新方案时优先保持所在模块现有风格。业务/权限、键盘交互、焦点管理、浮层层级等功能约束继续有效。不要为“全站统一”批量重做已验收页面。

## 2. 字体

- **当前常用标题**：思源宋体（Noto Serif SC）；字重和字距根据页面层级选择，不统一固定为 900。
- **当前常用正文**：PingFang SC / 微软雅黑；以清晰易读为目标。
- **当前常用数字**：Archivo；密集表格、数据展示可使用与具体设计更协调的字号和字形。

以上是品牌常用字体，不要求所有模块使用完全相同的字体组合、字号及排版密度。

## 3. 背景

当前站点 `body` 以 `/maayuan/maayuan-pattern.webp` 配合暖纸张渐变构成品牌背景。保留现有共享壳层资源；页面或功能区可按明确设计采用不同的局部底板、纹理与布局，不要求每个模块复制同一背景。

主站支持「浅色 / 深色 / 跟随系统」，首次默认浅色；访客可在桌面侧边栏底部的账号菜单「外观」或手机导航抽屉中选择。偏好保存在当前浏览器的 `yh_theme`，退出登录不清除，也不向账号或服务器同步。只有「跟随系统」响应系统主题变化；存储异常时仍能在当前会话切换，但刷新可能无法保留。

`index.html` 的首屏主题控制器在样式和应用加载前解析偏好，设置根节点 `data-theme`、`color-scheme`、底色和 `theme-color`；`src/store/theme.js` 接管同一个控制器的状态与系统监听，切换不刷新页面、不重挂载编辑器。浅色继续声明 `only light`，避免浏览器自行深色化；深色明确声明 `dark`。系统接管的 PWA 启动画面仍保持浅色；第三方强制夜间模式及真机冷启动需人工验收。

深色使用暖炭底、暖白文字与低饱和状态色。`src/styles/theme.css` 提供根主题和导出隔离作用域；原有 `--paper`、`--surface`、`--cream` 用于底板，`--on-strong`、`--on-surface`、`--on-paper` 用于原来深色块上的浅色文字，`--on-pastel` 保持游戏浅色属性印章上的深色文字。局部固定颜色使用 `var(--theme-语义, 原浅色值)`：浅色保留原值，深色才覆盖。不要按色值全文替换、整页反色，或把同一文字变量同时用作按钮底色；强调按钮底色使用 `--theme-control-bg` 等对应语义。基础色板正文对比度由 `test/themeColors.test.js` 检查，不能代替真实界面验收。

主题覆盖主站已有路由及 Teleport 浮层，包含主站 `/promo`，不包含独立 `promo-site/`。游戏素材、属性与稀有度标记保持身份含义；日历和招募分类通过共享 `eventTypeColor` 保留分类色系与浅色回退。账单导出的独立 `.cart-export-view[data-theme="light"]` 重置基础与深色语义变量，图片固定浅色，屏幕账单正常跟随用户主题。

星石配装/预设的错误提示使用深色危险文字变量，预设保存按钮使用 `--on-strong`；招募 21–30 抽徽标在深色使用强调底色；养成规划条件/策略图标优先使用 `--theme-accent-text`，浅色均保留原配色。

人工验收：打开桌面侧栏底部账号菜单/手机抽屉，切换三档，刷新后确认保留；选择浅色时改变系统主题不应影响页面，选择跟随系统时应同步。再打开公共弹窗、密探编辑器、日历和账单，确认文字/焦点/状态清楚、未保存草稿保留，深色下导出的账单仍为浅色。重点视口为 390px、768px、1440px，另检查窄屏和矮窗口中导航入口可达。

## 5. 核心组件约定

### 图标

- 系统界面图标统一使用 Lucide，主站从已有的 `@lucide/vue` 按需导入；禁止使用表情符号、字符画或其他图标库替代界面图标。
- 图标继承 `currentColor`，默认线宽为 2；同一层级保持尺寸一致。文字旁的装饰图标标记 `aria-hidden="true"`，纯图标按钮保留可访问名称。
- 按操作语义选择图标：编辑使用 `Pencil`，删除使用 `Trash2`，关闭使用 `X`，搜索无结果使用 `SearchX`，操作历史使用 `History`，导入与导出使用 `ArrowLeftRight`。
- 入口图标对应内容：公共密探图鉴使用 `BookUser`，招募卡池管理使用 `Layers3`，审计记录使用 `Logs`，自动化工具使用 `Workflow`。
- 星级等文本字段使用“星”等文字；品牌 Logo、游戏素材及数据图表保留各自资源，不作为通用界面图标替换。
- 独立宣传页使用来自 `@lucide/vue` 1.31.0 的本地 SVG sprite（`promo-site/public/icons/lucide.svg`），许可证随站点发布于 `/lucide-LICENSE.txt`，不依赖主站运行环境。
- 图标规则适用于内置界面内容，不清洗或改写用户提交的数据。

### 5.1 桌面轻量导航

桌面侧栏距左侧及上下各 12px，宽 232px，使用暖色不透明底板、18px 圆角、柔和细边框和轻阴影；保留紧凑密度，避免原先大留白。玩家入口保留原字体家族和 600 字重，使用较紧凑的行距与图标；选中项使用淡金底色与短竖线；已固定管理工具仍可直接进入，工作台和「更多」保留。主导航可滚动，底部账号与通知独立。

账号菜单包含账号与连接码（访客为登录/注册）、三档外观、退出登录及真实版本；支持 Esc 关闭并回到触发入口、点击外部或焦点离开关闭。手机继续使用原抽屉与主题入口。

今日一览桌面正文从侧栏后 32px 开始，页头和卡片左对齐，最大内容容器宽 1600px。沿用原鸟纹资源，桌面首页透明度降至 0.045、底色改用主题 surface；其它页面正文布局、手机背景及业务卡片不跟随重排。

### 5.2 跟打表（四方拉通的"货币"）

- 结构：回合 × 密探五列 + 备注列；记号语法 `↑上拉开大 · ↓下拉防御 · A 平A · 圈 特殊技能`
- 米白表底、茶棕表头、细棕线、超大圆角
- 关键动作用 1.3 马卡龙色块高亮（与 BWiki 出图一致，用户无缝识别）
- 备注列放控血 / 重开 / 赌点条件

### 5.3 标签

密探名册卡片的攻击、生命漆园蝶分别达到已知正数上限时，该行图标、当前值和上限以深绿色 `#276749` 强调；保留原数值，不新增完成标签。未满或上限未知时沿用原色。

桌面端 V3 密探名册与分享卡的两三字姓名保持单列竖排，高度随文字撑开，避免网络字体加载后折成两列；长称号与手机端沿用各自排版规则。

V3 名册与分享卡立绘挂载后主动排队加载，与库存图片共用最多 8 张并发的加载队列；成功或失败后继续后续图片，不依赖滚动进入视口。整页截图前仍需等待图片加载完成，iPhone 原生整页截图效果需真机验收。

- 分类标签：蜜黄底棕字
- 站点标签（如鸢/代号鸢）：透明底 + 描边
- 品牌标签（MaaYuanShare）：海盐蓝描边（学 YuanAssist 站内样式）

### 5.3.1 工作区导航与分段控件

| 类别 | 现有控件 | 维护约束 |
| --- | --- | --- |
| 顶层工作区 Tab | 库存清单/统计报告/操作历史、密探图鉴/养成总览/养成规划、星石背包/养成计划 | 现有页面复用 `src/styles/tools-workspace.css`；新设计可以采用局部视觉方案，不把该文件当所有 Tab 的统一模板 |
| 局部视图切换 | 统计报告 `.acquired-views`、日历列表/时间线/月历、招募展示视图 | 保留局部底板和层级；日历保持 `group` + `aria-pressed` |
| 状态/排序筛选 | `.feedback-status-tabs`、通知中心 `.tabs` | 保留各自筛选视觉与行为，不套顶层工作区样式 |
| 跨路由导航 | `FeedbackWorkspaceNav.vue` | 保留 `router-link` 和路由高亮，不声明为页内 Tab |

- 顶层 Tab 的现有底板、颜色、边框和字号以 `tools-workspace.css` 为当前实现参考；不统一强制 44px 高度、字号、圆角或选中态外观。若任务要求重新设计，可局部调整视觉，但保留 `aria-selected` 等状态语义，并避免切换时布局抖动。
- 非选中项、悬停与焦点的视觉反馈可随具体页面设计变化，但必须有可辨认的选中态与 `focus-visible`；禁用项保留原生 `disabled`。“即将上线”若可点击查看说明，应使用相应弹窗语义（如 `aria-haspopup="dialog"`），不冒充可进入的 Tab。
- 当前顶层 Tabs 采用容器内横向滚动；明确的新设计可以换行、折叠或重排，但不得导致整页横向溢出、裁切核心标签或遮挡操作。既有页面不因视觉统一而恢复旧 1080px fixed 底栏；网站一级导航独立维护。
- 库存、密探和星石采用手动激活 Tabs：左右键循环焦点，Home/End 到首尾，Enter/Space 经原按钮调用原有切换函数。焦点移动不能触发加载、编辑放弃确认或弹窗；离组后恢复当前选中项的单一 Tab 入口。面板以 `id`、`aria-controls`、`role="tabpanel"`、`aria-labelledby` 关联；密探面板保留原有懒挂载。星石截图识别是独立动作，导入时两个背包视图均不选中，内容区域使用有名称的 `region`。
- 新增控件先判断所属任务，不因类名含 `tabs` 就扩大共享选择器或套同一外观。背景与动画可按具体设计调整，同时确保文字对比度与 `reduced-motion` 可用性。

键盘模式依据 [WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)，沿用必要的键盘导航与焦点语义，不要求统一视觉外观，也不改业务数据流。

### 5.4 反馈中心

- 信息架构采用紧凑工作台：简洁 Hero、搜索与状态筛选、桌面表格、移动端工单卡、模态详情。
- 纸底、暖白卡与茶棕表头是当前工作台视觉基线；后续明确的反馈工作台设计可采用独立的密度、布局与配色，不强制与其它页面完全一致。
- 工单类型、板块、处理中和危险操作应能清楚区分；具体颜色可由本次设计方案决定，不以旧颜色映射作为全站硬限制。
- 详情对话允许左右分组，但提交人消息使用蜜黄，管理员消息使用暖白卡与茶棕细线。

### 5.5 浮层层级（z-index）

- 浮层顺序统一登记在 `src/styles/main.css` 的 `:root` 层级刻度中，组件只引用变量，不得再各写魔数。
- 刻度顺序（由低到高）：`--z-content-raised`(20)、`--z-card-active`(21)、`--z-card-open`(22) 供卡片局部浮起；`--z-sticky-low`(30)、`--z-sticky`(40)、`--z-sticky-controls`(45) 供页面固定工具；`--z-popover`(55) 普通下拉/提示；`--z-overlay`(60) 一级弹窗；`--z-banner`(70) 顶部信息条；`--z-overlay-panel`(90) 页面级详情/编辑弹窗；`--z-overlay-raised`(100) 二级弹窗；`--z-overlay-blocking`(200) 阻断式对话框；`--z-toast`(210) 全局通知；`--z-progress`(220) 路由进度；`--z-skip-link`(230) 键盘跳转入口。局部装饰可用 0–9，不作为全局浮层。
- 从一级弹窗或详情弹窗内部打开的弹窗属于二级弹窗，必须复用 `.modal-mask.is-raised`（或 `--z-overlay-raised`），否则会被宿主遮罩压住而不可见、不可交互。
- 下层弹窗不得越过上层弹窗响应 Escape：顶层弹窗打开时，详情层必须让出 Escape，只关闭最上层。
- 弹窗复用 `useModalFocus`：同步记录打开前的焦点，待 DOM 与模板 ref 更新后再把焦点移入弹窗；重渲染时保留已在弹窗内的焦点，包括录入字段和校验错误摘要；关闭后恢复到发起入口，嵌套弹窗保留父层焦点约束。

## 6. 响应式与跨设备约束

本文负责视觉语言；所有手机、平板、桌面端布局与交互适配统一以 [YuanHub 响应式开发规范](./responsive-development.md) 为准。

- 新增或修改 UI 时必须同步考虑移动端与桌面端，不得把移动适配延后到功能完成之后。
- 组件在窄屏下允许重排、折叠或改变容器形态，但必须保留核心任务与品牌视觉一致性。
- 响应式实现不得通过无限缩小字号、大面积隐藏核心操作或整页横向滚动来维持桌面结构。
- 表格、反馈工作台、管理工作台等密集界面应按响应式规范提供明确的移动端降级方案。

### 局部操作反馈

`p.action-feedback` 为显式接入的紧凑反馈样式，沿用主题底色、正文色和边线，长文本自然换行。提示放在所属工具栏或表单区域，保留原有 `status` / `alert` 语义；不要把普通说明文字全部转成反馈块。密探自动补全及编辑读取反馈归入页头内容区，与工具栏内容对齐。
