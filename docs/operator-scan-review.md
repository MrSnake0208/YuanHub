# 密探扫描复核

## 玩家操作

密探页面有三种入口：手动补录使用「录入密探」；扫描中的不确定项使用「待复核采集结果 → 查看并修改」；已有 JSON 备份使用「更多 → JSON 备份导入/导出」。库存仍使用原有库存导入入口，全站教程开关不受本功能影响。

复核表单展示密探头像、名称、所属游戏账号、已保存现值和采集值。点击待核原因中的链接可定位控件，使用等级、修为、化极/觉醒、奇闻数值或命盘复选控件修改，再选择「本次保存此项」。未知值保持未知，不自动填零或上限。

不在该密探图鉴中的命盘会排在组合选项顶部，以红色边框和文字提示疑似识别错误。例如将「初始能量+3」识别成「初是能量+3」时，请取消错误项，再对照游戏勾选图鉴中的正确命盘；站内不会自动猜测替换，原始采集值仍保留。勾选保存命盘后，校验会分别提示组合名、数量、重复或未知命盘问题；未知命盘的错误摘要会列出所在组合和具体名称，点击可聚焦异常选项。

「校验并预览」只读取服务器校验结果，不保存。核对逐项差异、可完整/部分写入、待核和拒绝数量后，点击「确认保存」。保存回执与预览分别展示；采集成功不等于全部字段保存成功。

取消、关闭、切账号或离开页面时，已修改内容使用现有未保存提示。取消放弃操作可继续编辑；明确放弃后重新打开读取原采集记录，不提供跨会话草稿恢复。

## 数据保护与兼容

- 每份修正仅包含当前密探中显式选择的待核字段，使用 `listed` 范围、手动来源和新的记录标识。可靠分区只读，不随旧采集重传；部分奇闻仅提交所选键，服务端沿用已有合并规则。
- 化极/觉醒中未修改的未知值保留现值中已确认的事实。显式修改仍须满足现有隐密、特殊形态和觉醒规则；无法确定身份时须先对照游戏确认密探。
- 确认前重新调用预览；目标版本或影响变化时更新预览、保留输入并要求再次确认。同一正文的网络重试沿用记录标识；明确的重复提交回执避免再次写入。切账号（包括 A→B→A）、退出登录、路由变化及卸载后的旧响应不得打开新表单或更新保存状态。
- 仅当所有待核项均已处理，且回执明确对应当前账号、密探和修正记录并表示成功，才自动关闭原提醒。部分成功、拒绝、未知分区或缺少逐项结果的旧响应保留提醒。已明确保存的字段锁定，后续修改不会重复提交这些字段。
- 原始 JSON、记录标识、字段路径和英文错误码默认收在「技术详情」中，保留原文复制；「复制脱敏诊断」仅含版本、状态、字段类型和受限错误码，不复制账号/密探/记录标识、自由文本或原始文档。未知错误保留服务端文字原意。

已装备星石、战斗观测和无法定位的其他采集信息暂不支持本表单编辑，原始内容保留，可补证或用 JSON 高级导入处理。保存受支持字段不会自动消除这些提醒。「已另行处理，关闭提醒」只关闭提醒，并明确告知不会保存剩余字段。

本次复用现有 preview/import/current/review 接口，未更改后端契约。确认前的重新预览不能将预览与写入变成原子操作；两次请求之间的并发写入仍受既有服务端校验和事务规则约束。

## 开发检查与集中回归

风险为 **L3**，涉及账号上下文、幂等重试和部分保存正确性。开发期只运行必要的定向安全行为检查、新增纯函数检查、受影响 SFC/JS 编译及局部合成浏览器检查；准确结果和 Git 基线见工作区 `.trellis/tasks/09-29-operator-scan-review/verification.md`。未执行的检查均为待集中回归，不能据此标记反馈已解决。

集中回归从 `YuanHub` 目录执行：

```bash
node --test test/operatorImportUx.test.js test/operatorV3Import.test.js test/operatorScanReview.test.js
npm run test:behavior -- behavior/operatorScanReview.spec.js behavior/operatorEntryDefaults.spec.js behavior/operatorOddityCompletion.spec.js behavior/operatorDiscardedGroup.spec.js
```

集中浏览器验收覆盖：

1. 星级待核、非法命盘、奇闻超限/缺失：只用字段表单修正，原因可定位，可靠分区不重传；含隐密、特殊形态、未知觉醒与原有账号事实。
2. 部分成功、全部拒绝、旧回执、冲突、网络失败、重复提交：逐项状态准确、失败保留输入、重新读回及重试可用，未入库字段和未支持分区可见。
3. 取消后继续、明确放弃后重开、Tab/Esc 与上层共享弹窗、切账号及 A→B→A、退出登录、离开/返回路由和旧文件读取：无草稿误覆盖或跨账号结果污染。
4. 320/390/768/1440 宽度和触屏/软键盘：无横向溢出、按钮可触达、错误定位可见；真实设备证据单独记录，jsdom 不作为手机渲染证据。
5. 手动补录、JSON v2/v3/v4 导入/导出、原文与脱敏诊断复制、现有库存导入和隐藏教程状态：入口正确且旧功能保留。回归以整个批次的前后端起止 Git 基线及全部功能为范围，单个任务的 `./test smart` 不能代替批次覆盖。

可复用的局部浏览器脚本 `test-support/operatorScanReview.browser.js` 仅在既有 Vite 服务中挂载合成组件，拦截业务 API，验证 390 宽度、错误聚焦和共享弹窗；它不验证真实账号写入、完整视口矩阵或真机。
