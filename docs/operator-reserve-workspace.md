# 未来密探储备

当前暂限平台管理员（`PLATFORM_ADMIN`）和超级管理员（`SUPER_ADMIN`）使用。公开开关 `operatorReserve` 默认关闭，管理员凭 `operator_reserve:use` 预览；普通用户、内测用户不显示入口，也不能读写储备接口。已有方案保留，真实培养规划照常使用。

在「培养计划 · 体力规划」进入「未来储备」，为尚未实装或尚未拥有的密探提前估算材料。新建储备方案后，添加培养目标，直接设置属性、职业、目标等级和目标修为；每个目标代表一位未来密探，统一从零培养。多位密探通过多个目标表示，可以选择相同属性与职业。目标默认等级 100、修为 17；属性与职业须主动选择，未补全时不显示确定总额，也不能保存整个工作区。

方案选择、新建与「保存更改」位于顶部，「管理方案」可重命名和删除；只有一个方案也可管理。新建方案后名称可直接编辑。目标四字段始终展开，宽度足够时为两列，窄容器单列。空方案显示添加入口，不显示零值材料表；有目标时在列表后完整展示材料、经验、五铢钱与库存缺口，长表底部也可通过同一保存操作提交。保存后下次打开或刷新从云端恢复；删除须确认并保存后生效。

每个方案是不同的假设：**独立试算，未预留库存**。真实清单也单独使用同一份库存试算，不能将多个方案解释为同时可完成。储备保存只写需求，不创建真实密探、不扣材料、不触发快捷提升或自动刷取日程。

## 费用与未知状态

复用现有 Wiki v9 revision93628 费用规则，普通新目标固定 `count=1`、`current={level:0,elite:0,breakthrough_stage:null}`。先汇总当前方案所有目标，最后抵扣一次共享库存。三种兵书折算同一经验余额，五铢钱独立汇总为总需求。心纸、化极和觉醒费用不在本功能范围。

同方案两个目标同材料各需 100、库存 100，合计缺口为 100，不对每个目标重复扣库存。历史多人目标仍按原人数倍乘后汇总。

职业和属性须在给定选项内。混沌合法但目前暂无费用规则；未补全、非法或规则未知的任一目标都会使整个方案费用保持未知，不输出看似完整的部分总额。等级/修为范围及对应上限沿用真实养成规则。历史目标整十等级突破未知时，仍保留「需确认突破」及未知费用，不要求普通新目标填写当前突破。

库存尚未加载、读取失败或有效数量不可用时显示「库存暂不可用」，保留总需求，不显示确定缺口。仍可编辑和保存合法需求；不要把读取失败解释为零库存或材料足够。

## 保存与恢复

保存失败保留当前草稿。保存期间禁止重复提交和编辑，但可查看费用。成功/失败回执位于保存按钮旁；输入无效时聚焦错误摘要，链接可定位具体字段。

云端冲突时不会覆盖草稿。点击「读回云端比较」查看云端全部方案和需求，再明确选择：

- 「采用云端，替换草稿」：放弃当前本地修改，采用读回内容，不再发写请求。
- 「保留草稿，重试保存」：以读回版本重试，将整个云端工作区替换为当前草稿；若期间再次更新会再次冲突。

切换方案保留所有本地修改，保存仍提交整个工作区；「返回培养清单」及页内重新进入通过保留组件继续保留草稿，不自动保存。切换账号会清空本组件状态，旧账号请求的晚响应不会回填。切换游戏后旧游戏方案保留为只读，可切换查看其他旧方案，需新建对应游戏账号继续编辑；删除账号会清理其储备。

草稿只在当前组件会话保留。未保存时常驻提醒切换账号、页面区域或离开前保存；浏览器刷新/关闭注册 `beforeunload` 提示，路由离开要求确认。页内切换到会卸载组件的其他区域仍需先保存，提示不是永久草稿存储或自动云端保存。

## 历史目标兼容

人数不为 1、原有等级/修为非零或存在原突破阶段的目标显示为「旧目标」。加载、查看、保存均保留原始结构和原计算；旧目标显示只读摘要，不在普通表单重新引入人数或当前进度输入。

「转为从零培养目标」说明清除原有培养进度可能增加材料需求，确认后才修改本地草稿：按原人数拆为独立目标，逐个生成新 UUID，保留属性、职业、目标等级与修为。原进度为零时转换前后总需求及缺口相同；原进度非零时按从零培养重新计算。转换不会自动保存，只有点击「保存更改」才提交。拆分后超过每方案 50 个目标则不提供转换，原数据及旧方案仍可保存，不截断人数。可保留旧目标，也可新建独立方案估算。

## 客户端协议与纯函数

独立 GET/PUT `/v1/operator/reserve-workspace?account_id=...`，沿用认证 request/ApiResult。GET 返回 schema_version=1、account_id、game_snapshot、read_only、revision、updated_at、active_plan_id、plans。空 GET 为 revision 0/plans []，不写数据。

PUT 只发送 `{schema_version:1, expected_revision, active_plan_id, plans}`；每计划为 `{id:UUID, name, demands}`；每需求为 `{id:UUID, count, attribute, profession, current:{level,elite,breakthrough_stage}, target:{level,elite}}`。最多 50 方案/每方案 50 组，名称 1–40 字符，人数 1–999。服务端校验全部范围与归属；未知字段拒绝。旧 training-workspace v1 和固定日程不混入储备字段。

`src/data/operatorReservePlans.js` 对后续调用方提供：

- `validateReserveDemand(demand)` → `{valid, errors:{[demandId]:{[fieldPath]:message}}}`，不强制转换输入。
- `reserveDemandCost(demand)` → `{items, experience, money, unsupportedReasons}`，已包含人数倍乘。非法/不支持时三项费用为 null。
- `reservePlanRequirements({demands}, stock=null)` → 同上总需求和 `shortage:{items,experience}|null`。stock 为成功读取的物品数量映射；null 表示不可用，{} 表示已读取的空库存。money 保留总需求。

unsupportedReasons 为 `{demandId,field,code,message}[]`，区分 invalid_demand、unsupported_attribute、unconfirmed_breakthrough、inventory_unavailable 等。任一组费用未知时不输出部分确定总额。

## 人工验收（未由 Node/jsdom 证明）

使用自己的测试账号，在 390/768/1440px 打开养成规划→未来储备，检查无方案、新建空方案、单目标、多目标与长材料表；待选属性职业不应出现确定总额。保存并刷新确认恢复，名册与库存保持原状。检查管理方案、移除目标、删除、账号切换提示、键盘错误定位、页内返回及重进的草稿/焦点、窄屏单列、深色主题和数字完整可读。网络失败/冲突时确认草稿保留并能按上述两条路径恢复；旧多人、旧非零进度及拆分超限应分别检查。真实布局、触控、焦点遮挡和浏览器表现需人工验收。
