# 库存页面快捷维护

库存页以完整分类总览为主体。资源道具、密探养成材料、属性分组、心纸、折算信息、分类顺序和分类编辑保持原数据来源；首次使用也直接展示目录，不需要先展开「全部资源」。

「今日一览」顶部也可点「＋记一笔」，在首页直接打开同一套获得／使用／兑换弹窗，默认获得，按当前游戏账号记账。入口位于「自定义首页」左侧，手机复用原有操作行；不受首页模块显隐设置影响。账号或库存正在读取、读取失败及未选账号时不可录入，需先处理页面提示。保存后显示原有回执并刷新首页资料状态，关闭返回原入口；库存的完整列表、操作历史及原「记一笔」入口仍在库存页。未保存草稿切换账号需确认，保存中或结果尚未确认时不可切换账号，按原操作重试确认结果。

## 首页今日奖励

「今日一览」问候区下方直接展示同一套今日奖励：勾选实际领取的项目后点「记录所选」，选中不等于已记账。登录并选定有效账号后加载；账号或库存状态未就绪时禁用记录。保存后刷新首页库存状态，原每日来源键、北京时间 05:00 换日、已记录禁选、未知结果原样重试保持不变。保存中或结果未知时，切号和「记一笔」均锁定；切号前确认未保存的奖励选择。

桌面宽屏采用单行工具栏，平板换成标题与奖励两行；手机采用三条紧凑单行奖励、标题旁的「前往库存」和底部记录按钮。图标 26px，正常状态不放大面积说明。必要的奖励编辑仍在各项目旁；补记历史、领取规则和待领邮件留在库存页。此快捷区域与顶部「记一笔」一样，不受首页模块显隐设置影响。首页原养成、活动等模块保持顺序。

人工验收：在 390px 手机与 1440px 桌面打开首页，检查奖励区占用、整行勾选、编辑及记录反馈；在 320px/768px 检查长数量换行和无整页横向滚动。在测试账号记录后进入库存，确认同项显示已记录。浏览器实际布局、触控及真实接口写入尚未由 Agent 验证。

## 玩家操作

1. **今日奖励**：勾选实际领取的每日茱萸、密探日常、月卡奖励，点击「记录所选」。数量来自现有奖励配置，月卡档位读取当前账号的养成规划设置；各奖励旁的编辑按钮打开独立面板，可改本次数量；月卡档位按最新版本保存到养成规划，保留其他计划和体力设置。日期和库存处理仅在「补记历史」面板出现。默认以紧凑选项展示，完整说明由「领取规则」展开；读取失败和恢复提示直接显示。
2. **记一笔**：默认「获得」，选道具、填数量、保存。支持多道具与心纸混合录入；「其他奖励」切换背包道具/密探心纸时保留同一份已选清单与数量，保存按非空类型生成最多两条流水，在同一个请求中提交，可在操作历史分别查看或撤销。来源名称包含「派遣」时须按类型分别录入实际体力，混合清单会阻止保存并保留草稿。弹窗宽度充足时左侧选奖励、右侧编辑同一份已选清单，保存位于清单底部，网格与长清单分别滚动；弹窗内容宽度不足 920px 时改为紧凑上下排列。来源与历史时间默认收起，展开保留渠道、派遣/历练及补记字段；心纸在奖励类型中切换。搜索与筛选仅影响候选区，不清空已选数量。使用与兑换沿用现有符传命令及固定游戏价格，不新增任意道具负数导入协议，也不显示获得专用的历史快照说明。
3. **更新数量**：直接输入当前实际数量。分类「编辑」仅提交本分类的局部更新；顶部入口用于跨分类维护。完整首次盘点仍需明确确认，未修改的既有数量保留。
4. **邮件**：「录入／调整储备」是主要入口；白金币邮件与符传邮件的未领封数可用 − / 数量 / ＋ 每次调整 1 封，也可手输，再统一保存。减封数是校正储备，不是领取；取消不保存。首次明确保存 0 封会建立零储备基准；已有基准且未修改时不重复保存。「记录领取」是次要入口，默认领取数为 0，「全部填入」只填数，仍需确认。面板同时显示待领邮件减少封数、剩余储备和背包预计增加量。领取原子更新库存与储备；不确定结果原文重试。保存结果不明确时须重新读取核对，不盲目重发。已计入背包的邮件不要再次领取入账。
5. **操作历史**：通过工作区 Tab 打开原操作历史工作区，保留查询、删除、撤销和报告导入；统计报告继续可用。顶部重复的「最近记录」入口移除。

最近完整盘点时间位于库存工具栏，随当前账号和道具/心纸类型更新，并保留读取中、读取失败及尚无完整盘点状态。编辑时保留类型上下文、范围和修改项数；保存/取消位于紧凑状态栏，首次完整盘点确认不折叠。桌面道具卡以图标、名称和数量横向排列；手机沿用完整分类网格，奖励纵向排列，搜索与筛选自然换行。

心纸选择「背包顺序」时，按阶级从高到低（绝密 → 机密 → 隐密），同阶级按密探编号从新到旧排列；不依赖固定姓名名单，新增密探自动参与排序。「关注优先」仅在同阶级内生效，反向排序同时反转阶级与编号顺序。显式选择按属性/职业分组时，各分组内遵循该顺序。

## 数据边界

- 今日奖励的每日茱萸编辑面板可选择记录茱萸或已领取的白金币，默认分别为 1 和 50；两种形式共用每日来源键。选择保存在当前游戏子账号云端并跨设备同步，切换游戏时各自的设置保留；数量修改仅本次记录有效，不自动勾选领取。云端无设置时迁移旧浏览器设置；云端已有设置优先。加载失败需重试后才能选择每日茱萸；其他页面修改设置造成冲突时，重新读取并取消旧币种的选择，需核对后重新勾选。
- 「记一笔 → 兑换」可选择茱萸兑换白金币，每个茱萸扣除 1 个并增加 50 白金币；只记录已完成且尚未入账的操作。两种资源都须有库存基线，余额不足时不写入；删除和恢复重放整笔流水，不计入奖励获得量。
- 日常快捷区复用 `dailyRewardRecordId`，与原日常入口共用来源/游戏日标识。游戏日按北京时间 05:00 划分；已记录项目不可再次勾选。
- 补记已包含在库存中的日常奖励时，选择「已计入当前数量，只补记录」，填写真实领取时间；仍由 `validateDailyAnnotation` 和后端 full/listed 基准决定是否只保存历史。
- 任意来源手工记录与无来源日期的聚合邮件储备，不能自动推断是否为同一笔游戏奖励；界面要求玩家核对是否已记录，不按相同数量猜测或合并。
- 写入结果不明时保留原文档/操作编号，禁止换账号、修改内容或生成新编号绕过重试。账号/身份变化与卸载后忽略迟到响应。

茱萸记账偏好接口：`GET /v1/accounts/{accountId}/daily-zhuyu-preference` 读取 `account_id`、`game`、`preference`（未设置为 `null`）；`PUT` 发送 `{ "game": "代号鸢", "expected": null, "preference": "baijinbi" }`。`expected` 为读取的原值，冲突返回 409；服务端按登录用户、账号和游戏校验并原子更新。偏好值为 `zhuyu` 或 `baijinbi`。

## 邮件联合领取接口

站内 JWT：`POST /v1/inventory/mailbox-reserve/claim?account_id=<当前账号>`。

正文为 `{ "expected_version": 1, "operation_id": "稳定操作编号", "selection": { "white_coin_mail_counts": [1, 0], "fu_chuan_mail_count": 1 } }`。数组与当前版本邮件组顺序、长度一致，各数值为不超过储备的非负整数；省略 `selection` 兼容旧版全部领取。不接受用户身份、客户端奖励金额、价格或发生时间。响应沿用 `MailboxReserveResponse`，禁止缓存。

后端从账号已保存储备计算白金币和普通符传（每封 3 张），使用现有 Hub Mongo 事务完成储备版本 CAS 扣减、奖励导入、当前库存和库存 revision 更新；不增加集合、索引或迁移。服务端当前时间作为刚领取时间，仍尊重更晚库存基准。记录 ID 为 `yuanhub:mail:<储备版本>:<操作编号>`，有选择时附加规范化选择的 SHA-256 前 16 字节十六进制摘要，防止相同编号更改选择后误确认，重复请求只返回当前储备；删除后的领取只能从原历史记录显式恢复。单笔奖励不能超过现有库存协议上限。

此接口需要前后端同时更新；旧后端不具备联合领取能力。不得用两个互不原子的前端请求替代。

- 本次精修未运行浏览器、真实 API 或开发服务。非浏览器组件检查不能证明实际布局、视觉还原、触控、软键盘和真实账号端到端写入；以上由用户人工验收。

## 邮箱历史与资源报告

每次有效储备调整和领取保留服务端时间与版本，储备校正不记作当天奖励收入。抽卡资源报告支持实际白金币、含茱萸等价值、含邮箱、含茱萸与邮箱四种口径，覆盖摘要、月历、净变化和趋势；邮件白金币与普通符传分别计入对应资源，天机符传不变。

旧账号仅保留最后一次可证实的储备观测，更早历史无法还原；本期没有有效邮箱基准显示缺测，不按零计算。删除／恢复领取奖励仅修正背包记录，不退回／再次扣除邮件，日期详情标明关联领取已删除；封数有误请单独调整储备。

人工验收：390px／1440px 打开库存邮件，检查录入先于领取且容易找到；点 ±1、手输、取消和保存，确认减一不会增加背包。再领取部分邮件，检查双向结果与含邮箱总量不变；在统计页切换四种口径，补看 320px／768px 和手机横屏下按钮、数字及弹窗操作可达。代码和非浏览器测试不代表这些真机交互已验收。

## 手机库存总览精修

首次盘点提示采用紧凑布局；每日奖励保留勾选、编辑、补记历史与领取规则，用分隔线组织奖励行。零封邮件收成一行，通过「管理」进入原储备管理流程；有邮件或待确认领取时仍保留领取入口。持有状态使用轻量筛选，分类编辑靠右，折算摘要允许换行。

已登录且当前库存读取成功、无完整盘点且无任何库存记录时，背包数量与资源折算显示「—」，并说明数量未知；有库存记录时继续显示真实数量，包括 0。本次不改变盘点、奖励与邮件写入逻辑。

人工验收：在 320px / 390px 手机宽度检查盘点提示、奖励勾选、规则展开、零封邮件管理、筛选及分类编辑；桌面检查原有操作可达。真实布局与触控需手动确认。


## 邮件自动累计（2026-10-31）

在「待领邮件 → 管理」分别开启白金币/符传的自动累计。沿用奶油白管理弹窗，日期仅开启时展开；桌面并排、手机纵排。白金币保留原有任意单封奖励输入，多组时选择自动累计的奖励组，每种邮件每天只增加1封，不给所有组同时增加。

首次累计默认下一业务日，允许当前业务日，不追溯过去。北京时间05:00换日，截止日期包含当天。有效期内默认每天收到，不判断游戏登录；站点访问时补齐，不是游戏邮箱同步。开启当天计入时会额外增加1封，须核对是否已包含在手动封数中。到期或关闭保留已有邮件；重新开启不补停用期，到期后延长从当前业务日恢复、不补到期期间。配置最多到未来10年。

- 合计只含当前待领，未来奖励不提前入账。手动减少是校正，不增加背包；已校正日期不自动补回。
- 「今日奖励／日常快捷录入」月卡使用对应日的邮件单封奖励，记录领取同时扣除那封邮件。批量邮件领取先扣无日期的历史基数，再按日期扣已跟踪邮件；已经领取或校正移除的日期不会再次通过日常入口加库存。
- 以上去重只适用于启用累计后有日期凭据的邮件和站内标准日常来源键。任意手工来源、第三方任意记录ID和旧聚合储备无法自动判断为同一奖励，仍需人工核对。
- 删除／恢复领取流水继续只影响背包，不返还／再次扣除邮件；如需修正待领封数，请单独调整储备。
- 自动累计历史归属各应发业务日，标注为估算；手动调整与领取扣减保存操作时的储备观测，不重写过去的邮箱快照。

接口增加 `POST /v1/inventory/mailbox-reserve/sync?account_id=...`（按日幂等补算，并返回当前储备与统计标记）；原 GET 保持只读。`GET /daily-status?account_id=...&day=YYYY-MM-DD` 返回 `monthly_claimed`、`monthly_coins`，供日常录入核对。PUT/响应增加可空 `white_coin_schedule` 和 `fu_chuan_schedule`；请求含 `start_date`、`end_date`，白金币另含 `coins_per_mail`。响应另有服务端 `through_date`，客户端不得提交进度。省略配置字段保留现有配置，传null关闭。

部署顺序：先后端再前端；新前端依赖 sync/daily-status，缺失时明确失败，不静默跳过去重。回退前端时应先关闭累计或保留新接口客户端，不能用旧GET代替补算。

人工验收：390px、768px、1440px打开管理，分别切换两种开关、输入日期、取消/保存、重开核对；检查零封开启、多个金额分组、过期配置及日期换行。开启当前日后核对封数只增加一次；在日常录入领取后重开邮件核对扣减，在邮件中领取后确认日常入口已记录。真实布局、触控、软键盘与浏览器表现尚未由Agent验证。
