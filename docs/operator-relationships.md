# 信赖与传闻

入口：密探名册 → 信赖与传闻。首版由用户录入游戏内的当前信赖值和已解锁传闻数量，仅展示已拥有密探；未记录与明确填写 `0` 分开处理。已接入信赖奖励；传闻奖励资料仍待补，不纳入奖励估算。

## 使用与计算

页面采用图鉴头像网格，左下角显示信赖值、明确的 `0` 或“未记录”，右下角铅笔打开居中编辑弹窗。头像、品质边框、属性和收藏沿用名册数据；未记录信赖不表示未拥有。

“信赖节点”按当前密探规则分段显示，每项包含信赖值和奖励，单选当前已达到的最高节点；打开时定位现有进度所在区间。选择只修改草稿，保存后更新头像与汇总。“未记录”清除信赖，“0 · 尚未达首档”明确记录为零。历史非节点值（例如 1350）原样保留，只有主动选择才替换；节点资料缺失时保留数值录入。

“传闻数量”继续录入整数，留空清除该项记录。切换弹窗内项目保留草稿，保存仅提交发生变化的字段，传闻变化不自动增加信赖。失败保留草稿；版本冲突可点击“重新读取并核对”，放弃草稿前仍需确认。关闭按钮、取消、Esc 和遮罩关闭共用未保存保护；保存中阻止关闭与重复提交。桌面弹窗居中，手机适配可用视口，正文独立滚动。

两款游戏共用信赖规则，按各密探实际上限显示 15 档（2000）或 40 档（10000），弹窗底部预览草稿的下一奖励档位；未解锁收益只包含阈值高于当前进度的档位。已达标但尚未领取的奖励不在统计内。未记录或规则不完整的领域不计入收益，页面按共享主体展示信赖规则覆盖数量。显式共享的信赖只汇总一次，传闻各自计算；搜索与筛选不影响全账号汇总。

历史记录若仅电影形态存有信赖值，会共同回显；多份相同值只统计一次。若同组旧值不同，显示“待核对”和各旧值，暂停该组估算。编辑时勾选“已核对”后按所选值统一；勾选后选择“未记录”将清除整组信赖。只修改传闻不会改动旧信赖。

## 独立备份

“更多 · 信赖与传闻备份”可导出当前账号全部已记录数据，包含列表之外的历史记录。格式 `yuanhub-relationships`，版本 1，与练度 JSON v5 分开；不包含预测奖励。恢复必须同游戏、密探 ID 有效，最多 1 MiB / 1000 位。

恢复先预览目标账号、修改数量、冲突数量及旧值到新值。默认保留当前已记录值；勾选覆盖才采用备份冲突值。恢复使用绝对值，不累加，不删除备份之外的字段。共享信赖冲突或超上限时整批拒绝；当前账号存在共享旧值冲突时，先在进度编辑中核对，不能通过覆盖恢复绕过；确认恢复仍接受服务器版本校验。

## 人工验收（尚未执行）

1. 在桌面和手机打开新页签：检查长名称、窄屏折行、键盘页签与焦点；建议宽度 320/390/430/768/1024/1440px。
2. 点击铅笔，选择节点保存，检查头像角标与重开回显；再分别选择 `0` 和“未记录”，确认两种状态不同。检查 `信赖 10000` 不覆盖铅笔。
3. 输入未保存内容后切页签、切账号、离开页面：确认保留/放弃提示；保存中不得误写到另一账号。
4. 导出备份，修改一项值后预览恢复：默认保留当前值，勾选覆盖后展示旧值→新值，确认后再读取核对。
5. 检查 15 层密探在 2000 达到上限，40 层密探仍有后续奖励；原形态与电影形态共用值且奖励只计一次，冲突旧值须人工核对；传闻资料缺失不能显示为剩余奖励零。

开发期仅执行 Node、Vitest/jsdom 和静态编译检查；这些不等同于真实浏览器、视觉或触控验收。
