# 体力日程的保存与回顾

## 月卡与每日固定来源

入口：养成规划 → 调整设置 → 常规日程规划 → 月卡权益与每日固定来源。配置属于当前子账号，切换培养清单仍共享；新建/未固定日程使用该配置生成推荐。已保存清单需先预览，再点击「应用到未来日程」，不会因配置同步而静默改写。

- 未配置不增加月卡。萤火/星光/月华/昭阳建议每日奖励30/35/50/60，商店免费20独立开关与数量；昭阳全选为额外80，仅商店为20。档位与有效日期独立，生效日及到期日均包含当天，留空表示不限制该端；无有效月卡不预测两项权益。自定义可编辑数值。
- 固定来源可从已有来源创建，或新增自定义名称/数量；同ID替换推荐来源，关闭该模板会抑制其对应默认来源（例如不领进膳）。删除模板则恢复原推荐规则。购买体力继续使用购买次数设置，费用口径不变；一次性体力储备不作为循环来源。
- 配置先保存至子账号云端，再预览应用于当前清单。预览显示今天起90天范围内的起止日期与受影响数量，覆盖也限此范围，周期外手工日期保留；开始日限今天起90天内，过去完整保留，开始日前已保存记录保持原样；默认保留整个手工日期。显式勾选替换手工来源时只替换规则管理的获取来源，保留其他一次性获取和手工支出，仍可按原流程处理超支或重新计算。
- 单日手工安排优先于固定模板，固定模板优先于原推荐。重复应用同日规则替换原规则，不叠加。规则按生效日期存于日程偏好的 `sourcePeriods`，不是将模板逐日复制；未来生成、库存更新重算、普通推荐和最优求解使用相同规则。单日修改不会改变模板或其他日期。
- 同一账号下已有其他清单仍保留各自已确认日程；在对应清单应用同一子账号配置即可更新。账号配置保存与清单应用是两次独立保存，失败时按云端错误提示恢复/重试；不得把本机缓存当更新依据。

所有体力获取均为**预测预计领取**，不会入真实库存，也不代表邮箱奖励已经领取。商店20需要主动领取；每周兑换300不摊入每日。

### 预设说明

月卡体力、商店免费体力与白金币档位采用用户提供的可编辑参考值，请以当前游戏实际权益为准。两个游戏各自持有预设表，配置按对应游戏子账号隔离，不宣称预设已完成官方核验。

### 最小验证与手动验收

纯逻辑：`node --test test/dailyStaminaSources.test.js test/fixedPlannerSchedule.test.js test/exactPlannerComparison.test.js test/operatorPlannerCloud.test.js`。

组件：`npm run test:behavior -- behavior/plannerDailySources.spec.js behavior/operatorGrowthOwnership.spec.js`（Node/jsdom，无真实浏览器）。

人工：390px手机、768px中间态、1440px桌面依次选择昭阳并保存，预览今天/未来应用，核对每日额外80；关闭每日奖励核对20；到期日之后核对0。创建活动固定来源、重复应用、修改一天，检查过去和其他手工日期不变。刷新、切清单、切账号，再从另一设备读取；确认云端冲突提示可恢复。320px及手机横屏补查输入/按钮可达性、无横向溢出。浏览器、软键盘与跨设备真实运行由用户验收。

体力规划以云端日程为权威来源，并以子账号和培养计划分别隔离。浏览器仅缓存最近一次成功的云端日程，用于再次进入时快速展示：

`yuanhub:planner-cloud-cache:v1:<accountId>:<planId>`

缓存展示后仍会请求云端并用云端结果校正，不能作为离线写入依据；规划规则版本变化时缓存自动失效。尚未自定义日程时，推荐随当前库存和日期生成。用户首次修改任意一天的获取、支出或产出配置时，向云端保存整个日程：库存与材料需求起点、培养目标、推荐配置、每日安排、结算结果及材料进度。原有本机 `cultivation-stamina-planner:v1` 数据仅用于首次云端迁移，旧版数据仍可读取。

- 刷新库存、真实日期变化或重新打开页面都不会自动改写已保存日程。清除某天的自定义安排后，完整日程仍保持固定。
- 已过日期以历史图标和「已过」标注，可查看当时保存的安排与预测；该标记不表示游戏内已完成。
- 计划预测与当前规划相关材料库存不同时显示差异，并提供「按当前库存更新」。比较以今天开始前的累计预测产出为基准；同一培养目标下的养成消耗按材料需求减少量扣除。
- 显式更新从今天的当前库存重新计算，保留过去日期的完整结算，以及今天和未来的自定义安排。清单或培养目标变化也会提示更新。
- 修改每日体力获取或支出时，保存修改并按原有安排更新账本与材料预测，不自动重新推荐其他日期。获取、支出的增减、添加、删除，以及自定义名称、单次体力和产出编辑，均可显示「重新计算当日及后续日程」提示。
- 用户点击后，使用所选日期的预测库存起点与全部体力来源，重新推荐该日全部历练和 6-24；保留派遣、自定义支出和未来手工安排，更新后续自动日程。此前日期逐字保留，重算未来日期不会把今天移入历史。
- 提示按日期保存在完整快照的 `context.planBaselines` 中（API 字段 `context.plan_baselines`），切换日期、刷新和云端恢复后仍可继续操作。恢复为编辑前的内容时提示消失；重算某天仅清除该日提示。旧快照没有此字段时按无待重算编辑处理。
- 编辑暂时造成体力超支时，后续已保存安排仍保留，预测产出暂停。可以修正账本或点击重算重新分配历练次数；若保留的派遣、自定义支出本身超出预算，则提示错误并保留原编辑。现有安排不足以备齐材料时显示「待重新计算」，不继续沿用旧完成天数。
- 修改推荐偏好时仍以计划保存的预测起点重算今天及之后，过去日期不变。
- 旧版过去的手工日期仅能恢复原安排，不能还原未记录的历史库存，界面会说明这一限制。

日期导航使用固定宽度的日期按钮，状态标记不改变布局。支持鼠标拖动、原生触屏滑动、前后一天按钮、方向键、Home / End 和回到今天；仅当选中日期被遮挡时，在日期栏内最小幅度滚动。不会将整个页面或已可见日期强制居中。

清除浏览器站点数据会移除快速展示缓存和未提交草稿，但不会删除已经保存到云端的日程。功能入口继续遵守现有 `operatorGrowthTracking` 构建时开关。

编辑日程现提供按需运行的全局最优求解器，先预览再采用。目标、证明范围、超时行为及资源说明见 [体力日程全局最优计算](operator-exact-planner.md)。

首页「我的养成计划」现读取当前清单已保存日程中今天的历练，可手动加入「今日待办」。它不运行求解器，不自动采用尚未保存的推荐；勾选仅保存完成次数，不改变库存、体力日程或 Maa 执行。日程变化后由用户明确更新待办，保留此前完成次数。详情、异常状态与验收见 [首页今日历练与待办](today-training-todos.md)。

手机端（≤640px）采用紧凑概览：标题旁提供次要的「刷新库存」操作，清单名称下先展示预计耗时、等级与修为进度、心纸及日体力结余，再显示「调整设置 / 查看体力日程」。测试提示常驻并提供反馈入口。概览继续区分当前材料已备齐、按已保存计划应已备齐和旧方案待更新，不将等级与修为进度解释为全部培养目标完成。

## 天数口径与已过记录

概览显示「从今天起预计还需（含今天）」，使用计算基准日与完成天数确定备齐日期，再扣除已过日期；不使用历史记录数量或最后一个手工日推算完成时间。已到预测完成日之后显示「按计划应已备齐」，不冒充真实库存确认。

日期导航显示第几条日程记录、共多少条及已过数量，记录数量不是剩余天数。可通过「收起已过日程」隐藏过去日期并随时展开，本机记住显示偏好；云端历史、当日与未来安排保持原样。收起后若没有未来记录，提供今天的查看入口。真正删除历史尚不属于此操作；现有云端校验要求已过日期保持不变。

目标天数模式明确从今天起算，额外体力仅用于今天；方案对比也明确标注从今天起（含今天）。

## 重设日程起始日期

「重设日程起始日期」显示影响说明，确认后从今天开始新阶段：使用当前库存与当前清单，清除今天及未来手工安排，按当前偏好重新推荐。旧阶段不再出现在日期栏、周期外固定日入口或记录数量中。当前阶段内的已过日期仍可收起或展开。

展示起点保存在 `schedule.context.displayStartDate`（云端 `display_start_date`），按账号和清单随快照恢复；后续库存更新、偏好调整、重算不会恢复旧阶段。底层不可变历史仍保留以兼容云端，重设不把旧预测产出充当真实库存。

清单或培养目标与保存快照不一致时，概览和方案对比显示「旧方案待更新」，不展示旧完成天数或旧最优结论；普通日程全局求解暂不可用，更新或重设后恢复。目标天数独立试算仍以当前清单计算。

日程编辑入口以图标按钮置于「体力日程」标题旁；重设起始日期、收起或展开已过日程位于日期导航操作行。编辑图标直接进入编辑界面；重设和收起／展开的说明集中在复用现有视觉样式的原生确认弹窗中，支持取消、Esc、键盘焦点约束和关闭后焦点返回。
