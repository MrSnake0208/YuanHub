# BOX 图片分享

在「我的密探 → 分享 BOX → 图片分享」生成图片，不需要开启链接分享。原有公开范围、链接复制和撤销操作在「链接分享」中保留。

- 默认导出养成总览的当前筛选结果与顺序，可切换为全部已拥有；只使用已保存的养成和配装，未保存的卡片草稿不会进入图片。
- 图片固定浅色、1440px、每行最多五张。导出网格显式覆盖总览的自动列数规则，避免超过五列。`OperatorBoxImageSheet.vue` 使用总览相同的 V1/V2/V3 桌面样式源和 `ShareCardStats`，沿用卡头、左右核心养成/攻血面板及双命盘的 DOM 分区；不再独立定义立绘位置、比例、渐变、姓名、卡片边框或命盘配色。状态色从总览原样提取至共享 `operator-ledger-card.reading.css`。
- 保留立绘、竖排姓名、属性/职业、只读养成状态、等级、修为、化极星数/节点/觉醒、攻击/生命、两套命盘全部已配词条及品质色。导出不再请求历程接口。未知值保持「—」或「化极待确认」，不虚构上限。奇闻数值和历程均不展示，也不保留占位。
- 化极沿用 `operatorHuaji()` / `operatorHuajiLabel()`，兼容历史 `starLevel/star_level`，不把历史字段当作额外的独立星级。攻血继续使用原有配装及后端面板结果，不显示星石槽及奇闻细项，但保留装备和奇闻对攻血的计算影响；未保存的编辑草稿不进入图片。
- 不包含账号名、UID、备忘、自定义标签、养成目标、私人命盘名称、星石装备槽、特别关注、置顶及编辑/保存/取消/提升/命盘添加等操作。只读文本替换输入框，移除虚线输入外观和操作列占位；养成总览的原有控件和数据流保留。
- `html2canvas` 的兼容处理只发生在导出副本：按浏览器计算结果转换现代颜色语法，按实际排好的字形坐标绘制竖排文字。手机生成也在 1440px 副本内测量与截取，避免手机视口改变导出卡片布局。此适配的真实浏览器表现仍需人工确认。
- 默认每张最多 30 位（五列六行），按完整卡片分图。105 位生成 30＋30＋30＋15 四张；也可生成完整长图。每张标明总人数、页数、序号范围与生成时间。
- 生成后预览并逐张保存 PNG；手机可长按预览图保存。逐张保存避免浏览器连续下载限制。生成失败保留已完成的分图，可重新生成；立绘/字体准备超时会报错，不输出缺图快照。

图片在本机浏览器生成，不上传图片、不写入账号或公开权限。关闭弹窗、切换分享方式、切换账号/游戏及离开页面后释放生成结果；异步旧结果不会出现在新账号。分享出去的图片不会随云端更新或撤销，发送前请核对预览。

完整长图超过 16,000,000 像素或高度超过 16,384 像素时提示使用分段；设备内存不足也可能导致生成失败。分段逐张渲染，及时释放 canvas 内存。聊天软件压缩清晰度、手机保存及真实视觉布局由用户人工验收。

静态对照已使用用户截图中的徐庶字段：等级 100、修为 17、5 星、攻击 7706、生命 37195、两套各两个已配命盘词条。未配置的第三词条不补造。`behavior/operatorBoxImageSheet.spec.js` 对照总览与导出分区的结构层级、共用样式来源，并检查同一密探的展示值和操作区域删除；这些静态证据不能证明真实像素一致。

人工验收：先导出截图中的徐庶，与总览对照立绘、竖排身份、左右面板、星数/节点和两套命盘，并确认奇闻、历程和对应占位已移除、每行不超过五张；确认未增加编辑步骤。再检查一位长姓名的密探，并在桌面及手机各保存一次分段图和长图。总览中的关注、置顶、星石、备忘和完整编辑应仍可使用。
