# YuanStar 私有源码：星石突破字段接入交接

后端与 YuanHub 宿主已支持实际突破次数。用户指定由私有源码拥有人反向同步，本次未修改 `public/yuanstar-embed` 产物。当前嵌入版会在业务快照规范化时丢掉未知字段，因此不能宣称其本地备份、Undo、JSON 往返已完成支持。

## 需要同步的契约

权威说明见 [Backend 星石突破契约](../../BackEndV3-Share/docs/star-breakthrough-state.md)。宿主业务快照使用可选 `breakthroughStage: number | null`；HTTP 使用 `breakthrough_stage`。数字是实际完成次数，0是确认未突破，null是未知，缺字段是旧客户端未声明。不可把它绑定到一次养成预览的临时开关，或按 `floor(level/10)` 一律推断。

| 品质 | 满级 / 次数上限 | 例子 |
| --- | --- | --- |
| 白 | 30 / 2 | 满级不再突破 |
| 绿 | 40 / 3 | 满级不再突破 |
| 蓝 | 50 / 4 | 满级不再突破 |
| 紫、橙 | 60 / 5 | 20级可1或2次，21级只能2次 |

## 私有源码改动清单

1. 库存条目类型、规范化和本地 IndexedDB 快照保留可选字段；缺失不转成0，显式null不删除。同ID/名称/等级的云端更新也必须接收突破变化。
2. `getCloudBusinessSnapshot` / `applyCloudBusinessSnapshot`、Session、Undo/Redo、恢复点保留字段；宿主 `starCloudCoordinator.js` 已双向透传，不需要另一套云存储。
3. JSON 导入/导出及验证器支持往返。旧文档继续读；若旧格式严格禁止额外字段，则显式演进格式版本，并提示旧版本导出会丢失突破事实。宿主 `starArchiveExport.js` 只改导出副本的账号名称，无法补回源码未导出的字段。
4. 完成养成后采用后端回执 `state.inventory[].breakthrough_stage`。起点已知且与 `start_already_broken` 冲突会409 `star_breakthrough_changed`，应重新读取核对；未知节点可让用户声明。重建/OCR不得把旧背包事实按名称猜给新实例。
5. 在私有源码加存储/云同步/Undo/JSON往返验证，再沿用[正式产物同步流程](./yuanstar-embed-sync.md) build 与同步，禁止手工修改压缩产物。源码提交/同步发布权限由维护者安排。

## 已有宿主行为与限制

密探编辑页在已装备星石下提供突破补录。选择后立即 CAS 保存服务器档案，成功后重新计算；它独立于密探的保存/取消。普通旧客户端PATCH只要实例身份和等级未变，后端会保留原突破；显式null会清除；旧JSON替换/rebuild没有节点事实时保持未知，不继承已被替换的旧背包。

当前旧嵌入版仍不能导出这些新事实。旧客户端丢失PATCH响应且无法证明突破一致时，应重新载入核对，不自动跨版本覆盖。迁移顺序为后端 → 宿主/私有源码 → 正式嵌入构建；回退须保留识别新字段的后端。

最小人工验收：在密探配装页把橙色20级实例从未知设为“已突破”，切走再返回应保留；完成私有源码同步后，再验证星石页面本地编辑、Undo、JSON导出/导入和跨设备读取仍为2次。真实浏览器和私有源码往返尚未由本轮执行。
