# 成就档案：使用范围与人工验收

页面为 `/achievement`，沿用现有导航、网站登录和全站游戏账号；不需要羁绊助手。开发与生产构建均开启，但页面、导航和后端接口要求 `archive:access`，暂仅平台管理员与超级管理员拥有；普通/内测用户及历史 `ARCHIVE_USER` 不放行。初始种子代号鸢0条、如鸢0条，实际目录由 MongoDB 已发布快照决定，管理员可在线维护。页面如实显示资料空缺，测试样例不会进入目录；有条目的真实使用验收需要已发布资料，组件测试不能替代真实资料验收。

## 功能与记录口径

主页面只显示“未完成 / 已完成”。历史 `completed` 对应已完成，`incomplete`、`pending` 及无记录均显示未完成，含义是“尚未标记完成”；仅浏览不会写回或批量改写历史数据。用户点击状态按钮时切换为另一状态；从已完成切回未完成才提交明确的 `incomplete`。顶部仅有已收录成就、已完成、未完成、我的关注四项统计，按当前游戏有效目录计算；未完成 = 已收录 − 已完成，关注独立于完成状态，移出目录的历史记录不参与统计。

每行单个状态按钮和星标直接保存；已完成为绿色勾选，未完成为中性空心圆，点击切换。档案尚未读取时显示“未读取”并禁用。保存成功才更新，保存中禁用重复提交；失败保持原值并在该行提示错误。状态仅提交状态，关注仅提交关注，不清空或填满数值进度、备注。未完成筛选中标记完成后，行内提示成功并提供撤销，停留6秒后移出结果；顶部统计立即按保存结果更新，筛选命中数在这6秒内包含待移出行。全页成功提示继续提供上一次操作撤销，恢复原始状态字段（包括历史 pending）及已知完成日期；不强制跳回页头。

列表最多50条，搜索名称/完整中文条件，保留游戏原生分类、结构化奖励、两态、关注和隐藏属性组合筛选。搜索、状态、游戏分类和关注在主筛选栏；奖励、进度来源、隐藏属性统一放在可展开的“更多筛选”，手机在原位置展开，启用条件时入口提示“已启用”。清除筛选与命中数同排，批量记录位于右侧。奖励输入提供奖励字典名称建议，也可输入关键词；目录为空时不生成奖励类别。先按分类顺序、组内sort、系统ID排序再分页；分类按目录顺序分组，分类头部显示整个分类的已完成数 / 有效目录总数，不随筛选改变统计口径。页面沿用常规模块的1180px容器上限，左右边距为桌面（≥1081px）48px、平板（768–1080px）32px、手机（≤767px）16px；列表占满该容器，不额外扩宽页面。桌面采用统一暖白列表与细分隔线，表头为成就、奖励、完成状态、操作；普通行以约72px为布局基准，长条件自然增高。有效数值/羁绊进度放在成就条件下方；无目标、无历史进度时不显示空占位，历史人工进度仍保留提示。平板按可用容器重排，手机将信息和直接操作分层，不依赖横向滚动。页头统计、搜索和列表共用同一内容边距。

成就名称为普通标题，不打开详情。页面没有右侧详情区、详情弹窗、抽屉或独立详情页。完成条件直接显示；条目不再包含攻略、剧透、来源、别名、关联密探、章节、核验日期或核验状态。旧目录非空资料会在后台列出兼容问题并阻止目录写入，不能静默丢弃。玩家个人备注仍独立保留。

只有明确的正整数target显示数值编辑入口。个人进度未知时显示“进度未记录”，不伪造零或进度条；填写后显示数值 / 目标及细进度条。点击进度在当前行展开输入，只允许非负安全整数与超目标值，拒绝小数，留空保存为未知。保存、取消均在行内，不使用 prompt，达标不会自动完成。

行末“备注”图标与文字按钮展开当前行的个人备注，可查看、编辑、保存或取消；无备注且未展开时不占额外高度。既有可选实际完成日期保留在已完成条目的备注编辑区。进度和备注分别提交变更字段，保存一个不丢另一个草稿；完成日期草稿在两态切换后继续保留，回到已完成可保存，也可明确取消。取消脏草稿需确认，离开页面、刷新、切账号或进入导入前沿用未保存确认。筛选隐藏、分页、断点切换或目录读取失败不清空草稿；顶部“返回编辑”可回到仍在目录中的草稿所在页。账号上下文真正变化时清除旧草稿；迟到响应不能覆盖新账号。

后端保存后，在另一个设备进入页面、刷新或无脏草稿时重新激活读取，不实时推送、不离线假保存。revision 冲突重新读取并提示核对，脏草稿保留，可重试保存。两端复用同一控制器、权限和 API，CSS 分别持有布局。

“更多 → 导入与导出”继续备份当前账号全部原始记录，包括历史三态和移出目录的记录，不受筛选影响。格式仍为 YuanHub 成就 JSON v1，5000条/16MiB。选择文件自动预览，默认保留冲突，采用文件也不以空备注擦除已有备注。未知 ID 须明确跳过；非法项整批拒绝。预览后变更账号/文件/策略/版本需重新核对，预览10分钟失效或后端重启后重做。文件源账号仅提示，不能取得其它账号权限。

后台维护入口仍为 `/achievement/admin`，同时需要 `archive:access` 和 `achievement_catalog:write`。见 [成就目录管理](achievement-catalog-admin.md) 及后端 `BackEndV3-Share/docs/achievement-api.md`。本次同步改造后端契约、目录和备份容量；访问范围按上述权限限制。

## 电脑和手机人工验收

复用正在运行的开发服务打开 `/achievement`。非浏览器组件检查不能证明真实布局、触控或软键盘表现；本轮没有启动、重启服务或执行浏览器自动化。

1. 桌面1440px：检查四项紧凑统计与搜索、全宽分组列表左右对齐；没有详情栏，标题不能打开详情。组合奖励、分类、状态和关注筛选，检查长条件自然换行。
2. 有真实条目时：在未完成筛选标记完成，统计更新、该行提示成功，可在6秒内撤销；等待移出后仍可用页头撤销。修改状态及关注后，确认个人进度和备注保持原值。
3. 有真实量化条目时：行内编辑进度与备注，分别保存、取消；未填进度不显示零。未保存备注时筛选隐藏/翻页，再“返回编辑”；离开/切账号应提醒，切换账号后不显示前一账号草稿。断网保存保留草稿，冲突提示核对最新内容。
4. 手机390px并补看320px，平板768px：检查筛选换行，状态、星标、备注及进度入口可达，无整页横滚或按钮重叠；展开输入后软键盘不妨碍滚动到保存/取消。缩放布局不应重建草稿或打开详情。
5. 少量明确选中后批量标记；导出并预览同一JSON，核对目标账号和历史三态兼容，预览不写入。真实跨设备保存、导入冲突和权限由用户独立验收。

账号删除会清除成就记录；有实质记录禁止修改游戏。涉及删除的人工验收仅使用用户自行准备的可丢弃账号。

## 奖励与羁绊边界

奖励显示“物品 × 数量”，null显示“奖励资料未补齐”，空数组显示“无奖励”，不把缺资料当零。旧奖励通过目录级legacy_rewards回显为“旧文本，未结构化”，不参与未来计算。target=null无数值入口；没有目标但仍有历史人工进度时原样显示并提示待核对。已有小数进度可读取和导出，改备注/状态保持小数；新写入及含小数备份的导入明确拒绝，不自动取整。

`linked_metric=yuan_bond_variants` 只是目录配置，当前显示“羁绊联动尚未接入；当前仅记录人工进度”；不显示虚构的0、不自动完成。后续羁绊只读指标与人工进度分别展示和备份，达标仍由用户确认。

本阶段没有导入或发布真实资料，没有连接真实数据库、自动启动/重启/停止开发服务或运行浏览器。桌面/手机人工验收须用用户安排的测试数据与已运行服务；实际视觉、触控和运行时联调未由Agent验收。

## 补充资料与我的投稿（K05）

在成就档案页选择“补充资料”，选择游戏、已发布分类，填写候选新成就、来源链接和可选补充说明后提交。不需要选择个人子账号，不会更改任何个人成就记录。奖励不清楚时保留“资料未补齐”并说明待核，不能填0表示未知。不支持通过投稿覆盖已有系统ID；更正现有成就可在说明中指出，由管理员编辑。

“我的投稿”按状态分页查看私人资料与审核结果。已采纳显示“已采纳到草稿，待管理员发布”，并区分当前已发布/尚未发布/发布状态未知；拒绝可查看原因，原单不退回编辑。来源与备注不向其他玩家公开。提交结果不确定时输入锁定，使用“重试上次提交”原样重试，避免重复投稿；明确的校验错误可修正后再交。离开页面前会提示未提交内容，页面刷新后不会保留未提交输入。

人工检查：在电脑和手机从成就页提交候选、查看本人详情、检查失败后输入保留与重试；换登录身份不应显示上一人的投稿。布局与真实触控尚需手动验收，jsdom测试不能代替。
