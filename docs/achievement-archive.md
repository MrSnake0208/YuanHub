# 成就档案：使用范围与人工验收

页面为 `/achievement`，沿用现有导航、网站登录和全站游戏账号；不需要羁绊助手。开发与生产构建均开启，但页面、导航和后端接口要求 `archive:access`，暂仅平台管理员与超级管理员拥有；普通/内测用户及历史 `ARCHIVE_USER` 不放行。初始种子代号鸢0条、如鸢0条，实际目录由 MongoDB 已发布快照决定，管理员可在线维护。页面如实显示资料空缺，测试样例不会进入目录；有条目的真实使用验收需要已发布资料，组件测试不能替代真实资料验收。

## 功能与记录口径

页头不再提供“帮助”入口及状态、同步、导出范围说明卡片；相关记录规则见下文。

主页面只显示“未完成 / 已完成”。历史 `completed` 对应已完成，`incomplete`、`pending` 及无记录均显示未完成，含义是“尚未标记完成”；仅浏览不会写回或批量改写历史数据。用户点击状态按钮时切换为另一状态；从已完成切回未完成才提交明确的 `incomplete`。顶部仅有已收录成就、已完成、未完成、我的关注四项统计，按当前游戏有效目录计算；未完成 = 已收录 − 已完成，关注独立于完成状态，移出目录的历史记录不参与统计。

每行单个状态按钮和星标直接保存；已完成为绿色勾选，未完成为中性空心圆，点击切换。档案尚未读取时显示“未读取”并禁用。保存成功才更新，保存中在原状态按钮内显示“保存中…”并禁用重复提交，不增加一行提示；失败保持原值并在该行提示错误。状态仅提交状态，关注仅提交关注，不清空或填满数值进度、备注。成功反馈统一位于列表上方的提示区，无保存结果或撤销入口时隐藏且不占位，使统计卡片与筛选栏保持紧凑；保存后吸附于页面顶部，只有一个撤销入口；不在普通行内插入成功横幅。页面不再展示游戏与资料范围说明，列表底部也不再展示“目录版本与资料范围”折叠说明。撤销入口随原有撤销状态保留，不随6秒移出计时消失；恢复原始状态字段（包括历史 pending）及已知完成日期，不强制跳回页头。未完成筛选中标记完成后，行内仅说明“即将从未完成列表移出”，停留6秒后移出结果；顶部统计立即按保存结果更新，筛选命中数在这6秒内包含待移出行。批量记录沿用原确认及保存语义，统一反馈本次保存条目数，不为各行增加成功提示或撤销按钮。保存成功后清空选择并退出批量模式，保留筛选、延迟移出及统一撤销；网络失败或 revision 冲突时保留批量模式和仍在本页的选择，核对后可重试。

列表最多50条，搜索名称/完整中文条件，保留游戏原生分类、结构化奖励、两态、关注和隐藏属性组合筛选。搜索位于工具区首行，有有效筛选时在同区显示“清除筛选”，手机搜索保持独占整行。五组筛选共用一块轻量暖白底板；桌面首排为状态与分类，第二排为奖励与关联进度，末排为属性与靠右的批量入口，空间不足自然换行；手机五组直接展示并换行，批量入口位于底板下方的结果数量旁。原“来源”仅更名为“关联进度”，仍使用原 linked_metric 筛选语义。状态、分类、奖励和关联进度点击选项立即筛选，每组有“全部”可单独恢复；关注与隐藏成就可独立勾选。奖励筛选只提供当前已发布目录 reward_filters 配置的名称，以及“全部”，不再提供其它奖励选项或奖励关键词输入；只收敛筛选入口，成就行仍完整展示实际奖励。各组可组合，选项按可用宽度换行，手机无需展开弹层或下拉框；筛选只读取目录与个人记录，不写回档案。无有效条件时显示“全部成就 · 共 N 项”，不显示清除入口；筛选生效后显示“找到 N 项”及工具区的“清除筛选”，纯空白搜索不算有效条件。结果数量紧接筛选底板下方，进入批量模式才展开选择与操作栏。无配置时仅展示“全部”奖励筛选项，结果为空。先按分类顺序、组内sort、系统ID排序再分页；分类按目录顺序分组，分类头部显示“本类已完成 X / 共 Y 项”，采用整个分类的已完成数 / 有效目录总数，不随筛选改变统计口径。页面沿用常规模块的1180px容器上限，左右边距为桌面（≥1081px）48px、平板（768–1080px）32px、手机（≤767px）16px；列表占满该容器，不额外扩宽页面。四项统计采用统一暖白底板、浅圆底语义图标与淡色水印，标签和数字分层，桌面四列、手机两列，统计口径不变。分类标题外不再叠加边框和底板，列表保留单层边界与细分隔线；桌面表头为成就、奖励、完成状态、操作，普通行以约68px为布局基准，长条件自然增高。有效数值/羁绊进度在桌面仍放于成就条件下方，手机在奖励后、直接操作前展示；无目标、无历史进度时不显示空占位，历史人工进度仍保留提示。平板按可用容器重排，手机依次展示名称与条件、奖励与适用进度、完成状态与关注/备注操作，不依赖横向滚动。页头统计、搜索和列表共用同一内容边距。

成就名称为普通标题，不打开详情。页面没有右侧详情区、详情弹窗、抽屉或独立详情页。完成条件直接显示；条目不再包含攻略、剧透、来源、别名、关联密探、章节、核验日期或核验状态。旧目录非空资料会在后台列出兼容问题并阻止目录写入，不能静默丢弃。玩家个人备注仍独立保留。

只有明确的正整数target显示数值编辑入口。个人进度未知时显示“进度未记录”，不伪造零或进度条；填写后显示数值 / 目标及细进度条。点击进度在当前行展开输入，只允许非负安全整数与超目标值，拒绝小数，留空保存为未知。保存、取消均在行内，不使用 prompt，达标不会自动完成。

行末“备注”图标与文字按钮展开当前行的个人备注，可查看、编辑、保存或取消；无备注且未展开时不占额外高度。既有可选实际完成日期保留在已完成条目的备注编辑区。进度和备注分别提交变更字段，保存一个不丢另一个草稿；完成日期草稿在两态切换后继续保留，回到已完成可保存，也可明确取消。取消脏草稿需确认，离开页面、刷新、切账号或进入导入前沿用未保存确认。筛选隐藏、分页、断点切换或目录读取失败不清空草稿；顶部“返回编辑”可回到仍在目录中的草稿所在页。账号上下文真正变化时清除旧草稿；迟到响应不能覆盖新账号。

后端保存后，在另一个设备进入页面、刷新或无脏草稿时重新激活读取，不实时推送、不离线假保存。revision 冲突重新读取并提示核对，脏草稿保留，可重试保存。两端复用同一控制器、权限和 API，CSS 分别持有布局。

“更多 → 导入与导出”继续备份当前账号全部原始记录，包括历史三态和移出目录的记录，不受筛选影响。格式仍为 YuanHub 成就 JSON v1，5000条/16MiB。选择文件自动预览，默认保留冲突，采用文件也不以空备注擦除已有备注。未知 ID 须明确跳过；非法项整批拒绝。预览后变更账号/文件/策略/版本需重新核对，预览10分钟失效或后端重启后重做。文件源账号仅提示，不能取得其它账号权限。

后台维护入口仍为 `/achievement/admin`，同时需要 `archive:access` 和 `achievement_catalog:write`。见 [成就目录管理](achievement-catalog-admin.md) 及后端 `BackEndV3-Share/docs/achievement-api.md`。本次同步改造后端契约、目录和备份容量；访问范围按上述权限限制。

## V2 视觉精修

### 分类积分与四档奖励（2026-10-29）

代号鸢的五个默认分类标题下新增积分奖励进度，沿用纸底与金棕色节点。选择单个分类时展开四档；全部分类模式下默认显示摘要，可通过“查看奖励”展开。桌面四档横排、手机两列排列，保留原成就列表、筛选、分页及行内操作。单分类即使筛选无匹配成就也保留积分区。

积分分别统计并蒂莲、同心结、梧凤鸣、玉管毫、吴钩雪，使用当前账号在当前已发布分类目录中标记 `completed` 的所有记录及其结构化奖励数量，不受搜索、分页和其他筛选影响。无该物品的已知奖励贡献零；未完成不计分。完成、取消、撤销和导入在原保存流程成功后派生更新，不额外持久化积分或发放库存。超过2000分保留总数，四档均达标。

积分是“按已完成记录估算”，不代表游戏内已领取余额。未记录的成就不贡献分数，目录外的历史记录不参与；已完成条目奖励未知、数量异常或总数超安全整数时显示无法计算，不把旧奖励文本解析为数量。无账号、读取中及读取失败不显示零分。失败重试沿用页面的重新读取入口。

积分配置来自公开目录 point_tracks，按稳定 category_id 关联，物品名称及具体档位均由所有者手动导入数据库。前端只计算积分和渲染已发布配置；无配置时不猜测或跨游戏复用。具体数据不保存在源码或构建包。

人工验收：在代号鸢账号的 `/achievement` 选择一个分类，检查积分和四档奖励；完成/撤销一条有积分的成就，再改变搜索和状态筛选，确认积分仅随成功保存改变。切换账号或游戏检查无前账号积分残留；在390px、768px、1440px和浅/深主题检查奖励完整可读、手机两列、原列表操作可达。浏览器视觉、触控和真实服务联调仍须用户验收。

### 现有页面基线

本页局部沿用主题语义色，将纸底提亮并叠加极淡纹理；顶部使用原创静态资源 `/achievement/archive-landscape.svg`，以主题色 mask 呈现简化山水、楼阁、花枝和飞鸟，向正文渐隐。它不是效果图裁切，不包含文字或交互内容，不引入依赖或动画，也不改变全站主题。画稿的水彩笔触和精细花卉采用轻量线描简化。

宋体页头、暖白账号选择器、统一次级辅助链接与四项统计形成层次；分类采用小型菱形纹饰、淡金章节线及原有分类统计。连续列表仍只有一层边界，表头浅暖色，名称下方完整保留条件，文字旁加入细短金线。移除逐行礼物图标，完整奖励文本及无奖励、未补齐、旧奖励语义仍由原 `rewardText` 输出。未关注为低强调描边，已关注填充；完成状态保留绿色语义。备注、进度展开区仅调整底板、输入与按钮外观。默认不显示成功提示；原有成功/撤销区域增加确认图标与浅绿底色，仍占用原提示位置。

页头按容器宽度换行，保留全部辅助入口；桌面维持四项统计与四列表格，窄容器沿用纵向信息排列，手机保留两列统计、完整奖励和直接操作。没有增加详情区、操作步骤或另一套业务状态；筛选、分页、保存、撤销、日期、草稿、账号及导入导出逻辑保持原实现；本次仅将批量保存成功后的页面状态改为退出批量模式。

本轮局部展示为 L1，批量成功后退出模式的局部交互按 L2 定向验证；`useAchievement.js`、`rules.js`、API 和账号状态逻辑未修改。开发检查限定相关 diff、Vue 模板/局部 CSS 编译及成就组件测试（含批量成功退出、失败保留选择、冲突重试与既有草稿/撤销路径）；未启动浏览器或服务，未执行全量测试/build。真实视觉、深浅主题、触控和展开状态仍须人工验收，不能将静态检查视为效果图还原验收。

## 电脑和手机人工验收

复用正在运行的开发服务打开 `/achievement`。非浏览器组件检查不能证明真实布局、触控或软键盘表现；本轮没有启动、重启服务或执行浏览器自动化。

1. 桌面1440px：检查顶部克制山水、圆底图标统计与搜索、全宽分组列表左右对齐，章节线与分类统计不重叠，分类仅有单层列表边界；没有详情栏，标题不能打开详情。默认显示全部数量且没有清除入口；直接点击奖励、分类、状态、关联进度并勾选属性组合筛选，检查选中态、结果数、各组“全部”、清除入口与长选项自然换行。
2. 有真实条目时：普通状态和关注保存后只有统一成功反馈及一个撤销入口，普通行不因保存中/成功增高，滚动位置不跳回顶部。在未完成筛选标记完成，统计更新、行内仅显示即将移出，可在6秒内撤销；等待移出后仍可用统一入口撤销。修改状态及关注后，确认个人进度和备注保持原值。
3. 有真实量化条目时：行内编辑进度与备注，分别保存、取消；未填进度不显示零。未保存备注时筛选隐藏/翻页，再“返回编辑”；离开/切账号应提醒，切换账号后不显示前一账号草稿。断网保存保留草稿，冲突提示核对最新内容。
4. 手机320px / 390px / 430px、平板768px / 1024px：检查搜索独占一行、五组筛选直接可见并自然换行，状态、星标、备注及进度入口可达，无整页横滚或按钮重叠；保存提示吸附时不遮住焦点、常用操作或编辑区，展开输入后软键盘不妨碍滚动到保存/取消。缩放布局不应重建草稿或打开详情。浅色/深色均需手动确认文字和状态可辨。
5. 少量明确选中后批量标记，核对确认中的账号、游戏、条数与目标状态，以及统一反馈的条目数、实际统计更新、清空选择并退出批量模式、整批撤销及没有各行重复横幅；断网或冲突应保留本页选择与批量模式，核对后可重试；导出并预览同一JSON，核对目标账号和历史三态兼容，预览不写入。真实跨设备保存、导入冲突和权限由用户独立验收。

账号删除会清除成就记录；有实质记录禁止修改游戏。涉及删除的人工验收仅使用用户自行准备的可丢弃账号。

## 奖励与羁绊边界

奖励显示“物品 × 数量”，null显示“奖励资料未补齐”，空数组显示“无奖励”，不把缺资料当零。旧奖励通过目录级legacy_rewards回显为“旧文本，未结构化”，不参与未来计算。target=null无数值入口；没有目标但仍有历史人工进度时原样显示并提示待核对。已有小数进度可读取和导出，改备注/状态保持小数；新写入及含小数备份的导入明确拒绝，不自动取整。

`linked_metric=yuan_bond_variants` 只是目录配置，当前显示“羁绊联动尚未接入；当前仅记录人工进度”；不显示虚构的0、不自动完成。后续羁绊只读指标与人工进度分别展示和备份，达标仍由用户确认。

本阶段没有导入或发布真实资料，没有连接真实数据库、自动启动/重启/停止开发服务或运行浏览器。桌面/手机人工验收须用用户安排的测试数据与已运行服务；实际视觉、触控和运行时联调未由Agent验收。

## 补充资料与我的投稿（K05）

成就档案页头不再显示“补充资料”和“我的投稿”入口。投稿页面仍可通过 `/achievement/suggestions` 访问，我的投稿为 `/achievement/suggestions?mode=mine`。投稿时选择游戏、已发布分类，填写候选新成就、来源链接和可选补充说明后提交。不需要选择个人子账号，不会更改任何个人成就记录。奖励不清楚时保留“资料未补齐”并说明待核，不能填0表示未知。不支持通过投稿覆盖已有系统ID；更正现有成就可在说明中指出，由管理员编辑。

“我的投稿”按状态分页查看私人资料与审核结果。已采纳显示“已采纳到草稿，待管理员发布”，并区分当前已发布/尚未发布/发布状态未知；拒绝可查看原因，原单不退回编辑。来源与备注不向其他玩家公开。提交结果不确定时输入锁定，使用“重试上次提交”原样重试，避免重复投稿；明确的校验错误可修正后再交。离开页面前会提示未提交内容，页面刷新后不会保留未提交输入。

人工检查：在电脑和手机从成就页提交候选、查看本人详情、检查失败后输入保留与重试；换登录身份不应显示上一人的投稿。布局与真实触控尚需手动验收，jsdom测试不能代替。
