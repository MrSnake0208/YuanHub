# 当前养成：置顶与自定义分类

当前养成支持单个密探跨状态置顶，也支持调整未置顶密探的分组顺序。“标签”直接复用现有筛选组件，与“状态”使用相同的筛选行、底板、选中样式和计数；没有标签时不显示空行。“分类设置”入口放在原工具按钮一排，点击后在同一筛选卡片内展开编辑，不增加独立工具区。

- 新置顶的密探排到置顶列表最前；多个置顶可在管理面板上移、下移。置顶仍受搜索、状态、标签、品质及练度筛选约束。
- 未置顶密探先按用户设置的分组顺序排列，同组沿用特别关注和原有排序规则。默认顺序仍为养成中、已毕业、养老中；未开放的已弃置分组不显示。
- 每个子账号最多 20 个标签，名称去除首尾空白后为 1–40 字且不重复；一个密探可属于多个标签。卡片支持单个添加/移除，选中密探后可批量添加/移除。标签筛选与其他条件取交集。
- 分组顺序、置顶顺序及标签定义先编辑草稿，再点击“保存分类设置”；卡片置顶和标签、批量标签直接保存。保存失败保持原分类，管理草稿保留；其他设备修改导致版本冲突时须重新读取并核对草稿。
- 管理区按容器宽度排版：宽屏排序与标签两栏，窄屏单栏。标签使用紧凑列表与统一名称表头，名称、关联数量及删除操作横向对齐；容器不超过 360px 时操作换到下一行，避免挤压输入。新增标签自动聚焦名称，空白/重复名称显示字段提示并禁止保存；草稿在折叠后仍通过工具按钮显示“未保存”。保存结果紧邻操作区，“放弃修改”恢复已保存分类。
- 切账号或通过路由离开时，未保存分类使用现有确认流程；保存期间禁用账号切换。刷新/关闭页面交由浏览器原生离开提示，实际呈现依浏览器及用户交互条件而定。
- 分类按登录用户与子账号保存到独立云端数据，不修改养成状态、特别关注或练度，也不进入 MaaYuan 采集、分享及旧密探交换文件。重新加载和切账号均读取对应账号的分类。

## 备份与兼容

分类备份统一放在顶部“更多 → 导入/导出 JSON”，分类管理面板不再显示独立备份区。“导出密探档案”沿用原账号范围和 v4 格式；“导出当前账号分类”导出独立 JSON 文件，格式为 `yuanhub.operator-organization`、版本 `1`。仅导出已保存分类，不含练度、特别关注或未保存草稿。原密探档案备份不包含这些设置。

恢复时校验大小（最多 1 MB）、版本、游戏及密探 ID。共用原“JSON 备份导入”的文件选择与粘贴入口，自动识别分类格式，点击“校验并预览分类”展示置顶数量、标签名称及分组顺序。点击“确认恢复分类”才替换并保存当前账号分类；有未保存分类草稿时先确认，取消或失败保留草稿与预览。保存使用预览时的 revision，冲突需重新读取并重新预览；输入、账号或游戏变化会使旧预览失效。旧密探交换文件仍走原 v2/v3/v4 预览和导入，不进入分类 API。

`operatorDiscarded` 继续关闭，不因本功能开启“已弃置”。已有弃置状态不迁移或删除。用户可创建“暂缓培养”等私人标签；标签不改变 MaaYuan 读取的 `growth_state`。如账号更换游戏导致旧分类引用不在当前图鉴中，面板提供显式清理引用，不删除任何密探档案。

后端须先加载 [独立分类 API](../../BackEndV3-Share/docs/operator-organization-api.md) 再使用前端；旧后端会显示分类加载错误并禁用保存。普通分类读取不创建记录。

## 手动验收（桌面与手机各一次）

1. 登录并选择子账号，打开“当前养成”，将一位养老中密探置顶：全部列表中应排在养成中之前；切到养成中筛选后应被排除。
2. 在筛选区内展开“分类设置”，调整分组和多个置顶顺序，新增“主力”“备用”标签并保存；刷新后设置保持。新增空标签应聚焦名称，空白/重复时禁止保存并有字段提示；放弃修改后恢复已保存内容。
3. 给同一密探添加两个标签，批量给所选密探加/移除标签；标签与状态筛选取交集。删除标签只删除分类，练度、关注和养成状态保持。
4. 编辑标签后切账号，应先确认，选择继续编辑保持草稿；保存中不能切账号。两窗口同时编辑时，迟到保存应提示冲突，草稿可保留并显式放弃。在“更多 → 导入/导出 JSON”导出当前账号分类（不含草稿），再通过原文件入口导入：先预览，确认恢复后直接保存；取消草稿确认或恢复失败不丢内容。
5. 在约 1440px 桌面、768px 平板和 390px 手机宽度检查按钮、展开标签和管理面板；以组件可用宽度约 700px 为双栏切换点，缩放时输入不丢失。分类入口归于原筛选卡片，手机可直接点击上移/下移，无需拖拽，页面无横向溢出。
