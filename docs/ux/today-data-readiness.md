# 今日一览工作台与数据状态

## 展示结构

今日页保持 `TodayLayout` 单元素根节点，以兼容全站 `out-in` 路由过渡。首页设置弹窗放在布局的 `status` 插槽内，仍通过 Teleport 显示到 body；不要将其作为页面第二个顶层节点，否则离开首页时会只剩背景、目标页面无法挂载。

首页按五类真实业务组织，保留全站导航。稳定 `TodayLayout` 提供动态重点条及两列独立内容流：768px 起左列为活动待办→养成，右列为游戏活动→私人安排。每列各自向下衔接，短卡下方不会等待另一列最高卡片；没有任何内容的列收起，另一列占满。卡片不强制等高、不设固定高度；1081px 起避让现有 292px 导航。`overview` / `activities` / `training` / `notes` 分别承载四类业务，保持独立。

手机采用独立密度：日期和账号同行、问候与值守短场景、按需重点条、最多三条未完成任务、可切换的三条游戏活动预览、紧凑横向密探带、最多两项私人安排。局部 h1 保留读屏语义，页面名由现有全局手机页头显示；不添加导航或空页脚。长任务与活动名称最多显示两行，完整文本仍保留在原生控件的可访问名称中，详情进入现有页面。正文没有横向滚动，密探带可局部横向滚动并通过角色链接键盘访问。

PC/Mobile 各自维护互斥的 `*Desktop.css` / `*Mobile.css`，共享业务控制器和唯一功能实例。布局宿主仅监听 `(min-width: 768px)`，通过原生 Vue Teleport 移动同一游戏活动实例：桌面进入右列，手机插在待办之后、养成之前，保证视觉、读屏及 Tab 顺序一致。媒体监听在卸载时清理，移动后恢复原焦点；不重建业务组件、编辑器或 Teleport 目标，不复制 API 请求、清单状态、值守偏好或账号数据。缺少 matchMedia 的非浏览器环境明确使用手机顺序。

## 活动待办

只从当前账号已订阅活动的真实 Checklist 提取可勾选任务，范围沿用进行中与未来 90 天。订阅数量与未完成任务数量分别记录；多个订阅但没有 Checklist 时明确提示不会自动创建任务。任务行展示标题、关联活动和实际活动截止信息，无截止的活动保留详情入口；仅日期的截止不伪造 23:59 或倒计时，精确时刻换算为北京时间。

默认最多三条未完成任务；已勾选项进入“查看已勾选清单”或完整清单，仍能取消完成。展开后仅清单列表限高滚动（桌面最多360px、手机最多300px，均不超过50dvh），标题、收起按钮和完整日历入口仍在列表外；默认摘要随实际条数自然收缩。清单全部勾选只代表任务状态，不代表活动整期完成；本期完成标记继续独立维护。保留原版本校验、保存确认、失败锁定、读取最新状态、冲突恢复、账号切换丢弃旧响应和键盘焦点恢复。

常规订阅总数、未标记本期完成的活动数、历史/不可用订阅与完整入口放在默认收起的“订阅概况”。该统计不冒充待办数量。保存成功使任务离开预览时，将该任务上的焦点移至下一任务或标题入口；后台刷新不为保留旧任务自动展开列表。

## 游戏活动

公开活动、招募与近期日程使用类型票签和状态徽标，不使用可勾选的任务样式，不伪造活动缩略图。继续读取原公开日历接口的进行中及未来 7 天范围，按游戏筛选、去重并忽略过期内容。

“进行中”按实际起止时刻计算，包含今日开始/结束且当前已开始的活动；“今日结束”是进行中的子集，三个数字不能相加作为总数；“即将开始”包含今天稍后才开始的活动。日期精度记录沿用日历日边界，精确时间沿用 `calendarTimeBounds`；今日结束及显示日期按北京时间换算，避免来源时区制造错误的今日状态。

默认展示进行中，没有进行中时回退即将开始；用户可主动切换三个状态段，每段最多三条，剩余数量与完整日历入口保留。切换只改变本地预览，不重复请求。进行中按截止时刻排序、即将开始按开始时刻排序；状态与日期分开显示，去掉重复开始日期及服务器日期说明。活动链接保留游戏、月历日期并定位真实 `event`。跨起止时刻和服务器午夜继续更新，卸载清理定时器与监听。

## 今日重点

综合当前账号 72 小时内截止的订阅活动及真实未完成 Checklist，以及今天/明天达到已开启提醒条件的私人事项。相同活动合为一条，不推断清单存在；Checklist 与本期完成保持独立。复用首页两个数据实例的身份标记快照，由独立组件在 `#today-reminders` 展示，默认预览三条但计数包含全部去重条目，可展开完整重点；成功为空隐藏，部分读取失败保留其它来源并明确提示。完整规则及验收见 [今日重点](../today-highlights.md)。

重点条默认展开，可收起；跨断点保留展开状态和焦点。提醒消退且焦点原本在内部时恢复至待办入口，不抢走外部焦点。仅日期活动按北京时间日历日截止，精确截止换算为北京时间。没有新增私人提醒聚合或第二套提醒算法。

## 我的养成计划

复用当前账号的培养工作区、特别关注、养成目标、密探备注和公共图鉴，只读，不写回计划、不导入本地草稿、不扣库存或推算体力。当前非空清单优先，否则回退第一个非空清单；统计所有非空清单与真实成员数，同一密探出现在不同清单时分别计数。

独立角色区域最多预览五名成员的真实头像、姓名和定位链接；不添加虚构进度、等级达成率或资源缺口。图鉴失败回退本地目录，头像缺失显示名字首字，两处未知的 ID 原样显示。更多成员、清单与备注保留简短入口说明；首条非空备注为最多 80 字的纯文本单行预览。成员链接和管理入口仍进入原养成总览。

身份/账号/游戏切换立即清空旧内容；异步响应核对账号并丢弃旧轮结果。普通刷新失败保留上次内容并标注，权限失效清空内容并停止刷新；页面恢复与现有账号事件合并刷新，卸载清理。功能继续受 `OPERATOR_GROWTH_TRACKING` 控制。

## 私人安排

复用 `GET /v1/activity-calendar/private-items` 与 `privateCalendarItem` 校验，独立读取当前账号进行中及未来 7 天的日期事项，按真实时间顺序最多预览两项；更远事项留在完整日历。日期侧记展示时间/全天、标题、多日范围及最多 80 字的纯文本备注，没有勾选框或完成状态。

首页始终启用 `hideEmpty`：成功确认近期无内容后隐藏卡片，组件读取实例仍保留；加载、错误、权限失效不得伪装为空。普通刷新失败保留旧内容并标注，身份/账号/游戏变化立即清空并丢弃旧请求；页面可见与北京时间跨日刷新，卸载清理。入口沿用我的日历与具体事项定位，不改变日历模型或筛选体系。

## 首次建档和异常

账号、真实资料读取与建档逻辑保持原样。登录/创建账号/录入状态互相独立，读取失败显示 unknown，不要求覆盖重录。首次确认密探、库存、星石全空时保留紧凑引导，待办/养成成功为空才隐藏，真实业务内容及错误仍可显示。已有资料时不展示补齐区或账号详情。

## 原有资料准备规则

沿用 auth/account/data/ready 阶段，分别判断密探、库存与星石，不把读取失败伪装成缺失，不因一项失败要求覆盖重录。

库存“正库存种类数”与“已有录入证据”独立。复用 `/v1/inventory/current` 的 `full_baseline_at` 与库存条目：完整基准存在时，即使entries为空或全部为零也属于已录入；有效零条目（包括listed局部盘点）表示已有录入，但不宣称完整盘点。正数量条目也表示已有录入；只有完整基准才能显示完整盘点说明，`updated_at`不作为完整盘点证据。

成功返回空数组表示没有当前库存记录；旧格式空文档、缺元信息或无有效证据时显示“录入状态待确认”；请求失败显示“暂时无法读取”。两种unknown均不展示重新录入按钮。零完整基准显示“已盘点，当前库存为零”，局部零录入显示“已有录入，当前库存为零”。

首页读取继续复用当前账号与现有sequence保护；切换账号后旧响应不得覆盖新账号。连接码授权仅代表允许同步，不作为盘点或同步成功证据。

最小回归：`node --test test/todayData.test.js test/todayPage.test.js`、`npm run test:behavior -- behavior/todayComingSoon.spec.js`。在YuanHub目录执行，由用户/CI负责运行。
