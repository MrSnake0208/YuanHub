# 今日一览的数据录入状态

双栏时个人工作台占主要宽度，常规信息侧栏以 28% 为目标并保留 240px 的可读下限；单栏时个人内容排在常规信息前。

桌面今日一览以个人工作台为左侧主栏，依次显示“我的待办”“我的养成计划”和“我的事项与备注”；右侧依次显示“当前活动”“临期活动”和“账号详情”。窄屏先显示个人内容，再显示常规信息。临期活动继续使用当前账号订阅摘要中的未来 72 小时截止提醒，通过 Teleport 呈现到布局提供的区域，与待办共用一个数据与计时实例。没有账号时仍保留原有建档流程与活动单栏；有账号但尚未录入游戏数据时，也可以查看个人待办、培养清单与私人事项。

养成卡片复用当前账号的培养工作区、特别关注、养成目标与密探标注 GET 接口，按培养清单显示成员、已保存目标与完整纯文本备注，并保留清单外的密探备注。特别关注清单继续使用 `trainingPlanMemberIds` 合并实时关注、显式成员和排除项；自定义清单使用自身目标，未保存的默认目标不在首页推算。卡片只读，不导入本机草稿、不生成体力模拟日程、不写回工作区或扣除库存；点击成员进入养成总览并定位密探，管理入口进入养成总览。此卡片受已有 `OPERATOR_GROWTH_TRACKING` 开关控制，独立于活动日历开关与基础资料录入状态。

养成摘要使用紧凑分组列表：当前清单优先显示，其余清单保持工作区顺序；标题下显示非空清单数和培养目标条数，同一密探在不同清单中分别计数。每个清单显示人数，当前清单以文字标签标识。成员行复用密探头像组件，缺少头像时显示名字首字；点击整行仍进入对应密探。桌面卡片内容宽度达到 480px 时横向排列姓名与目标，其余宽度及手机端分行显示，长名称和目标允许换行。备注完整显示在成员下方的浅底区域，保持纯文本与原始换行。右上角入口为“管理养成”；首页不新增完成进度推算。

养成读取独立于首页其他摘要。身份、账号或游戏切换立即清空旧内容并丢弃旧响应，随后合并同一轮状态更新再读取，避免登录状态先更新时使用旧身份发起请求；所有私有响应核对账号；读取失败显示重试入口，普通刷新失败保留上次内容并标注，权限失效清空内容并停止刷新。页面重新可见、恢复页面或收到当前账号的培养清单、目标、备注、关注更新事件时合并刷新，卸载时清理监听和计时器。培养清单和其他密探备注的名称优先使用与养成页相同的 `GET /v1/operator/catalog` 公共图鉴；图鉴读取失败、格式无效或条目没有有效名称时回退本地目录，两处目录均未知的 ID 原样显示。公共图鉴失败不阻断个人计划展示，名称变化不改变成员链接中的定位 ID。定向回归：`npm run test:behavior -- behavior/todayTrainingPlans.spec.js behavior/todayComingSoon.spec.js`，由用户/CI执行。

私人事项复用 `GET /v1/activity-calendar/private-items` 和 `privateCalendarItem` 校验，展示当前账号进行中及未来 90 天的事项、完整纯文本备注和日期范围。点击标题进入我的日历列表并定位事项，在日历继续编辑。读取独立于活动待办，慢请求或失败不会阻塞待办；身份、账号或游戏切换立即清空旧备注并丢弃旧响应，权限失效清空内容并停止自动刷新。普通刷新失败保留上次内容并明确提示；页面重新可见或北京时间跨日时刷新，卸载后清理。新增定向回归：`npm run test:behavior -- behavior/todayPrivateItems.spec.js behavior/todayComingSoon.spec.js behavior/todayActivitySummary.spec.js`，由用户/CI执行。

平板与桌面卡片按内容自然增长，不将待办拉伸到右侧整列的高度。981px 起可使用双栏，只有侧栏出现的 1081px 起才预留正文左侧空间。主区左边距与全站一致使用 292px，避开右边界为 264px 的固定导航并保留 28px 间距，页头和正文一起避让。768px 起的页头默认使用紧凑场景，只有页头容器内部可用宽度达到 1000px 才展开大立绘；活动摘要同步收紧间距，完整保留标题、日期、统计和入口。相关样式检查：`node --test test/todayLayoutStyles.test.js`；断点状态保留检查：`npm run test:behavior -- behavior/todayComingSoon.spec.js`，由用户/CI运行。

沿用 auth/account/data/ready 阶段，分别判断密探、库存与星石，不把读取失败伪装成缺失，不因一项失败要求覆盖重录。

库存“正库存种类数”与“已有录入证据”独立。复用 `/v1/inventory/current` 的 `full_baseline_at` 与库存条目：完整基准存在时，即使entries为空或全部为零也属于已录入；有效零条目（包括listed局部盘点）表示已有录入，但不宣称完整盘点。正数量条目也表示已有录入；只有完整基准才能显示完整盘点说明，`updated_at`不作为完整盘点证据。

成功返回空数组表示没有当前库存记录；旧格式空文档、缺元信息或无有效证据时显示“录入状态待确认”；请求失败显示“暂时无法读取”。两种unknown均不展示重新录入按钮。零完整基准显示“已盘点，当前库存为零”，局部零录入显示“已有录入，当前库存为零”。

首页读取继续复用当前账号与现有sequence保护；切换账号后旧响应不得覆盖新账号。连接码授权仅代表允许同步，不作为盘点或同步成功证据。

最小回归：`node --test test/todayData.test.js test/todayPage.test.js`、`npm run test:behavior -- behavior/todayComingSoon.spec.js`。在YuanHub目录执行，由用户/CI负责运行。
