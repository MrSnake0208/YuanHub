# 今日一览的数据录入状态

首页采用内容自适应工作台，不再把三个业务模块包进纵向大底板，也不为短私人事项永久保留一列。桌面根据正文容器实际宽度排布：不足 640px 时单列；达到 640px 时待办和游戏日程并排，养成和私人事项接在下一行，三块内容中的落单模块跨整行，只有公开日程或仅启用养成时占满可用宽度。只有容器至少 1000px 且待办、日程、养成、私人事项、真实临期提醒均存在时才启用三列：待办 / 日程 / 临期，下一行养成跨两列、私人事项占第三列。提醒消退或模块隐藏自动回到双列，不生成占位内容。模块不强制等高，也不设置工作区固定高度；1081px 起继续避让原有导航 292px。

手机按稳定 DOM 顺序呈现：有内容的临期提醒 → 待办 → 公开日程 → 养成 → 私人事项。日期和账号放在同一行，本地 h1 仅保留读屏语义，使用原有全局页头显示“今日一览”；值守问候紧接其后，保留更换密探、立绘加载失败和保存失败反馈。本页移除空 SiteFooter，不影响其他页面。待办标题与来源可同行，添加入口与订阅概况共用轻量底栏；日程用开始日期标识、标题及状态同行、截止时间另行，缺精确时间继续标记“仅日期”；养成采用头像在上、姓名在下的成员带，其他清单/备注提示合并排列。没有日期切换、体力或资源推算，完整日程进入原活动日历。

临期提醒继续使用当前账号订阅摘要中未来 72 小时截止的真实记录，通过 Teleport 呈现到稳定的 `#today-reminders`，与待办共用一个数据与计时实例。无临期记录时目标不占布局空间；常规订阅数量、历史/不可用订阅说明和完整入口留在待办底部“订阅概况”，默认收起。临期提醒默认展开，可由用户收起；跨断点不替换组件或移动目标、不丢展开状态和焦点。临期记录全部消退时，若焦点仍在该提醒内，则恢复至待办标题入口，不抢走其它控件的焦点。仅改变展示，不改变临期算法、待办范围、完成语义或请求数量。

首页不再展示“账号详情”，但保留录入状态读取、账号切换保护和首次建档引导；活动关闭时不保留空侧栏。没有账号时仍保留原有建档流程与活动单栏；有账号但尚未录入游戏数据时，也可以查看个人待办、培养清单与私人事项。双端使用互斥 `*Desktop.css` / `*Mobile.css`，稳定 Vue 实例共享请求、状态、错误与权限处理。

首次引导放在账号选择与问候区域之后、业务概览之前。确认密探、库存和星石均为空时，以“从一份资料开始”提供三个手动录入入口与连接 MaaYuan 的入口；手机端录入入口使用紧凑行，桌面端保持三列，去除空状态的重复说明。仅对这类确认全空的账号启用业务卡片 `hideEmpty`：组件仍挂载并独立读取，成功确认为空后隐藏卡片，有内容、正在读取或读取失败时仍显示；因此已有待办、培养计划及私人事项不会被资料引导遮掉。个人区全部为空时，活动摘要使用单栏，不留下空主栏。已有任意一项游戏资料时保持原有规则，不显示补齐引导；状态未知时不启用空卡隐藏，并将仍需展示的资料提示明确标为“数据状态待确认”，不冒充首次建档或提供重录未知资料的入口。

待办默认仅预览最多 3 条未完成任务，数量统计仍覆盖原有进行中及未来 90 天范围。已完成项默认不占预览空间；原有完整清单展开和取消完成能力保留，“查看全部”进入我的日历。保存成功导致任务离开预览时，将该任务上的键盘焦点移至下一条可见任务或标题入口；后台刷新不会为了保留旧任务而自动展开全部。

养成卡片复用当前账号的培养工作区、特别关注、养成目标与密探标注 GET 接口，仅展示培养清单摘要，不逐人展开等级、修为、星级等目标属性。特别关注清单继续使用 `trainingPlanMemberIds` 合并实时关注、显式成员和排除项；首页不推算未保存目标。卡片只读，不导入本机草稿、不生成体力模拟日程、不写回工作区或扣除库存；点击成员进入养成总览并定位密探，管理入口进入养成总览。此卡片受已有 `OPERATOR_GROWTH_TRACKING` 开关控制，独立于活动日历开关与基础资料录入状态。

养成摘要只预览优先清单：当前非空清单优先，否则回退首个非空清单；标题下仍统计所有非空清单与培养目标，同一密探在不同清单中分别计数。预览显示该清单总人数及最多 3 名成员的头像、姓名和定位链接，超出人数与其他清单数量以简短文字提示。头像缺失时仍显示名字首字，长名称允许换行。密探备注仅保留首条非空纯文本的单行预览（最多 80 个字符，超出加省略号），清单外备注只显示人数；完整目标与备注在养成页查看。右上角入口为“管理养成”；首页不新增完成进度推算。

养成读取独立于首页其他摘要。身份、账号或游戏切换立即清空旧内容并丢弃旧响应，随后合并同一轮状态更新再读取，避免登录状态先更新时使用旧身份发起请求；所有私有响应核对账号；读取失败显示重试入口，普通刷新失败保留上次内容并标注，权限失效清空内容并停止刷新。页面重新可见、恢复页面或收到当前账号的培养清单、目标、备注、关注更新事件时合并刷新，卸载时清理监听和计时器。培养清单和其他密探备注的名称优先使用与养成页相同的 `GET /v1/operator/catalog` 公共图鉴；图鉴读取失败、格式无效或条目没有有效名称时回退本地目录，两处目录均未知的 ID 原样显示。公共图鉴失败不阻断个人计划展示，名称变化不改变成员链接中的定位 ID。定向回归：`npm run test:behavior -- behavior/todayTrainingPlans.spec.js behavior/todayComingSoon.spec.js`，由用户/CI执行。

私人事项复用 `GET /v1/activity-calendar/private-items` 和 `privateCalendarItem` 校验，统计当前账号进行中及未来 90 天的全部事项，按原有时间顺序最多预览 2 条。保留日期范围和单行纯文本备注（最多 80 个字符，超出加省略号），其余事项提示剩余数量；“查看全部”进入我的日历列表，标题链接继续定位具体事项，完整备注与编辑在日历中进行。读取独立于活动待办，慢请求或失败不会阻塞待办；身份、账号或游戏切换立即清空旧备注并丢弃旧响应，权限失效清空内容并停止自动刷新。普通刷新失败保留上次内容并明确提示；页面重新可见或北京时间跨日时刷新，卸载后清理。新增定向回归：`npm run test:behavior -- behavior/todayPrivateItems.spec.js behavior/todayComingSoon.spec.js behavior/todayActivitySummary.spec.js`，由用户/CI执行。

所有实际模块参与同一布局网格，原主区/辅助区包装用 display: contents 保留挂载位置，不以 slot/Teleport 的空文本锚点判断是否有内容。首次建档各业务确认全空后，公开日程占单栏；仅开启养成时不生成辅助栏。桌面账号区与值守区横向排列，值守场景手机至少 64px、桌面至少 92px，随状态文字自然增高，不覆盖账号选择或任务内容。活动保留最多 3 条当日活动与 1 条未来 7 天的预览。

定向非浏览器验证（YuanHub 目录）：`node --test test/todayLayoutStyles.test.js test/todayData.test.js test/todayPage.test.js`；`npm run test:behavior -- behavior/todayComingSoon.spec.js behavior/todayCalendarSubscriptions.spec.js behavior/todayActivitySummary.spec.js behavior/todayLobby.spec.js behavior/todayTrainingPlans.spec.js behavior/todayPrivateItems.spec.js`。这些检查不代表真实像素、触控或浏览器验收。人工检查 320/390/430/768/1024/1440px 及 767/768、1080/1081px 和正文容器 640/1000px 临界状态：有临期与无临期顺序、长名称换行、空/错/首次引导、跨账号内容与任务勾选焦点。

沿用 auth/account/data/ready 阶段，分别判断密探、库存与星石，不把读取失败伪装成缺失，不因一项失败要求覆盖重录。

库存“正库存种类数”与“已有录入证据”独立。复用 `/v1/inventory/current` 的 `full_baseline_at` 与库存条目：完整基准存在时，即使entries为空或全部为零也属于已录入；有效零条目（包括listed局部盘点）表示已有录入，但不宣称完整盘点。正数量条目也表示已有录入；只有完整基准才能显示完整盘点说明，`updated_at`不作为完整盘点证据。

成功返回空数组表示没有当前库存记录；旧格式空文档、缺元信息或无有效证据时显示“录入状态待确认”；请求失败显示“暂时无法读取”。两种unknown均不展示重新录入按钮。零完整基准显示“已盘点，当前库存为零”，局部零录入显示“已有录入，当前库存为零”。

首页读取继续复用当前账号与现有sequence保护；切换账号后旧响应不得覆盖新账号。连接码授权仅代表允许同步，不作为盘点或同步成功证据。

最小回归：`node --test test/todayData.test.js test/todayPage.test.js`、`npm run test:behavior -- behavior/todayComingSoon.spec.js`。在YuanHub目录执行，由用户/CI负责运行。
