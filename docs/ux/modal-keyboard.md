# 输入弹窗与软键盘

适用弹窗：反馈工单详情（回复和流转说明）、通用输入对话框、日历私人事项、密探编辑、星石预设、库存奖励录入及报告粘贴。

打开弹窗时，遮罩跟随 `visualViewport.height/offsetTop`；无该 API 时回退窗口高度。通常保持标题与操作区，正文独立滚动以显露焦点。可视高度小于 360px 时，整个弹窗成为滚动区，标题与按钮也参与滚动，避免短横屏被固定头尾挤满。关闭/卸载清理视口监听。

实现位于 `src/composables/useModalViewport.js`，仅显式接入上述弹窗。接收可见性、正文 ref、面板 ref；面板的 `focusin` 触发焦点显露。各组件保留独立的 PC/Mobile CSS：面板高度使用 `--modal-viewport-height`，`.is-short-viewport` 切换滚动容器。视口事件不重建表单、不提交或清空草稿、不滚动背景。既有提交、校验、焦点栈、取消确认及业务接口保持原流程。

## 人工验收（尚未执行）

1. **390px 手机竖屏**：逐个打开上述弹窗，点击中部和靠下输入框，连续输入多行；当前文字和光标应可见，能滚动到操作按钮。收起/重新弹出键盘，草稿应保留。
2. **768–1080px 平板及手机横屏**：同样输入，尤其检查键盘后只剩约 200px 高度的场景；此时可在弹窗内部滚动标题、输入与按钮，背景不跟随滚动。旋转回竖屏后焦点与草稿应保留。
3. **1440px 桌面**：确认正常布局密度，长表单滚动、Tab/Shift+Tab、关闭和取消确认保持可用，提交仅在主动点击时发生。
4. **嵌套弹窗**：从反馈详情打开二级输入，从密探打开星石预设；输入和键盘变化应只滚动当前弹窗。关闭上层后下层内容与草稿仍在。

定向测试使用 jsdom 和模拟视口/元素矩形，验证监听、滚动目标、DOM/草稿/焦点保留及清理；它们不能证明真实 iOS/Android 软键盘、CSS 几何或浏览器缩放表现。
