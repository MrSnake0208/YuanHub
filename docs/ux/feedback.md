# 反馈中心

## 多平台专区（2026-10-26）

默认入口 `/feedback`、`/feedback/plaza` 保持 YuanHub 主站，无“先选平台”步骤。合作入口使用 `/feedback?space=<稳定标识>`（提交入口可加 `&new=1`），公开广场为 `/feedback/plaza?space=<稳定标识>`；登录继续沿用原认证和 `redirect=完整目标路径`。专区来自真实目录，不预置演示合作方。

页头仅增加紧凑专区上下文；多专区显示原生选择器，单专区显示名称。反馈中心、广场、我的反馈及提交保持同一专区。新提交固定使用填写时的专区和其内部板块，失败保留内容与附件；停用专区阻止新提交，仍保留历史阅读。“查看我在所有专区的反馈”仅扩大本人列表范围，不改变新反馈的提交归属。

工作台 `/feedback/manage` 自动让仅有合作专区权限的用户进入其授权范围；多专区可切换，超级管理员另外有 `?space=all`。专区与工作队列是独立维度。切换清理旧板块、页码和详情，保留通用搜索/排序，列表与计数重新请求，迟到响应不能覆盖新专区。回复、流转及公开修改草稿沿用离开确认；进行中的写入阻止危险切换。列表仅在所有专区范围显示归属，具体专区不逐行重复。

未读轮询按真实工单归属分组；当前专区“全部已读”包含筛选之外的本专区工单，不影响其他专区。所有专区总管理有明确作用范围说明。反馈公开授权、工单详情、回复、处理与合并关系继续复用原组件和岗位约束。

既有 `/feedback/admin` 的折叠“专区设置”承载创建、改名、开放状态与合作入口；成员通过同页既有岗位/板块授权配置。全局岗位不因切换专区自动变化，保存当前专区板块时保留其他专区已有授权；删除整份授权会明确提示作用于全部专区。仅拥有既有授权配置权限者可修改，不给普通专区成员额外配置权。创建/修改可在原审计页追溯。

新反馈图片使用私有上传，详情鉴权下载并在离开时释放临时地址；普通文件能力与 10 个混合附件上限保留。**旧 `/media/` 图片地址未迁移，仍有原公开访问边界**，详见后端反馈接口文档。合作专区没有独立版本目录，不复用主站草稿版本。

界面净变化仅为页头选择器、个人历史文字入口、必要的跨区归属和折叠配置；暖纸张主题、侧栏、队列、筛选、表格及详情骨架保留。没有新增示例工单、FAQ、统计或全站导航。非浏览器组件检查不能证明实际布局、触控或视觉通过；人工验收建议桌面 1440px、手机 390px，补查 768px 临界布局，检查页头换行、选择器、详情展开、键盘焦点、草稿取消及返回列表。

新建反馈、用户追加消息和管理员回复，每条消息最多添加 10 个附件，截图与普通文件合计计数。选择器显示当前数量与上限，超过上限时保留原附件并提示。

反馈图片采用清晰度优先的有损压缩：超过 128 KiB 后优先编码为 WebP，质量从 0.84 调整到最低 0.78，目标 512 KiB、前端上传上限 3 MiB。保留原始像素尺寸与长宽比例，不再把长截图缩到 2560 像素；编码反而增大且原图不超过 3 MiB 时保留较小的原图。压缩后仍超限会提示裁剪无关区域或拆成多张截图，不继续降低质量或缩小尺寸。原文件 25 MiB、4000 万像素、单边 12000 像素的处理边界保留。缩略图与点击打开大图的入口不变，上传后只保存最终选中的图片，并非同时保留未经压缩的原图；历史附件不重新压缩。实际小字可读性与放大查看仍需人工验收。

上述 3 MiB 是当前前端的图片规则；后端通用媒体接口仍为 10 MiB，旧客户端或直接调用接口不受此前端策略约束。TXT、LOG、JSON、PDF、ZIP 普通附件仍为每个 10 MiB，头像与更新公告沿用各自压缩策略。

手机选择 JPG/JPEG、PNG、WebP 时，允许文件类型声明为空或 `application/octet-stream`，按后缀补齐标准图片 MIME；`image/jpg` 仅按 JPEG 处理。补齐 MIME 保留原始文件名与图片字节，后续仍沿用现有压缩规则；明确冲突的类型/后缀与 HEIC 等不支持格式仍拒绝，服务端继续校验文件头。这仅修复可复现的文件识别问题；真实手机的相册唤起、预览和上传仍需人工确认。

桌面侧栏与手机导航抽屉均直接展示「反馈中心」，位于活动日历后，不再收在「更多」中。登录用户进入我的反馈，游客进入公开反馈广场；该入口不显示管理员待阅反馈角标，也不订阅管理反馈轮询。管理员待阅状态在反馈工作台内查看，个人回复提醒仍通过站内通知与我的反馈列表显示。反馈页面高亮独立入口，管理页面仍归属管理工作台。

反馈广场、我的反馈、反馈工作台和权限配置使用统一的「反馈中心」标题与紧凑页头；浏览器和手机顶部标题同时标明当前分区。所有反馈页面的内部导航仅保留「反馈广场 / 我的反馈」，手机端等宽单行展示并裁切选中背景圆角；管理页面不高亮这两个用户入口。反馈工作台和权限配置不再作为页内导航标签，管理员通过全站导航中的「管理工作台」进入「待处理反馈 / 反馈授权」，仍按账号权限显示。反馈页面内不再重复展示「管理工作台」入口。各分区保留独立路由、刷新直达与浏览器返回能力。

我的反馈在请求成功确认没有工单、且没有筛选条件时收起搜索、筛选和页码，优先展示「提交第一条反馈」，反馈广场保留为次要文字入口。筛选无结果保留控件并可清除条件；加载中或失败时不会被误判为空态，重试和权限错误提示仍可访问。手机端压缩页头与空态留白，空态说明使用常规字重。搜索、工单状态与板块筛选形成连续区域，不展示反馈类型。OPEN 始终表示处理中；新消息标识来自通知记录，不因历史 hasAdminReply 一直显示已回复。列表优先显示标题，私人列表的编号折叠展示。

反馈广场区分全站暂无公开反馈与当前筛选无结果：有效关键词（去除首尾空白）或状态任一生效时使用筛选空态，提供「清除筛选」与原有提交入口。清除取消待执行搜索，清空这两项并回第一页，保留排序选择；加载失败保留筛选与重试，不显示成功空态。

公开功能计划成功确认无筛选且没有目标时收起阶段工具栏与进度解释，保留提交建议入口；阶段筛选无结果保留控件与「查看全部目标」，请求失败保留筛选和重试，管理视图仍保留工具栏。完成标准与需求来源继续使用真实目标数据。

反馈广场允许游客浏览。登录后，广场列表、公开详情和相似反馈会根据服务端的本人支持记录恢复「已关注」，刷新或重新进入后仍保留；支持总数面向所有人显示，本人状态随登录用户变化。

新建反馈仅需选择服务端动态板块并填写内容，普通提交固定 `type=OTHER`，不展示类型选择。板块支持自定义及重命名，目录失败时禁止提交。旧链接继续解析实际可用板块（含活动日历 `builtin_key`），类型参数不改变普通提交类型，不复制链接中的正文。默认仅私下沟通，无需标题。用户主动勾选「允许管理员整理后发布到反馈广场」后才显示必填标题和相似反馈；勾选不会自动发布。取消勾选保留标题草稿，但不提交隐藏标题、不继续相似检索。公开授权与附加浏览器/操作系统/IP 信息的选择相互独立且默认关闭；客户端授权收在可选设置。表单单列，紧凑附件，长内容内部滚动，底部取消/提交保持可达。

管理员只能发布明确授权的反馈，共享发布面板显示授权状态；未授权时不能发布或修改公开正文，已公开反馈仍可维护状态或取消公开。缺少授权字段的历史反馈按未授权处理，不由管理员补授权；普通历史公开内容不会自动撤下。举报 `REPORT` 及旧 `FEEDBACK/category=REPORT` 仅供私下处理：后端禁止发布，公开读取/关注返回不存在，公开列表与相似检索在查询层排除；不能通过改类或与普通工单相互合并绕过。私有读取与原有工单处理权限不变。

反馈广场详情提供「管理此反馈」，点击后按需读取管理详情并核对该条权限；当前运营负责人或超级管理员可直接维护公开信息，游客和普通用户不读取内部接口。保存后同步刷新公开详情与列表，取消公开后关闭详情并移除卡片。失败保留编辑内容，收起管理、关闭详情、离开页面和刷新前保护未保存修改。

相似反馈详情在新标签页打开，支持相似反馈也保留标题、正文和附件草稿。关闭未提交的草稿仍需确认。表单支持 Tab 焦点限制、Esc 关闭及关闭后返回入口。

「标记完成」表示问题已解决并结案，不能继续追加消息；确认框会说明这一后果。管理员结案已公开反馈时，默认勾选「同时将反馈广场标记为已完成」，可取消勾选以保留公开进度；用户自行结案不改变广场状态。内部结案与公开完成通过单次条件更新保存，并发修改时提示冲突。提交成功后说明回复将通过站内通知送达。

管理员工作台按当前搜索和负责板块显示各队列总数，数量来自服务端分页总数，失败时显示「—」和重试提示。运营可进入「程序已交回」队列；「需我回复」只包含本人负责、处理中且用户最后一条消息尚未被管理员回复的工单。默认按最新提交排序，也可选择最近更新或最早提交；最早提交不等同于用户等待回复时长。

回复文字、附件和流转说明在取消、关闭详情、切换工单/筛选、离开路由及刷新页面前受草稿保护。拒绝放弃时保留正文、附件和原筛选值。回复表单打开后聚焦输入框，详情、发布、合并与权限弹窗限制 Tab 焦点，Esc 关闭最上层，关闭后返回入口。处理记录仍位于原有「工单流转」菜单，入口条件不变。

管理员回复框提供「插入当前版本」按钮，旁边显示当前页面加载的前端产品版本（与侧边栏一致）。点击后在光标位置插入版本号，选中文字时替换所选内容，并返回输入框继续编辑；例如「该功能已于 v0.0.1-beta.15 实现」。插入不会自动发送，不使用用户提交反馈时的旧版本；插入后超过 1000 字符会提示并保留原文，发送期间按钮不可用。更新发布后应先刷新页面，再插入新版本。

完成、驳回和重新打开使用明确的确认文案，成功后显示结果并保留筛选、排序和有效页码；原页消失时回退至最后有效页。管理列表优先显示两行摘要、待办状态、负责人及更新时间，编号折叠后可复制；手机列表保留状态和进入详情的操作。

「全部管理范围已读」收在「管理操作与列表设置」中，与列表筛选分开呈现，确认框说明数量及包含筛选之外的工单，只更新阅读状态，不结案。界面不再展示或维护反馈类型，发布/编辑公开摘要不改写历史类型；底层枚举及内部兼容 API 保留。内部结案与广场进度保留独立字段，管理员结案时可明确同步完成，其他状态不自动同步。合并弹窗展示来源及主反馈，搜索或来源改变立即清除旧选择，旧请求不能覆盖最新结果。

权限页优先展示运营/程序岗位与负责板块；通知接收及兼容管理授权放在折叠区域，预览和保存仍保留全部授权。通知、兼容管理和工作台岗位分别生效，不自动授予岗位或覆盖岗位板块。


## 轻量工作台与人工验收（2026-10-16）

主要入口为待接单、我负责、需我回复、待程序处理；程序已交回、已结束、全部为次级入口。纯程序岗位默认 DEV，仍只展示有权限的队列。队列不是互斥状态，不能相加；程序已交回表示曾交回，不等同尚未验收。每页数量收在列表设置；搜索/板块/排序保留原服务端筛选、总数与有效页码逻辑。

桌面表格按反馈内容、板块、待办/状态、负责人、更新时间、查看工单排列。未分配负责人不再重复显示待接单。编号可展开及复制，新消息未读与需回复分别来自 teamUnread 和 needsReply。手机为纵向卡片，队列可横向滚动，不新增底部导航。

以下均为**待人工验收**，非浏览器自动化结果：

1. **1440px**：打开 `/feedback?new=1`，只选板块填正文即可私下提交；勾公开授权后才出现必填标题与相似提示。添加/粘贴截图、文件，核对失败提示、重复提交防护、取消草稿确认及成功反馈。两个授权默认关闭。
2. **390px**（同时抽查 320/430px）：新建弹窗单列、正文独立滚动，操作按钮位于正文滚动区之外；展开公开标题与客户端设置后按钮仍可到达。点击正文/标题输入框并唤起软键盘，当前输入应可见，继续输入多行、收起键盘和横竖屏切换后草稿与焦点不丢。工作台显示卡片，队列区域可独立横向滚动，整页不横向溢出。
3. **768/1024px**（抽查 1080/1081px 断点）：搜索/板块/排序自然换行，长自定义板块、负责人、工单编号不撑开容器；切换宽度不丢草稿。表格与卡片分别检查焦点、下拉和详情关闭后返回入口。
4. **工作台**：按运营/程序岗位检查可见队列及默认入口；接单、回复、转交、转程序/交回、结案/重开、合并及公开管理沿用现有权限。筛选后打开管理设置，全部已读确认必须明确包含筛选之外工单。
5. **隐私与兼容**：旧日历链接能预选重命名板块；不同历史类型仍可打开/回复。举报不可发布、不可改类绕过，公开详情/关注不可访问；广场仅有状态筛选和中性关注按钮，未授权反馈不能编辑公开正文。

新建弹窗沿用日历软键盘修复（`10d48a1`）的方式：打开期间跟随 `visualViewport` 高度与顶部偏移，视口变化时只调整正文滚动位置；正文框在短视口下限制高度，保留内部文本滚动。没有该 API 时回退窗口高度，关闭或卸载后移除监听。未修改全局缩放、输入字号及其他弹窗。


## 反馈板块隐藏与恢复

超级管理员在「反馈权限 → 反馈板块」点击「隐藏」或「恢复显示」。隐藏项标注「已隐藏」，留在板块管理列表中供恢复；用户新建/筛选、管理员筛选/调整板块和各类授权选择不再提供该项。历史工单名称和原有授权保留；编辑授权后也不会因选项隐藏而丢失旧权限。隐藏属于展示控制，不代表撤销权限或禁止直接 API 提交。全部板块隐藏时显示「暂无可选反馈板块」并禁用提交，不阻断历史列表。

用户验收（390px、1440px）：隐藏一个已有历史反馈及授权的板块，刷新个人反馈和管理工作台，确认选择中消失、历史名称仍在；编辑并保存原授权，确认权限未丢失；回板块管理恢复显示，再刷新确认可选。再检查全部隐藏后仍可恢复且无加载失败提示。真实布局、触控和浏览器运行时由用户手动验收。
