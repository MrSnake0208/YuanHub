# 今日重点：个人综合提醒

「今日重点」位于今日一览主工作台上方，沿用 `highlights` 模块 ID 和已有电脑/手机独立偏好。默认预览三条，数量表示去重后的全部条目，可展开完整清单。读取成功且无重点时不占位；加载或失败时明确说明状态，单个来源失败不隐藏另一个来源的内容。一般刷新失败保留上次内容并提示可能未更新；身份/权限失效清除该来源的数据。

## 规则

- **订阅活动**：当前账号已订阅、未截止、实际截止在未来 72 小时内且未手动标记本期完成。纯日期截止使用北京时间当天结束边界，精确时刻按实际时间并换算为北京时间。
- **活动待办**：只计真实 Checklist 中未勾选条目，且关联活动进入同一 72 小时窗口。与活动合并为一条，仅展示未完成数量。全部勾选不会使活动本期完成；活动本期完成也不替代 Checklist 完成，所以整期完成但仍有未勾选项时保留一条待办提醒（详情链接使用全部范围）。
- **私人事项**：仅提醒已启用的事项，先以今天、再以明天调用现有 `privateItemReminder`，匹配一次就生成一条。遵循 START/END、当天/提前一天设置；提前一天的事项在事件当天继续显示，沿用弹窗既有规则。明天才达到提醒条件的事项标注「明天提醒」；例如后天开始、提前一天提醒的事项也会作为明天的提醒出现。事项日期与提醒日期分别表达，不把可选开始时间当成提醒时刻。
- **排序与去重**：今天需要留意优先，再按实际截止时刻/提醒日升序，最后按稳定 ID 排序。活动按 event_id 去重；私人事项按事项 ID、START/END、目标日期和提前天数去重。
- **弹窗状态独立**：「稍后提醒」「今天已知悉」只影响原弹窗，首页不读写其免打扰存储，不新增推送、弹窗或完成按钮。

## 数据与刷新

纯聚合逻辑在 `src/data/todayHighlights.js`，展示在 `src/components/today/TodayHighlights.vue`。桌面/手机的几何和密度分别由 `todayHighlightsDesktop.css`、`todayHighlightsMobile.css` 持有，切换布局不重建数据实例。

首页复用完整订阅列表（90 天相交范围，覆盖所有 72 小时临期活动）及私人事项列表（进行中和未来 7 天，覆盖今天/明天提醒）。不能使用最多三条的订阅 summary API 计算重点。订阅列表和概况独立采用成功结果；概况失败不会阻止列表生成重点。

Checklist 确认保存立即更新同一快照；活动/私人事项修改沿用各自的更新事件，按用户及账号过滤。页面重新可见、pageshow、北京时间跨日和活动边界继续刷新。切换用户、账号、游戏、登出或卸载使旧请求失效，页面同时校验快照上下文，不接收旧账号迟到结果。未使用提醒弹窗作数据源，也未改后端 API。

## 人工验收

真实浏览器、视觉、触控和跨设备服务端同步由用户验收，组件测试不证明这些事项通过。

1. 390px 手机、768px 临界宽度、1440px 桌面打开今日一览；检查长标题换行、日期可读、无横向溢出和工作台上方的紧凑密度。更多于三条时展开/收起，Tab 可进入所有详情，收起及提醒消失后焦点仍可达。
2. 临期订阅添加三条 Checklist，应只出现一条重点并显示三条待办；逐条勾选后数量减少，全部勾选但整期未完成仍显示活动截止。整期完成但有未勾选项时仅保留待办提醒，点详情应能进入该活动。
3. 私人事项分别设置 START/END、当天/提前一天/关闭提醒，确认今天和明天的标签；点原弹窗的稍后或已知悉，重点应保留；关闭提醒并返回首页后该重点消失。北京午夜及精确截止时刻附近核对日期边界。
4. 分别隐藏活动待办、私人安排、今日重点；前两者不删重点，隐藏重点不关闭全站弹窗。电脑/手机各保存不同配置并刷新，在另一台同类设备确认同步。
5. 快速切换用户、游戏账号及游戏、返回页面；不得闪现旧资料。单来源离线应显示该来源失败并保留另一个来源，重试恢复；全部成功为空时模块隐藏，新增有效提醒后重新出现。
