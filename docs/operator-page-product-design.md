>
> 重置与持久撤销同时提供：成功后及重新打开的重置记录内均可撤销。恢复原等级/修为/突破并扣回本次实际返还数量，保留其他资源；关联密探后续修改、相关库存盘点覆盖或材料不足时整笔阻止，不覆盖后续数据。库存记录显示返还来源并指向密探重置记录，禁止单独删除。账号备份导入不复制这段撤销历史。
>
> 重置弹窗按「核对练度 → 核对完整材料 → 确认记录」排列，正常流程不再手动更新预览。修改数量暂停 450ms、失焦或选择突破状态后自动请求服务端预览，旧预览及人工确认立即失效；预览失败保留数量并提供重试。未知兵书留空，五铢钱不计入库存。桌面为三列表格，手机材料行下展示库存变化，底部确认与操作保持可达，极矮窗口整体滚动。
>
> 突破状态直接采用当前账号、游戏下已保存的密探资料，不要求重复填写。只有 10–90 级整十关口且档案状态未知时才补充核对；100 级无需选择。补充选择后先由服务端重新计算材料种类和参考数量，再将玩家手填数量交回服务端确认库存变化，不沿用旧参考数量覆盖新结果。当前状态不适用的手填材料明确提示暂不计入，切回原状态保留填写值；左侧同步展示所选状态，未完成最新预览不得提交。
>
> 返还与撤销清单在材料名称左侧复用库存已有材料图标；图片缺失或加载失败时保留完整名称，不显示错误素材。桌面与手机共用同一套材料行。
>
> 顶部「重置记录」进入同一弹窗的历史视图，分页与读取失败重试保留；「查看撤销预览」展示完整扣回清单，返回恢复历史滚动位置，再返回保留返还草稿。成功后可完成并返回原密探编辑，或查看本次记录。未记录的数量编辑关闭前就地确认；网络结果未知时锁定原请求，可原样重试或查询记录，不能发起另一笔操作。账号、游戏或用户变化立即退出并忽略旧响应。
>
> 提交前将原请求、幂等键与清单保存到当前标签页的会话存储，按用户、账号、游戏和本体/SP 组隔离；存储失败不提交。结果未知时关闭或刷新后重开会恢复原操作，不重新生成编号；恢复优先于默认历史视图。明确成功或服务端明确拒绝后清理凭据，迟到响应只清理所属操作。关闭标签页、换浏览器或清理会话存储不提供自动恢复，应通过历史核对。所有关闭入口均受提交中保护，提交时收起放弃确认。已保存练度为 1级/修为+1 时直接进入记录，不请求无效重置预览。

## 1. 产品定位

密探模块不是单一的角色列表，而是一个面向单个游戏子账号的养成工作台：

1. 图鉴用于认识和查找全量密探。
2. 当前养成用于维护账号已经拥有的密探状态。
3. 养成追踪用于根据特别关注名单和库存流水决定下一步资源投入。

“特别关注”是用户维护的养成目标集合，不只是列表排序或过滤条件。关注名单按子账号隔离，与密探心纸库存和库存流水关联，但不进入库存流水本身。

## 2. 页面信息架构

### 2.1 一级视图

`/operator` 保留三个一级 Tab：

| Tab | 用户问题 | 数据范围 | 默认排序/结构 |
|---|---|---|---|
| 图鉴 | “有哪些密探？我还缺谁？最近出了谁？” | 公共目录全量，登录后叠加拥有状态 | 最新实装优先；紧凑头像网格 |
| 当前养成 | “我现在把谁练到了什么程度？” | 当前子账号有养成记录的密探 | 默认按置顶、分组与练度；可选品质、等级、阶级、星级升降序 |
| 养成追踪 | “我下一步该练谁？材料够不够？收集速度如何？” | 特别关注密探、养成状态、心纸库存、库存流水 | 目标优先；仪表盘 + 目标列表 |

图鉴中的“全部 / 已拥有 / 未拥有”仍然保留，因为它回答的是目录覆盖问题；它不能替代当前养成，因为当前养成提供的是可比较、可操作的养成台账。

### 2.2 图鉴

图鉴顶部工具栏：

```text
搜索 · 筛选结果数 / 当前游戏总数 · 录入密探 · 更多筛选
招募状态：全部（数量） / 已招募（数量） / 未招募（数量）
```

工具栏直接复用养成总览的 `OperatorFilterDossier`，使用相同的暖白圆角面板、细边框、虚线分区与分段筛选底板；选中项为暖白底、强调色文字与轻阴影。两处公共控件均按搜索、结果数、录入密探、更多筛选、重置排列，手机搜索独占首行，其他公共控件在下一行；养成总览专属的关注排序、分类设置、批量选择另起一行，避免插入公共入口之间。「更多筛选」使用描边按钮，展开后保留目录版本、属性、职业、品质和养成条件。搜索结果数随全部筛选变化，招募状态数量按当前游戏全量统计，不随搜索或高级条件变化。

筛选与排序规则：

- 默认按密探 ID 中的发布序号降序，无法解析序号的 ID 排在最后。
- 图鉴提供与当前养成一致的快捷预设和自定义范围：等级 100、修为 17、二星以上、四星以上、只看觉醒可一键启用或关闭；等级、修为、星数范围可分别输入上下限并独立启用。养成条件只筛选当前子账号已招募的密探，星数第 6 档代表觉醒。
- 可选排序：最新实装、等级、星级节点、修为、稀有度、名称。
- 特别关注不单独复制一套列表，而作为状态和可选过滤条件接入图鉴。
- 登录且选择子账号后，卡片允许加入/取消特别关注。
- 未登录时仍可浏览全量目录，但关注和养成编辑需要登录及子账号。

图鉴卡片只保留目录浏览需要的信息：头像、名称、官方属性图标、拥有状态和少量操作。静态稀有度不再以“5★ · 阳”文字标签堆在头像下方。

手机端图鉴保持三列紧凑网格（≤640px），一级 Tab 与搜索区等宽。工具栏沿用共享组件的响应式布局：手机搜索独占一行，数量与操作按空间换行，招募状态在下方独立分区；桌面搜索、结果数、录入与更多筛选同行。重置入口复用原清除筛选流程，并将焦点送回搜索框。未招募卡片只淡化头像或占位图，状态使用暖白底棕字，名称、收藏与编辑入口保持清晰可辨。

已拥有密探在名称下方显示「蝶已满 / 蝶未满 / 蝶待确认」。状态来自当前子账号已保存的三项奇闻，与当前养成卡片保持一致；未拥有、未登录、未选择账号或当前账号/版本数据未可靠加载时不显示。

### 2.3 当前养成

进入批量选择时，筛选区直接展开属性、职业、品质及养成条件，方便组合查找；批量模式内不提供折叠入口。退出批量后恢复进入前的展开状态，不清空搜索与属性、职业、品质条件。批量模式不再提供重复的「批量快捷选中」栏；统一使用上方「快捷预设」筛选，再通过「全选当前结果」或逐张勾选密探，批量设置养成状态，或点击同栏「导出图片（N）」直接导出所选密探练度；导出不写标注，关闭分享弹窗保留选择。养成预设继续采用紧凑气泡：桌面最小高度 28px、手机 34px。

当前养成的分组入口遵循文末 `operatorDiscarded` 发布门禁。默认排序保留用户的置顶、分组和特别关注设置，置顶不绕过筛选。自定义多标签、批量分类和独立分类备份详见 [置顶与自定义分类](./operator-organization.md)。默认比较顺序为：

1. 用户设置的置顶顺序，跨越状态分组；
2. 用户设置的分组顺序，初始为养成中、已毕业、养老中，已弃置遵循发布门禁；
3. 同一分组内可选“特别关注优先”；
4. 品质降序、等级降序、化极节点降序；
5. 属性固定顺序、实装顺序降序，最后按中文名称比较。

当前名册工具栏通过 `OperatorFilterDossier` 的专属插槽提供“游戏排序选项”：默认、品质、等级、阶级、星级。非默认时提供“从高到低／从低到高”切换，首次降序；阶级对应 Hub 修为，星级使用包含节点的归一化化极值。四项各自为独立主排序，筛选后按完整列表排列，暂不应用置顶、分组和特别关注优先；切回默认恢复这些设置。未知值在两种方向下都置后，同值按稳定 ID 的 ASCII 字典序升序，不随方向反转。

排序偏好按本浏览器的子账号与游戏保存，切账号分别读取；无效或读取失败时回默认，存储写入失败不阻断当前操作。排序不写服务器分类，也不改变筛选条件；空名册、加载中仍可选择。共享筛选组件、图鉴和他人 BOX 不增加这套专属排序。两款游戏复用截图对应选项，未核验游戏内部隐藏排序差异。化极兼容、本机偏好及人工验收细节见 [游戏排序选项](./operator-organization.md#游戏排序选项)。

推荐采用横向数据行而不是与图鉴相同的头像网格：

```text
头像  名称 + 属性图标/从属    Lv 90    5星·3    修为 17    攻生/奇闻
      已装备星石 6 槽摘要     命盘一详情       命盘二详情       编辑
```

当前养成的功能重点：

- 快速比较等级、修为、化极、奇闻和攻生；
- 奇闻按 `attack / hp / special` 稳定键读取，第三项名称由管理员可编辑的密探公共图鉴统一展示；
- 身份信息下方显示只读「漆园蝶已满 / 漆园蝶未满 / 漆园蝶待确认」，V1/V2/V3 共用同一判定，与可编辑养成标注分开；
- 直接查看双命盘详情与当前已装备星石；
- 对单项进行校正/提升，并可安全卸除单颗或整套星石；
- 单条/批量标记养成中、已毕业、养老中、已弃置；已弃置可恢复到明确目标状态，同时保持特别关注和清单成员独立；
- 任选任意数量密探生成委托交接资料。

如果账号没有养成记录，空态应引导“快捷导入”或“从图鉴选择密探”，不能只显示“暂无数据”。

### 2.4 养成追踪

养成追踪的标题建议为“养成追踪”，副标题为“特别关注的密探与材料进度”。“特别关注”作为名单名称保留在说明和操作中。

顶部概览建议显示：

- 关注密探数量；
- 已拥有 / 未拥有关注密探；
- 当前持有心纸总数；
- 当前周期获得心纸；
- 最近 7 天或 30 天心纸日均；
- 本期获得过心纸的关注密探数；
- 最近最久未获得心纸的关注密探。

下面展示目标列表。每个目标至少包含：

```text
头像 + 属性图标  密探名称
心纸：当前 / 目标
等级：当前 / 目标
修为：当前 / 目标
命盘：当前方案数 / 2
材料：已知缺口摘要
流水：周期获得量 · 日均 · 最近获得日期
操作：设置目标 / 编辑养成 / 查看流水
```

目标列表不应把“加入关注”与“设置养成目标”混为同一个动作：星标只是加入追踪，目标等级、目标修为和目标星级是另外的用户设置。

目标列表上方增加“关注目标总账”：先合并所有关注密探的等级、修为和化极需求，再对共享材料库存抵扣一次。单个密探行仍可展示“如果只养这一位”的独立缺口，但必须标明是单人测算，不能把同一份库存分别抵扣后再汇总为整体缺口。心纸按密探 ID 分别抵扣，不作为可在密探之间调配的共享材料。

## 3. 数据能力与计算边界

### 3.1 当前前端已经能做的真实统计

库存接口和已有统计逻辑已经提供：

- 当前密探心纸数量：`GET /v1/inventory/current?entity_type=agent`；
- 指定时段获得量：`GET /v1/inventory/acquired?entity_type=agent`；
- 奖励流水分页与明细：`GET /v1/inventory/records`；
- 关注名单：`GET/PUT/DELETE /v1/inventory/agent-favorites`；
- 关注心纸周期总量、排行、覆盖率、最久未获得、幸运日等派生统计。

这些数据可以立即支持“收集进度”和“收集速度”面板，但必须区分：

- 当前持有量：库存投影的余额；
- 周期获得量：指定时间范围内的流水增量；
- 速度：周期获得量 / 日历天数，或周期获得量 / 有流水的活跃天数；
- 目标缺口：目标数量 - 当前持有量，不能用周期获得量代替。

### 3.2 本地 Wiki 页面已经提供的静态需求数据

`docs/reference/yuan-operator-calculator/` 保存的是页面完整 HTML 和依赖资源，计算逻辑与数据都内嵌在 HTML 中，不是截图。当前页面元数据为 Wiki 修订号 `93628`，页面最后编辑时间为 2026-07-05，抓取缓存时间为 2026-08-19。等级、修为和化极消耗视为固定规则，YuanHub 不提供版本切换或版本维护界面。

从修订号 `93628` 的脚本可以直接提取出以下数据：

| 养成维度 | 已有数据 | 计算方式/注意事项 |
|---|---|---|
| 等级 | 1-100 每级经验；10、20、30…90 级突破门槛；通用材料、五铢钱、70/80 级职业专属材料 | 按 `now + 1 .. target` 累加经验；只有跨过门槛才计突破材料；职业专属材料按破军、龙盾、岐黄、神纪、诡道分别统计 |
| 化极/星级节点 | `1-0` 到 `4-5`、一至四星升星、觉醒共 25 个节点；每节点心纸和五铢钱，觉醒另有装金玻璃 | 按节点序号累加 `now + 1 .. target`；心纸应与账号中对应密探的 `entity_type=agent` 库存关联 |
| 修为 | 修为 1-17 的逐级材料消耗与五铢钱；风火、地水、阴阳三套材料序列 | 先累加目标区间，再抵扣“已有材料”；页面还根据历练 1-12 的奖励数组给出体力和关卡策略 |
| 好感 | 绝密/机密/隐密的若干解锁阈值与金锁消耗表 | 可作为后续扩展；当前不是完整的好感目标计算器 |

因此，Wiki 数据足以让 YuanHub 做出“目标值 → 总需求 → 当前库存抵扣 → 净缺口”的第一版计算器。当前 `src/data/inventory/catalog.js` 已覆盖页面列出的修为材料、突破材料、三类兵书和装金玻璃；心纸不是通用物品，而是对应密探的 `agent_id` 数量。五铢钱只展示目标总需求，不进入库存缺口、收集速度或 ETA 规划。

等级经验的三类兵书是三种经验面额，不是三份需要同时扣除的材料。应先统一折算经验：

```text
owned_exp = 残卷数量 × 100 + 全卷数量 × 1000 + 六韬数量 × 10000
exp_gap = max(required_exp - owned_exp, 0)
```

Wiki 页面当前只是分别显示 `ceil(required_exp / 面额)`，不能把三个显示值相加为总需求。另外，觉醒节点数据中存在 `装金玻璃 × 1` 字段，但原页面只渲染心纸和五铢钱；修为逐级数据中也有五铢钱数组，但合并后的 v9 结果区没有汇总展示。YuanHub 提取数据时应保留这些字段，并为它们单独补测试。

### 3.3 不能直接把 Wiki 脚本当成后端契约的部分

下面这些内容仍需要 YuanHub 自己定义和校验：

- **数据主键**：Wiki 使用中文材料名和图片 URL，库存使用稳定 `item_id`/`agent_id`。不能在运行时依赖中文名称或外链图片匹配。
- **职业/属性口径**：等级突破使用五种从属，修为使用风火、地水、阴阳三类，需在适配层明确映射，不能把两套枚举混为一谈。
- **算法可解释性**：修为区块的历练策略是页面内置的贪心算法；YuanHub 应至少展示“材料净需求”和“估算体力”，并标注策略为估算，不应把它当成唯一最优解。
- **星石**：本页面没有星石等级/经验星石消耗表。当前养成只同步当前已装备星石，并把它作为攻生输入；星石升级缺口、替换推荐和多方案仍必须等待独立星石管理能力与可靠数据源。
- **账号状态**：Wiki 只给静态总需求，不知道用户当前等级、节点、修为、库存或流水，这些必须来自子账号养成记录和库存接口。

提取后的规则应落成前端静态资源，而不是在 Vue 组件运行时解析 HTML：

```text
target_stage + profession_or_attribute?
  -> item_id + required_count
```

心纸需求在计算时动态绑定当前密探 `agent_id`；`target_stage` 至少覆盖 `level`、`xiuwei`、`star_node`、`awakening`。

### 3.4 缺口、速度与 ETA 的计算边界

接入上述需求资源后，缺口可以这样计算：

```text
net_gap(item) = max(required(item) - current_stock(item), 0)
```

速度仍只能由 YuanHub 流水计算，Wiki 不提供速度：

```text
daily_rate(item) = acquired_in_window(item) / calendar_days
                 或 acquired_in_window(item) / active_days
eta_days(item) = net_gap(item) / daily_rate(item)
```

UI 必须同时显示统计窗口和口径。没有流水、窗口过短或速度为 0 时，显示“样本不足/暂无 ETA”，不能伪造日期。多个材料的目标完成日应按最慢的正缺口材料计算，并允许用户展开查看每项材料的速度来源。五铢钱始终排除在该计算之外。

## 4. 版本与子账号

一个子账号原则上对应一个游戏版本。版本是账号级上下文，不应每次保存都依赖页面顶部筛选猜测。

推荐账号字段：

```json
{
  "id": "acc_xxx",
  "name": "大号",
  "game": "代号鸢 | 如鸢"
}
```

交互规则：

- 创建子账号时允许选择版本，默认 `代号鸢`；
- 旧账号没有版本时由后端迁移为 `代号鸢`；
- 选择后后续表单默认跟随账号版本；
- 不提供 `all`、`universal`、空值或“不区分版本”；
- `代号鸢` 使用完整密探目录，`如鸢` 使用适用子集；
- 库存、密探和快捷导入读取同一个账号版本，切换账号时版本同步切换。

前端已将版本入口提升到共享子账号工作区，并按账号 ID 本地持久化作为过渡。后端上线 `game` 字段后，后端值是跨设备权威值，本地映射仅作为旧接口兼容兜底。

## 5. 双命盘与当前已装备星石

养成总览和密探 BOX 分享提供「全部／有完美盘／有待洗盘」命盘筛选，三选一，与搜索、属性、职业、分组、标签及觉醒等已启用条件取交集。任意一套手动标记命中即可，一盘完美另一盘待洗可分别出现在两种结果中；不会按词条或目标自动判定完美。旧数据缺少标记时视为未标记。重置、切换账号或分享码时清除命盘条件。分享页另提供「只看觉醒」，沿用已有觉醒数据规则。

公开分享包含每套命盘状态，卡片显示一盘／二盘标记；目标词条、备注与计划保持私有。后端需先支持分享 `disc_loadouts[].status`；旧接口缺少状态时，「全部」仍可查看原数据，完美／待洗筛选不会误判命中。

这两类数据都影响密探资料完整性，但语义不同：

```text
双命盘：最多 2 套，可命名；两套都展示，不维护当前盘
已装备星石：密探级 3 主星 + 3 辅星当前快照；参与攻生，可快捷卸除
```

推荐概念模型：

```text
disc_loadouts:
  id, name, discs

star_stones（站内 current 现有字段；v3 交换名为 equipped_star_stones）:
  operator_id, slot(main1..3 / assist1..3), stone_id, level, updated_at
```

星石不能绑定到某一套命盘。自动采集即使从命盘 active slot 中读取到星石，也必须先去重并归一成一份密探级当前装备。扫描攻生与这份装备快照绑定；星石变化后旧观测值立即过期。

当前养成的编辑边界：

1. 基础养成、奇闻与攻生校正；
2. 双命盘编辑；
3. 当前已装备星石详情与卸除；
4. 养成状态与目标入口。

名册的双命盘目标摘要使用紧凑的米白状态栏：绿色完成图标与「一盘完美」、琥珀色刷新图标与「二盘待洗·3处」之间用细线分隔，两盘完美时合并为「两盘完美」。未标记的命盘不展示，两盘均未标记时隐藏整栏；目标未完整设置时只显示「待洗」，不报告数量。数量沿用原有差异规则，尚未拥有的词条仍标为「差 N 项」，目标已达成也不自动改变待洗标记。

桌面状态栏位于两行命盘下方、六个快捷星石槽上方；手机保留命盘左侧、六槽右侧的原布局，摘要位于两者下方。状态栏保持单行、小字和小图标，单套标记按内容收拢，两套同时展示时省去尾箭头以节省空间；点击整栏沿用双命盘目标详情入口。编辑、筛选、保存及云端同步规则不变。

后续独立星石管理页再增加完整星石资产、替换、升级、推荐和多套方案。快捷卸除只解除装备关系，必须保留星石资产，并同时提供即时撤销和刷新后仍可使用的「恢复上一颗」；恢复链路是卸除按钮的上线前置条件。

### 6.2 当前养成与养成追踪

当前养成使用高密度数据行，养成追踪使用目标卡/目标行。两者都应保留头像和属性图标，但信息重点不同：

- 当前养成突出“当前状态”；
- 养成追踪突出“当前值、目标值、缺口和速度”。

编辑界面采用宽编辑面板：头部固定显示密探身份、当前子账号和版本上下文，中间内容区独立滚动，底部操作栏固定显示状态、取消和保存。这样命盘、星石和后续养成目标可以继续纵向扩展而不遮挡保存操作；移动端使用接近全屏的编辑面板。

手动录入新密探时，等级与修为默认均为 1，化极默认「未拥有」；快捷批量录入每个星级步骤也默认等级 1、修为 1、节点 0。已有记录按原值回填；从「未拥有」选择其他星级时，仅将等级、修为的零值补为 1，保留已有正数（包括 SP 与本体同步的养成值）。切回「未拥有」不清空养成值；只有用户保存后才写入云端，不批量迁移历史数据。

快捷录入的批量栏提供「100级 / 修为17」「90级 / 修为15」预设，仅填充当前星阶页的等级与修为草稿，不改变勾选集合。点击「保存本页并下一步」后才应用到已勾选密探；保存仍会写入本页星级与节点，因此不作为保留各自化极的批量升级入口。

「蓝卡全选」「紫卡全选」「全选本页」仅作用于当前筛选结果。遇到其他星阶已勾选的密探时，汇总为一次询问：「跳过全部已选」保留原星阶勾选，继续选中剩余未分配密探；「覆盖全部」将冲突密探统一移到当前星阶，同时选中其余密探。关闭弹窗（含 Escape 或点击遮罩）取消本次全选，保持操作前的选择。单个密探跨阶勾选仍单独确认；这些操作只调整草稿，保存后才写入档案。

快捷录入分为「首次建档」和「快速补录」：首次按 1 星至觉醒顺序推进，未勾选页可以跳过；快速补录（`/operator/quick?mode=supplement&account=<id>`）可以直达任意星阶、搜索角色，每阶单独保存，不自动翻页。切阶保留该阶勾选与表单。补录默认保留已有等级、修为，新密探使用本页设置；用户主动勾选「同时覆盖已有密探的等级、修为」后才批量覆盖。页面列出完整修改前后预览，保存前再次确认目标账号、受影响角色与覆盖/保留字段。每页保存立即生效，离开或取消后续录入不会撤销之前的保存。

当前账号的已有养成读取成功前不能快捷保存，读取失败提供重试，不能按空档案继续导入。草稿按登录用户、账号和游戏在当前页面内存中隔离；切回原账号恢复草稿，退出登录或更换登录用户清除草稿，离开页面不持久化。所有异步读取、选择确认和保存回调在上下文变化或页面销毁后失效。同一已确认提交失败重试复用完整交换文档（包括 `record_id` 与时间），修改草稿则重新预览确认并生成请求；`superseded` 或未接受的结果保留草稿，不显示保存成功。`warnings` 显示在保存结果中。

快捷保存沿用 v2 `listed` 交换协议：只导入列出的密探，保留读取到的第一套命盘与已装备星石，第二套命盘由后端既有合并规则保留；SP 与本体的等级、修为联动及未拥有占位记录沿用后端既有规则，预览明确关联角色。v2 导入不提供编辑器 PATCH 的 `expected_revision` 乐观锁，网络失败重试的 409 也不等同于编辑器的 revision 冲突；需要多个客户端并发编辑同一角色时，优先使用现有单角色编辑器。

名册在默认图鉴筛选前区分未登录、无账号、加载中、读取失败、空档案和无可展示已招募密探；仅成功读取后的空档案提供首次/补录动作。单角色入口聚焦现有图鉴搜索，复用编辑器。分享与交换保持默认折叠、账号条保持现有组件。养成规划已在开发与生产构建开放；规划面板持续显示「测试中：存在很多 Bug」，提醒核对结果后再操作。

单个密探编辑器的等级、修为输入旁也提供上述两个预设，仅填充当前编辑草稿的等级和修为，保留化极、奇闻、命盘和星石；点击保存后生效。

单密探编辑与快捷录入的等级、修为框聚焦时全选，方便直接替换默认值。逐字输入等级时不联动下调修为，结束等级编辑后才按最终有效等级校正；单密探编辑中暂时清空等级会保留修为，空等级仍不能保存。快捷录入结束编辑时沿用原有数值归一化与保存预览。

每条奇闻的上限旁提供「拉满」，只填入该项图鉴上限，保留其他奇闻与养成草稿；上限未知时禁用并说明原因。原有「奇闻全部拉满」继续可用，两种操作都需保存后生效。

打开密探编辑时显示读取状态，并暂时禁用该密探的编辑入口；连续选择不同密探时只打开最后一次请求，迟到请求不能清空新编辑器。读取失败显示可见提示，允许重新点击编辑恢复；账号切换及卸载后的响应不再打开编辑器。编辑弹窗直接显示，不依赖滚动显现动画。

图鉴、当前养成、分享与养成规划统一以 `starLevel > 0` 判断拥有。星级为 0 时，即使等级或修为非零仍为未拥有，且不计为养成目标已完成。

### 6.3 攻击力 / 生命力

战斗属性是由基础等级面板、修为阶段、化极节点、当前已装备主/辅星石和奇闻属性共同得到的派生值。Wiki 面板计算器的固定公式已经提取到 `src/data/operatorPanelCalculator.js` 与 `src/utils/operatorCombatStats.js`：

```text
（等级基础值 + 化极固定值 + 星石固定值 + 奇闻属性）
×（1 + 化极百分比 + 星石百分比 + 修为百分比）
```

编辑器实时展示攻击力、生命力和来源状态。扫描 JSON / 自动上报的攻生命值作为观测值保存，并与等级、修为、化极、奇闻和已装备星石输入签名绑定；任一输入变化后旧观测值标记为过期。用户可以直接在两张面板卡内填入手动修正值，留空后恢复公式结果。

奇闻采用稳定键维护的 `oddities` 结构，固定为 `attack / hp / special` 三项并单行展示，只允许编辑当前值。交换文件、账号投影和浏览器备用数据都不得把“增伤值”“免伤值”“治疗加成”等展示名称作为键。当前只有 `attack`、`hp` 参与攻生命公式，`special` 不会被误计入攻击或生命。

当前版本暂时隐藏总览和养成卡片中的漆园蝶完成标签及原因提示，保留内存中的三态计算、保存响应更新和账号隔离；行为测试继续验证这些数据规则，并确认标签不会展示。

漆园蝶完成状态只依据已保存的服务端三项 `current` 和当前公共图鉴 `oddity_schema.*.max`：三项明确记录、数值与上限均为有效非负数且分别相等时为「已满」；三项完整有效且未超限，至少一项小于上限时为「未满」；缺项、null、非法值、负数、超限或公共上限缺失/无效时为「待确认」，原因记录为「第三项尚未记录」等。明确零值合法，归一化补零与旧浏览器缓存不能作为完成证据；旧记录附带的 `max` 不参与判断。

状态与等级、修为、化极、星石、命盘、手动毕业标注及攻生命观测过期独立。第三项缺名称但稳定键和上限有效时仍可判断。卡片和编辑器未保存草稿、取消或保存失败不改变标签，保存成功合并服务端响应后才更新。账号/版本切换、加载中或加载失败隐藏旧提示，迟到的读取/保存响应不能恢复旧上下文状态；公共 schema 更新后重新计算。完整性信息只存在前端内存，不写入 PATCH、交换档案或 localStorage，不新增筛选、统计或第三项快捷编辑。数值比较不额外取整；当前后端仍按整数保存奇闻，不表示已支持小数保存。

奇闻输入区提供「奇闻全部拉满」，只将三项当前值填到公共图鉴上限，保留等级、修为、化极、命盘和星石；图鉴缺少上限的项保留原值并提示待维护。原有「一键拉满等级/修为/漆园蝶」继续同时填入等级 100、修为 17 和奇闻上限。两种操作均在点击保存后生效。

第三项名称属于密探公共图鉴。管理员在现有公共图鉴编辑器维护每位密探的 `special_oddity_name`；公共接口根据该字段和稀有度返回 `oddity_schema`，其中包含三个稳定键的展示名称与上限。上限按稀有度确定：3 星为 `300/1560/9`，4 星为 `350/1820/11`，5 星暂沿用 `500/2600/15`，管理员不逐个填写上限。职业只可用于管理员录入时的预填建议，不能作为用户侧正式名称的静默推断。存量目录缺名时显示“第三属性（图鉴待维护）”，并在管理员列表标出待补齐。

修改公共图鉴名称只改变展示，不迁移 `special.current`，也不使既有攻生观测失效。扫描 OCR 原始名称只用于诊断；与图鉴不一致时提示复核，不能覆盖目录。

任何等级、修为、化极、已装备星石或奇闻变更都会刷新结果。前端继续兼容旧 `curios` 攻生命字段，但缺少稳定键的旧数据显示漆园蝶待确认。当前养成读取与 `PATCH /v1/operator/current/{operatorId}` 已支持双命盘、奇闻和攻生命扩展字段，服务端记录优先；只有服务端完全没有战斗属性字段时，完整编辑器才兼容读取旧浏览器缓存，该缓存不参与列表完成状态。

页面继续使用设计规范中的纸底、暖白、奶油、暖棕、茶棕和蜜黄；官方属性图标是内容资产，不扩展页面主色板。不得使用纯黑、大面积海盐蓝或黑底黄字。

## 8. 验收标准

完成当前前端阶段后，用户应能：

1. 在图鉴中按最新实装顺序浏览全部密探，并看到官方属性图标。
2. 在图鉴中加入/取消特别关注，切换账号后关注状态不串号。
3. 在当前养成中快速比较等级、星级节点和修为，而不是重复浏览图鉴卡片。
4. 在养成追踪中看到关注密探的当前心纸、周期获得量、速度和最近流水状态。
5. 对已配置的等级、化极和修为需求看到材料缺口；没有对应版本、映射或流水数据时明确知道原因，不会看到伪造数量或 ETA。
6. 在首次编辑或快捷导入时明确知道保存对应的游戏版本。
7. 使用键盘和移动端完成关注、筛选、编辑入口和 Tab 切换。
